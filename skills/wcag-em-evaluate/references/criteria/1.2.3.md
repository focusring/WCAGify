# 1.2.3 Audio Description or Media Alternative (Prerecorded)

Level A · WCAG 2.0+ · Guideline 1.2 Time-based Media · Group: `media`

Sources: [Understanding][u] · [Spec][spec] · [Techniques][tech] · [Plain English][plain] · ACT:
[c5a4ea](https://www.w3.org/WAI/standards-guidelines/act/rules/c5a4ea/),
[1ea59c](https://www.w3.org/WAI/standards-guidelines/act/rules/1ea59c/),
[1a02b0](https://www.w3.org/WAI/standards-guidelines/act/rules/1a02b0/),
[ab4d13](https://www.w3.org/WAI/standards-guidelines/act/rules/ab4d13/)

## Requirement

> An alternative for time-based media or audio description of the prerecorded
> video content is provided for synchronized media, except when the media is a media alternative
> for text and is clearly labeled as such.

Terms (WCAG 2.2 glossary): **alternative for time based media**: "document including correctly
sequenced text descriptions of time-based visual and auditory information and providing a means for
achieving the outcomes of any time-based interaction". **audio descriptions**: "narration added to
the soundtrack to describe important visual details that cannot be understood from the main
soundtrack alone [...] Note 3: Where all of the video information is already provided in existing
audio, no additional audio description is necessary." **media alternative for text**: "media that
presents no more information than is already presented in text [...]". **prerecorded**:
"information that is not live".

## In plain terms

A prerecorded video with a soundtrack must give a viewer who cannot see the picture its visual
information, by either route the author picks: narration in the audio describing the important
visuals, or a screenplay-like text document carrying everything the video presents — dialogue,
non-speech sound, what is shown, whatever any interaction needs — in sequence. Either route alone
satisfies it. It serves people who are blind or have low vision and people who find moving images
hard to process. At AA, evaluate 1.2.5 on the same video: the text route leaves it unmet.

## Applies when

- Present: a visible prerecorded video with an audio track the viewer can play: a `video` element,
  an embedded player (`iframe`, `object`, `embed`), or a player reached from a poster, lightbox,
  tab or carousel slide, in any state of the sample. Detect with `media.js`: every `media` entry
  with `kind` `video` or `embed`, reading `selector`, `provider`, `sources`, `duration`, `controls`,
  `tracks`, `textAlternativeNearby`; `structure.js` `iframes` catches what the probe misses.
- Not present: no state of the sample holds a video, or every video found is silent. Silent video
  and `audio` elements are 1.2.1; `animatedImages` are 1.1.1 and 1.2.1.
- Exceptions: (1) "except when the media is a media alternative for text and is clearly labeled as
  such": visible page text carries everything the video presents and visible text names it as a
  repetition of that text (ACT ab4d13). (2) Understanding's note: "if all of the important
  information in the video track is already conveyed in the audio track, no additional audio
  description is necessary". (3) A live stream (step 1's `live: true`, a "LIVE" badge) is 1.2.4.

## axe-core

No axe-core rule is tagged with 1.2.3; `axe-page.mjs` reports none and everything below is manual.

## Manual procedure

1. Inventory the players in every state, then qualify them (ACT c5a4ea, 1ea59c and ab4d13
   applicability: "every non-streaming video element that is visible, where the video contains
   audio"; 1a02b0 drops the audio condition). Accept the consent dialog blocking embeds, open the
   lightbox or tab holding a player, advance the carousel; for each play control or poster:
   `click` it, `wait 1500`, re-run `media.js`, `press Escape` or `back`.

   ```bash
   agent-browser eval --stdin < <skill-dir>/scripts/probes/media.js
   agent-browser eval --stdin < <skill-dir>/scripts/probes/structure.js
   agent-browser eval --stdin <<'JS'
   (async () => { const out = [];
     for (const v of document.querySelectorAll('video')) {
       const wasMuted = v.muted, wasPaused = v.paused;
       v.muted = true; await v.play().catch(() => {});
       await new Promise(r => setTimeout(r, 2000)); v.pause();
       const b = v.webkitAudioDecodedByteCount ?? null, played = v.currentTime > 0;
       v.muted = wasMuted; if (!wasPaused) v.play().catch(() => {});
       out.push({ src: v.currentSrc, live: v.duration === Infinity, played,
         seconds: Number.isFinite(v.duration) ? Math.round(v.duration) : null,
         hasAudio: v.mozHasAudio ?? (!played || b == null ? null : b > 0) });
     } return out; })()
   JS
   ```

   `hasAudio: false` with `played: true` → video-only, 1.2.1, drop it; `hasAudio: true` proves an
   audio track, not sound, so a soundtrack silent throughout is 1.2.1 too. `hasAudio: null` or
   `played: false` → nothing decoded (autoplay policy, DRM, metadata still loading): `click` the
   visible play control, `wait --load networkidle`, re-run once, then `cannot-tell`.
   `live: true` →
   1.2.4, drop it. `is visible "<selector>"` false in every state: drop it. An audio-only embed
   (`provider` `soundcloud` or `spotify`) → 1.2.1; any other embed has audio unless its controls
   say
   otherwise: `frame "<iframe selector>"`, `snapshot -i` for a mute or volume control, `frame main`.
   Done when the list holds every visible prerecorded video with audio, or is empty and the outcome
   is `not-present`.

2. Establish what the picture carries that the soundtrack does not (ACT 1ea59c expectation: the
   visual information "is available through its audio, or through an audio description track").

   ```bash
   agent-browser eval --stdin <<'JS'
   (() => { const v = document.querySelector('<video selector>');
     v.currentTime = v.duration * 0.15; return v.currentTime; })()
   JS
   agent-browser wait --fn "!document.querySelector('<video selector>').seeking"
   agent-browser screenshot "<video selector>" .notes/audit/evidence/<sample>--1.2.3-f1.png
   ```

   Repeat at 0.3, 0.5, 0.7 and 0.9 of the duration; for an embed `click` play, `wait 5000`,
   `screenshot "<iframe selector>" <path>`, repeat. Read what the audio says through the captions:
   `get attr "video track[kind='captions']" src`, then `agent-browser read <src>`. On-screen text,
   slides, charts, demonstrated steps, scene changes or wordless action the captions never mention
   → the visuals carry information of their own; a single speaker against an unchanging background
   whose captions cover everything shown → the Note case. Done when each video is
   `needs-alternative`, `covered-by-audio`, or `cannot-tell` (no captions or transcript, frames
   ambiguous).

3. Route A — audio description (ACT 1ea59c). Look, in this order, for a second, user-selectable
   audio track ([G78][g78]): a control or settings entry named "Audio description", "AD",
   "Described" or "Audiodescriptie" — YouTube: `frame "<iframe selector>"`,
   `find role button click --name "Settings"`, `snapshot -i`, `press Escape`, `frame main`. Then a
   described version ([G173][g173]) or an extended one ([G8][g8]): a link near the player, "Watch
   with audio description" — `tab new`, `open <href>`, qualify it as in step 1: it plays and
   `seconds` is near the original's or longer. SMIL media offers the SMIL route instead —
   [SM6][sm6] or [SM7][sm7] for description, [SM1][sm1] or [SM2][sm2] for extended description —
   which a browser-driven evaluator rarely meets. Then narration in the soundtrack
   ([G226][g226]), or a
   voiceover already describing the picture: claimable only from captions or a transcript in which
   the narrator names what is on screen. A `tracks` entry of `kind` `descriptions` ([H96][h96],
   advisory) counts only when a player on the page speaks it — c5a4ea: "there is no native support
   in any major browser for this technique [...] can not be relied upon to conform to 1.2.3".
   Done when each video is `ad-track`, `ad-version`, `ad-integrated`, `ad-unsupported` or
   `ad-none`, with a screenshot of the player and its menu open.

4. Route B — an alternative for time-based media (ACT 1a02b0, an input rule of c5a4ea; [G69][g69]).
   It must hold, in sequence, descriptions of the visual information, transcripts of the dialogue
   and the non-speech sound, and the links or controls for any interaction in the video. Find it in
   `media.js` `textAlternativeNearby`, in `snapshot -s "<container css>"`, or behind a link
   immediately next to the player ([G58][g58]) or in the `object` body ([H53][h53]) — `tab new`,
   `agent-browser read <href>`, `tab close`. It must be in the accessibility tree: `snapshot` shows
   it (1a02b0 Failed Example 3: an `aria-hidden="true"` transcript fails); it need not be visible
   (Passed Example 3: off-screen text passes), only route C requires that. Match it against the
   step 2 frames and captions: the actions, on-screen text, names and figures in the frames appear
   in the document (Failed Examples 1 and 2: a transcript about other content fails); captions that
   carry all the dialogue plus page text describing the visuals count together (Passed Example 4). A
   talking head needs only static text for the setting, credits and unspoken on-screen text
   ([G203][g203]). Done when each video is `alt-full`, `alt-partial` (dialogue only, picture
   undescribed), `alt-wrong`, or `alt-none`.

5. Route C — the exception, a media alternative for text (ACT ab4d13). Expectation 1: all the
   information in the video is available as text that is visible and in the accessibility tree —
   compare the step 2 frames and captions with the surrounding page text (Failed Example 1: the
   video contains more than the text; Failed Example 2: the text is not visible). Expectation 2:
   visible text in the tree labels the video as an alternative for that text, "watch the same
   information again in video form" (Failed Example 3: no label; Failed Example 4: label not
   visible). Check both with `is visible "<css>"` and `snapshot -s "<css>"`. Done when the video is
   `alternative-for-text` or the claim is rejected.

6. Decide and record. Per c5a4ea, a video passes when "the outcome of at least one of the following
   rules is passed" — 1ea59c (route A), 1a02b0 (route B) or ab4d13 (route C) — so when route A, B or
   C succeeds, or step 2 marked it `covered-by-audio`. At target level AA or AAA give the same video
   a separate 1.2.5 verdict: only route A satisfies 1.2.5. Evidence per failing video:
   `highlight "<player selector>"`, `screenshot --full`, the step 2 frames, and `record start` /
   `record stop` for a link or toggle that does nothing (see Reporting). A player that cannot be
   opened (blocked embed, login wall, DRM): `cannot-tell` with the embed URL and the blocker.
   Done when every video has a verdict and every fail an evidence path.

## Deciding

- Fail (certainty ≥ 90): a video marked `needs-alternative` against its own captions or transcript
  with `ad-none`, `alt-none` and no ab4d13 claim (95; 1a02b0 Failed Example 4). The only mechanism
  is a `descriptions` track in a bare `video` element and nothing speaks it (95; c5a4ea Failed
  Example 4). The transcript or described version is about other content (90; 1a02b0 Failed
  Examples 1 and 2, c5a4ea Failed Example 2). The transcript link is dead, its page empty, or the
  described version does not play (90). The transcript is on the page but outside the tree,
  `aria-hidden` or hidden (90; 1a02b0 Failed Example 3).
- Fail (70–89): `alt-partial`, the only text being a dialogue transcript with no description of
  what is shown, with `ad-none` (85). `needs-alternative` decided from the frames alone, with no
  captions to confirm the audio is silent about them, `ad-none` and `alt-none` (75). An ab4d13 claim
  rejected because the frames show more than the visible text, or the label is missing or not
  visible, and no other route exists (75; ab4d13 Failed Examples 1 to 4). A link to the described
  version that resolves to the same file as the original (75). The video asks for an interaction
  ("click the link on screen") that the transcript does not provide as a link (70).
- Needs confirmation (50–69): the frames mix a speaker with slides, demonstrations or lower-thirds
  and there are no captions: ask whether the narrator says what the slides show (60). A transcript
  that reads complete: ask the human to watch and name anything visual it omits (55). An "Audio
  description" entry present but unheard, or an opaque scripted player: ask the human to check (55).
- Pass: every visible prerecorded video with audio has one working route — audio description
  (`ad-track`, `ad-version`, `ad-integrated`), an `alt-full` alternative for time-based media in the
  accessibility tree matching the frames, or an `alternative-for-text` claim meeting both ab4d13
  expectations — or is `covered-by-audio`; and no state reveals another player.
- Not present: no state of the sample holds a visible prerecorded video with an audio track.
- False positives to avoid: a full transcript is enough here, so never fail 1.2.3 because the
  description is text rather than audio (that gap is 1.2.5); an off-screen transcript in the
  accessibility tree passes; silent video and `audio` elements are 1.2.1; live streams are 1.2.4; a
  narrator who says everything shown needs nothing added; a missing `descriptions` track is no
  defect (H96 advisory); a described version as a separate file passes (G173).

## Reporting

- File under: 1.2.3 when the video offers neither audio description nor a full alternative for
  time-based media. At AA that defect also fails 1.2.5: keep one issue here, name 1.2.5 in the body,
  record `fail` for both in the findings. When a full transcript exists and only the audio
  description is missing, 1.2.3 passes and the issue belongs under 1.2.5. Captions: 1.2.2. Silent or
  audio-only: 1.2.1. Live: 1.2.4. One issue per video, naming the other samples that carry it.
- Title patterns: "Video has no description of its visual content", "Transcript covers only the
  spoken words", "Transcript belongs to a different video", "Link to the transcript is broken"
- Severity: High when the video is the only carrier of its content (a tutorial, a lecture with
  slides, a demonstration, instructions) or the transcript link is broken; Medium when the page text
  covers the essentials and the video adds unspoken detail, or the transcript covers only the
  dialogue; Low when the unspoken visuals are marginal (a name caption, credits, a logo).
- Type: Content when the transcript or description must be written, recorded or corrected;
  Technical when one exists and the page hides it (unspoken track, dead link, missing menu entry).
- Evidence: a full-page screenshot with the player highlighted and no transcript or description
  link beside it; one or two step 2 frames holding the undescribed visuals; the open settings menu.
- Recommendation: either publish an alternative for time-based media — a screenplay-style document
  with the dialogue, the non-speech sound and a description of everything shown, in the order of
  the video ([G69][g69]) — linked immediately next to the player ([G58][g58]) or in the `object`
  body ([H53][h53]); or provide audio description as a second, user-selectable audio track
  ([G78][g78]), a described version ([G173][g173]), an extended one where the pauses are too short
  ([G8][g8]), or narration with the descriptions built in ([G226][g226]). For a talking head the
  static text of [G203][g203] suffices. Add `track kind="descriptions"` ([H96][h96]) only alongside
  one of these, since no browser speaks it.
- Related: 1.2.5 (audio description at AA — the text route passes here and fails there, so check
  both on every video), 1.2.2 (captions), 1.2.1 (silent video, audio-only), 1.2.4 (live), 1.2.8
  (AAA, media alternative mandatory), 1.1.1 (unnamed player or poster), 4.1.2 and 2.1.1 (controls).
