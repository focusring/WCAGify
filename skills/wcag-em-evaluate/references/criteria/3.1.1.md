# 3.1.1 Language of Page

Level A · WCAG 2.0+ · Guideline 3.1 Readable · Group: `structure`

Sources: [Understanding](https://www.w3.org/WAI/WCAG22/Understanding/language-of-page.html) ·
[Spec](https://www.w3.org/TR/WCAG22/#language-of-page) ·
[Techniques](https://www.w3.org/WAI/WCAG22/quickref/#language-of-page) ·
[Plain English](https://aaardvarkaccessibility.com/wcag-plain-english/3-1-1-language-of-page/) ·
ACT: [b5c3f8](https://www.w3.org/WAI/standards-guidelines/act/rules/b5c3f8/),
[bf051a](https://www.w3.org/WAI/standards-guidelines/act/rules/bf051a/),
[ucwvc8](https://www.w3.org/WAI/standards-guidelines/act/rules/ucwvc8/)

## Requirement

> The default human language of each web page can be programmatically determined.

Terms (WCAG 2.2 glossary): **programmatically determinable**: "determined by software from
author-supplied data provided in a way that different user agents, including assistive
technologies, can extract and present this information to users in different modalities". **web
page**: "a non-embedded resource obtained from a single URI using HTTP [...] a resource must be
'non-embedded' [...] to be considered a web page." The Understanding fixes the default as "the
language which is used most" and, when several are used equally, "the first language used".

## In plain terms

The author declares, in markup, the language most of the page is written in, so software can act
on it: screen readers "load the correct pronunciation rules", media players "show captions
correctly". In HTML that is one attribute, `lang` on the `html` element. It matters to everyone
who listens to the page, to braille readers and to caption users: wrong language, wrong voice.

## Applies when

- Present: on every HTML sample and on every recorded state that is a page of its own (a view
  whose `get url` differs from the sample's address, or the state after a language switch).
  `structure.js` reads the declaration: `lang` and `xmlLang` (raw root attributes, `null` when
  absent), `title`, `langParts` (elements under `body` with their own `lang`) and `iframes`. A PDF
  sample sets the catalog's `/Lang` ([PDF16](https://www.w3.org/WAI/WCAG22/Techniques/pdf/PDF16)).
- Not present: never. Every sample is a web page with a root element; a page without text and
  without a title (ucwvc8 Inapplicable Example 2) still needs a `lang` attribute (b5c3f8).
- Exceptions: none in the criterion text. Scope limits from the ACT rules: only the root element
  of the top-level browsing context is a test target; documents inside `iframe` and `object` "are
  not web pages according to the definition in WCAG" (bf051a); only the primary language subtag
  counts, region, script and variant subtags are free (`en-US-GB` passes bf051a); an HTTP header
  or a `meta` element is assumed "insufficient", so only `lang` counts (SVR5 is advisory).

## axe-core

| Rule                     | Decides                              | Result → outcome                    |
| ------------------------ | ------------------------------------ | ----------------------------------- |
| `html-has-lang`          | `lang` on `html`, not blank (b5c3f8) | violation → fail (100); else step 2 |
| `html-lang-valid`        | known primary language tag (bf051a)  | violation → fail (100); else step 3 |
| `html-xml-lang-mismatch` | `lang` and `xml:lang` agree (5b7ae0) | violation → step 3 decides          |

All three report failures only, never incomplete, and sit in the default WCAG 2.0 A & AA rule set.
W3C deprecated ACT 5b7ae0 ("modern screen readers no longer use xml:lang when the lang attribute is
given") and holds a mismatch against 3.1.1 only "when there are inconsistencies between assistive
technologies as to which attribute is used": it is the one axe violation here that is not a fail on
its own. Settles: on every state the axe run covered, a non-blank `lang` on the root element, its
primary subtag in the language subtag registry, and whether `xml:lang`, when present, agrees.
Leaves open: whether the declared language is the one the page is written in (ACT ucwvc8, the
common defect and the one no axe rule covers); the default when the page mixes languages; a
registered tag naming a language the author did not mean (`uk` is Ukrainian, `se` Northern Sami);
states axe did not run on; same-origin `iframe` documents; a PDF sample (PDF16).

## Manual procedure

Structure mode: read the sample as loaded, then each recorded state that changes the page's text.
`snapshot` does not expose `lang`: `get attr` and the probe read the attribute, the page's own text
decides its language.

1. Read the declaration after the page has settled (a script may set it late):

   ```bash
   agent-browser wait --load networkidle
   agent-browser get attr html lang
   agent-browser eval --stdin < <skill-dir>/scripts/probes/structure.js
   ```

   Record the `lang` value verbatim, `xmlLang`, `title` and the `lang` values in `langParts` in the
   findings file, with the URL. `get attr` prints a blank line for `lang=""` and `✓ Done` when the
   attribute is absent, so take the value from the probe, which separates `""` from `null`. Done
   when the exact attribute value, or its absence, is in the findings file.

2. Confirm b5c3f8 and bf051a on a state axe did not cover, or when the value looks odd:

   ```bash
   agent-browser eval --stdin <<'EOF'
   (() => {
     const el = document.documentElement, tag = el.getAttribute('lang');
     const primary = (tag ?? '').trim().split('-')[0].toLowerCase();
     let name; try { name = new Intl.DisplayNames(['en'], { type: 'language', fallback: 'none' })
       .of(primary) } catch {}
     return { tag, blank: !(tag ?? '').trim(), primary, known: !!name,
       wellFormed: /^[a-z]{2,3}$/.test(primary), xmlLang: el.getAttribute('xml:lang'),
       bodyLang: document.body?.getAttribute('lang') ?? null };
   })()
   EOF
   ```

   b5c3f8 expects `blank: false` on the root `html` of the top-level document; `xml:lang` alone
   (its Failed Example 4) and `lang` on `body` only leave the root without `lang`. `wellFormed:
false` fails bf051a outright (`#1`, `i-lux`, `en_US`, whose underscore makes it one subtag);
   `wellFormed: true` only clears the shape, and `known` sorts the rest without settling it:
   `Intl.DisplayNames` is not the subtag registry, so three-letter ISO 639-2 codes (`eng`, `deu`,
   `fra`, `nld`) and grandfathered `i-` tags fail bf051a whatever it returns (Failed Examples 3 and
   4), while registered languages it cannot name (`se`, `frr`, `csb`, `zxx`) pass it. On
   `wellFormed: true`, an `axe-page.mjs` run on that state decides bf051a. Done when both rules
   have verdicts.

3. Determine the default language of the page and compare it with the declaration (ucwvc8).
   Collect the text that inherits its language from the root: visible text outside any element
   with its own `lang`, the document title and accessible names outside such elements (text
   inside a `lang` part counts for that part, not for the page):

   ```bash
   agent-browser eval --stdin <<'EOF'
   (() => {
     const root = document.documentElement, words = [], parts = {};
     const owner = (el) => el.closest('[lang]') ?? root;
     const walker = document.createTreeWalker(document.body ?? root, NodeFilter.SHOW_TEXT);
     for (let n; (n = walker.nextNode()); ) {
       const el = n.parentElement, w = n.textContent.trim().split(/\s+/).filter(Boolean);
       if (!el || !w.length || !el.checkVisibility({ visibilityProperty: true })) continue;
       if (owner(el) === root) words.push(...w);
       else { const l = owner(el).getAttribute('lang'); parts[l] = (parts[l] ?? 0) + w.length }
     }
     const names = [...document.querySelectorAll('[alt], [aria-label], [aria-labelledby]')]
       .filter((el) => owner(el) === root).map((el) => el.getAttribute('aria-label')
         ?? document.getElementById(el.getAttribute('aria-labelledby'))?.textContent
         ?? el.getAttribute('alt')).filter(Boolean);
     return { lang: root.getAttribute('lang'), title: document.title, rootWords: words.length,
       partWords: parts, sample: words.slice(0, 120).join(' '), names: names.slice(0, 12) };
   })()
   EOF
   ```

   Read `title`, `sample` and `names` and name the language they are written in; when `sample`
   mixes languages, the one with the most words is the default, on an even split "the first
   language used". A match on the primary subtag of `lang` passes this state (`en-GB` over
   American English matches); a different language fails (see Deciding). Only `rootWords: 0` with
   an empty `title` and no `names` means the page has no default language (ucwvc8 Inapplicable
   Examples 2 and 3): a `lang` that passed step 2 passes here, while a title or an accessible name
   on its own still names the default (Passed Example 4). `cannot-tell` here, queued: text
   readable as either of two languages (Inapplicable Example 4), or too little root text to name
   one. Done when the root text's language is named next to `lang`, "matches" or "does not match".

4. Repeat steps 1 and 3 in every recorded state that changes the page's text: a view with its own
   URL, and the state after a language switcher where the sample plan records one. `get url`,
   then `get attr html lang`: a state whose text switched language while `lang` stayed, or a
   `lang` a script rewrote to a value the text no longer matches, fails on that state. Done when
   every recorded state has a `lang` value and a language verdict.

5. Check embedded documents that carry the page's content. For each `iframes` entry of
   `structure.js` whose `src` is on the sample's origin and whose frame holds readable text
   (`frame` takes a snapshot ref; a CSS selector does not resolve a frame):

   ```bash
   agent-browser snapshot -i
   agent-browser frame @eN            # the ref of that iframe
   agent-browser get attr html lang
   agent-browser frame main
   ```

   The embedded document is not a web page under the ACT rules, yet b5c3f8 notes that the parent's
   language "will likely not be inherited": a frame without `lang` goes under Needs confirmation;
   a cross-origin frame (a video player, a cookie banner) gets a note, not a verdict. Done when
   every same-origin frame has a note.

6. A PDF sample is outside the browser's reach: it exposes neither the `/Lang` entry (PDF16) nor
   passage entries (PDF19). Record `cannot-tell` and queue it for a check with a PDF tool. Done
   when the queue entry names the sample.

## Deciding

- Fail (certainty ≥ 90): no `lang` attribute on the root `html` element, including `lang` on
  `body` only or `xml:lang` alone (axe `html-has-lang`: 100; by step 2 on a state axe did not
  cover: 95); `lang` empty or white space only (100 / 95); a `lang` whose primary subtag is not a
  registered language: `#1`, `em`, `jp`, `cz`, `eng`, `i-lux`, `en_US` (axe `html-lang-valid`:
  100; by step 2 on a state axe did not cover, when `wellFormed` is false: 95).
- Fail (70–89): a registered language that nothing on the page is written in, or one the author
  did not mean (`lang="da"` over all-English title, text and names, ucwvc8 Failed Example 1; `uk`
  on British English, `se` on Swedish) — 85; `lang` names the language of a minority of the root
  text while most of it is in another (a template's `en` on Dutch pages with an English footer;
  Failed Example 2) — 85; `lang` matches only text that sits in `lang`-marked parts (Failed
  Example 3) — 80; a state after a language switch whose text changed while `lang` stayed, or a
  `lang` a script rewrote to a value the text no longer matches (step 4) — 80.
- Needs confirmation (50–69): root text split evenly between two languages with `lang` naming one
  of them — 60: ask which is meant as the default; text readable as either of two languages, or
  too little root text to name one — 55: ask which language the page is in; a same-origin `iframe`
  holding the page's main content without `lang` — 55: ask whether it is in scope; `lang` and
  `xml:lang` naming different languages while `lang` matches the page text (axe
  `html-xml-lang-mismatch`) — 55: ask whether any assistive technology in scope reads `xml:lang`.
- Pass: on the sample and every recorded state that changes its text, the root `html` element has
  a `lang` attribute whose primary subtag is a registered language and names the language used
  most in the text that inherits it (title, visible text outside `lang` parts, accessible names).
  A differing `xml:lang` does not take this pass away; it goes to the queue.
- Not present: never; every sample has a root element that must declare its language.
- False positives to avoid: a registered language `Intl.DisplayNames` cannot name (`se`, `frr`,
  `csb`, `zxx`), which axe and bf051a pass; a region, script or variant subtag that does not fit
  (`en-US` on British English, `en-US-GB`): only the primary subtag decides (bf051a Passed Example
  2); upper case (`EN`, `FR`); a handful of foreign words, proper names, brand names or code in
  the root text (ucwvc8 Passed Example 2); foreign passages correctly inside `lang` parts (3.1.2;
  they do not change the default); a missing `Content-Language` header; `lang` on `svg` or `math`;
  a screen reader that does not switch voice (a user setting).

## Reporting

- File under: 3.1.1. A phrase or passage in another language inside a correctly declared page is
  3.1.2. A missing, blank or unknown `lang` comes from the template: one issue naming every sample
  it is on; a wrong language on translated pages that kept the template's value is one issue
  naming those samples; a switcher that leaves `lang` behind is one issue naming the states.
- Title patterns: "Pages do not declare their language", "Page language is declared as English on
  Dutch pages", "Language switch does not update the page language", "lang and xml:lang disagree"
- Severity: High when `lang` is missing, blank, unknown or names the wrong language on every page,
  so every page is read with the wrong pronunciation rules and braille table; Medium when a subset
  of pages or one state (the translated pages, the switched view) carries the defect while the
  rest of the site declares its language; Low when only `xml:lang` disagrees with a correct `lang`.
- Type: Technical: the attribute lives in the template, the router or the switcher script. Content
  when the CMS has a per-page language field that an editor filled wrong on translated pages.
- Evidence: a screenshot of the first screen of text (`screenshot <path>`) with the root start tag
  quoted in the issue body (`<html lang="en">` above Dutch text, or `<html>` with no `lang`); for
  a switch state, two screenshots before and after with their `lang` values. No `highlight`, no GIF.
- Recommendation: put the page's main language on the root element
  ([H57](https://www.w3.org/WAI/WCAG22/Techniques/html/H57)): `<html lang="nl">`, set from the
  page locale in the template and on a client-side switch (`document.documentElement.lang = 'en'`).
  For a PDF set the `/Lang` entry ([PDF16](https://www.w3.org/WAI/WCAG22/Techniques/pdf/PDF16))
  and `Lang` on foreign passages ([PDF19](https://www.w3.org/WAI/WCAG22/Techniques/pdf/PDF19)).
- Related: 3.1.2 Language of Parts (the Understanding "strongly encourages" it on multilingual
  sites even at Level A; a wrong page language often comes with unmarked passages: the page goes
  here, the passages there); 2.4.2 Page Titled (a title in the wrong language is a clue here).
