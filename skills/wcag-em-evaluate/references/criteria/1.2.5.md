# 1.2.5 Audio Description (Prerecorded)

Level AA · WCAG 2.0+ · Guideline 1.2 Time-based Media · Group: `media`

Sources:

## Requirement

> Audio description is provided for all prerecorded
> video content in synchronized media.

Terms (WCAG 2.2 glossary): **audio descriptions**: "narration added to the soundtrack to describe
important visual details that cannot be understood from the main soundtrack alone [...] Note 3:
Where all of the video information is already provided in existing audio, no additional audio
description is necessary." **prerecorded**: "information that is not live".

## In plain terms

Every prerecorded video with a soundtrack must be playable with narration that describes the
important visual details the soundtrack leaves out: actions, characters, scene changes, on-screen
text. It serves people who are blind or have low vision and helps people who find visuals hard to
interpret. Unlike 1.2.3, a transcript is not enough: at Level AA the description has to be audio.

## Applies when

- Present: a prerecorded video with an audio track that the user can play: a `video` element, an
  embedded player (YouTube, Vimeo, other `iframe`, `embed` or `object` players), or a video opened
  from a thumbnail, lightbox or carousel slide. Detect with `media.js`: every `media` entry with
  `kind` `video` or `embed` (`provider` names the third-party player); `structure.js` `iframes`
  (`src`, `title`) catches players the probe does not recognise. Live streams (`duration` is
  `Infinity`, or a "LIVE" badge in the player) belong to 1.2.4.
- Not present: `media.js` returns no `video` or `embed` entry in any state of the sample, or every
  video found has no audio (silent hero loops, muted product clips: video-only, 1.2.1).
  `animatedImages` are not synchronized media; leave them to 1.1.1 and 1.2.1.
- Exceptions: (1) synchronized media excludes "a media alternative for text that is clearly labeled
  as such": the page text carries all the video's information and visibly names the video as a
  repetition of it (ACT ab4d13). (2) Note 3, in Understanding's words: "if all of the important
  information in the video track is already conveyed in the audio track, no additional audio
  description is necessary": a talking head, a narrator who says everything shown. For a talking
  head, static text for the setting, credits and unspoken on-screen text suffices
  ([G203](https://www.w3.org/WAI/WCAG22/Techniques/general/G203)); G203 does not apply when several
  speakers are identified only by on-screen text and not by the audio (G203 Description), so mark
  such a video `needs-description`.

## axe-core

No axe-core rule is tagged with this criterion; everything below is manual.

## Manual procedure

1. Inventory the videos in every state of the sample. Reach hidden ones first: accept the consent
   dialog that blocks embeds, open the lightbox or tab that holds a player, advance the carousel.
   Run the probe in each state:

   ```bash
   agent-browser eval --stdin < <skill-dir>/scripts/probes/media.js
   agent-browser snapshot -i
   ```

   For each embed also `frame "iframe[src*='youtube']"`, `snapshot -i`, `frame main` to see its
   controls. Record per video: `selector`, `provider`, `sources`, `duration`, `controls`, `tracks`,
   `textAlternativeNearby`. Done when every video with a play control is listed, or the list is
   empty and the outcome is `not-present`.

2. Confirm each `video` element is prerecorded and has audio (ACT 1ec09b applicability: visible,
   non-streaming, contains audio):

   ```bash
   agent-browser eval --stdin <<'JS'
   (async () => {
     const out = [];
     for (const v of document.querySelectorAll('video')) {
       const m = v.muted; v.muted = true; await v.play().catch(() => {});
       await new Promise(r => setTimeout(r, 2000)); v.pause(); v.muted = m;
       out.push({ src: v.currentSrc, loaded: v.readyState > 0, live: v.duration === Infinity,
         duration: Number.isFinite(v.duration) ? v.duration : String(v.duration),
         hasAudio: !!(v.audioTracks?.length || v.mozHasAudio || v.webkitAudioDecodedByteCount) });
     }
     return out;
   })()
   JS
   agent-browser reload
   ```

   `hasAudio: false` with `duration > 0` → 1.2.1, drop it. `live: true` → 1.2.4, drop it. `loaded:
false` (or `duration: "NaN"`, the string the script emits because JSON turns a real NaN into
   null) → not loaded (autoplay policy, DRM): `click` the visible play control and re-run. The
   script and the `reload` put the original `muted` state back for the 1.4.2 pass; re-open the
   consent dialog, lightbox or tab before step 3. A YouTube or Vimeo embed has audio unless the page
   says otherwise. Done when the list holds only prerecorded videos with audio.

3. Look for the audio description mechanism of each remaining video, in this order:
   - A user-selectable described track
     ([G78](https://www.w3.org/WAI/WCAG22/Techniques/general/G78)): a control in the player or its
     settings menu named "Audio description", "AD", "Described" or "Audiodescriptie", or an
     audio-track menu with a "descriptive" entry. YouTube: `frame` into the iframe, `find role
button click --name "Settings"`, `snapshot -i`, `press Escape`; Vimeo: the "CC" menu. Native
     players: an `audio` element paired with the `video` and mixed in by the player.
   - A described version ([G173](https://www.w3.org/WAI/WCAG22/Techniques/general/G173),
     [G8](https://www.w3.org/WAI/WCAG22/Techniques/general/G8)): a link or button near the player
     such as "Watch with audio description" (`textAlternativeNearby`, the snapshot around the
     player). `tab new`, `open` its `href`, run step 2 there: it plays, `duration` ≥ the original.
   - A `tracks` entry with `kind` `descriptions`: counts only when the page ships a player that
     speaks it (a "Descriptions" toggle in the controls); a bare `video` with such a track has no
     working description in any browser (ACT 1ec09b Failed Example 3;
     [H96](https://www.w3.org/WAI/WCAG22/Techniques/html/H96) is advisory only).
   - Narration integrated in the soundtrack
     ([G226](https://www.w3.org/WAI/WCAG22/Techniques/general/G226)): claimable only through
     captions or a transcript that show the narrator naming what is on screen (step 4).

   Screenshot the player with its menu open. Done when each video is marked `track`, `version`,
   `spoken-track`, `integrated`, or `none`.

4. Judge whether the visuals carry information the audio leaves out (ACT 1ea59c Expectation; the
   glossary Note 3 case). The evaluator cannot hear; take frames and read the text forms instead:

   ```bash
   agent-browser eval --stdin <<'JS'
   (() => { document.querySelector('video').currentTime = 30 })()
   JS
   agent-browser wait 1000
   agent-browser screenshot "video" .notes/audit/evidence/<sample>--1.2.5-frame-30s.png
   agent-browser frame "<embed selector from media.js>"
   agent-browser find role button click --name "Play"
   agent-browser frame main
   agent-browser wait 5000
   agent-browser screenshot "<embed selector>" .notes/audit/evidence/<sample>--1.2.5-embed-1.png
   ```

   Repeat at five points spread over `duration`; on a YouTube embed `focus "<embed selector>"`, then
   `press 3`, `press 6` and `press 9` (the player seeks to 30, 60 and 90 % of the duration), with a
   screenshot after each. Read the captions when there are any: `get attr "video
track[kind='captions']" src`, then `agent-browser read <src>`; or `read` the transcript page
   linked near the player. On-screen text, charts, demonstrated steps, scene changes or wordless
   action that the captions do not mention → description is needed. A speaker in front of an
   unchanging background, captions covering everything shown → Note 3, none needed; then look for
   the G203 static text in `textAlternativeNearby` or the snapshot. No captions and no transcript →
   decide from the frames alone only when they are unambiguous (a pure talking head, or a silent
   demonstration with on-screen text), else record `cannot-tell` and queue "watch <src> and say
   whether the visuals show anything the narration does not say". Done when each video is marked
   `needs-description`, `covered-by-audio`, or `cannot-tell`.

5. Verify the description where a mechanism exists (ACT 1ea59c: the visual information "is
   available through its audio, or through an audio description track"). A spoken `descriptions`
   VTT: `get attr "video track[kind='descriptions']" src`, `agent-browser read <src>`, match its
   cues against the frames of step 4: cues naming the shown actions and text → verified; an empty
   file, placeholder cues or cues about another video → incorrect. A separate audio track or
   described version: the accessibility tree shows the control's name and that it toggles, never
   the sound; record it as present and queue "listen to the described track of <src> and confirm it
   describes <the items seen in the frames>". The described version must load and play. Done when
   each mechanism is `verified`, `present-unverified`, or `broken`.

6. When the video is presented as a media alternative for text (ACT ab4d13): Expectation 1, all
   information in the video is in visible page text that is in the accessibility tree (compare
   frames and captions with the surrounding text); Expectation 2, visible text names the video as
   an alternative ("the same information in video form"). Check with `is visible "<css>"`; a
   `display: none` label does not count. Done when the video is marked `alternative-for-text` or
   the claim is rejected.

7. A player you cannot open (blocked embed, login wall): record `cannot-tell` with the embed URL
   and the blocker. Done when every inventoried video carries one mark from steps 3 to 6.

## Deciding

- Fail (certainty ≥ 90): a video marked `needs-description` (unspoken visuals confirmed against
  captions or a transcript) and mechanism `none` (90). The mechanism is only a `descriptions` track
  in a bare `video` element, nothing speaks it, and the video is `needs-description` (90; ACT 1ec09b
  Failed Example 3). The described version or track is `broken`: dead link, empty player, no audio
  in the file (90). The video is marked `needs-description` (step 4) and its only alternative is a
  transcript or text page (90; ACT 1ec09b Failed Example 2: a transcript meets 1.2.3 only).
- Fail (70–89): `needs-description` decided from frames alone (no captions to confirm the audio is
  silent about them) and mechanism `none` (75). A spoken `descriptions` VTT that is empty, filled
  with placeholders, or about other content (80; ACT 1ea59c Failed Example 2). A media-alternative
  claim rejected: the text visibly lacks information the frames show, or the label is not visible
  or not in the tree, and no other mechanism exists (75; ACT ab4d13 Failed Examples 1 to 4). A
  described track whose VTT cues leave the long dialogue-free stretches seen in the frames
  undescribed (70; [F113](https://www.w3.org/WAI/WCAG22/Techniques/failures/F113)).
- Needs confirmation (50–69): frames mix a speaker with slides, demonstrations or lower-thirds and
  there are no captions: ask the human whether the narrator says what the slides show (60); several
  speakers named only by lower-thirds are `needs-description`, never a G203 static-text case. A
  talking head whose only unspoken visuals are names, titles or a URL on screen, with no static
  text nearby: ask whether that text matters for the page's purpose (55). A track labelled as
  described that has the same source URL as the main audio: ask the human to listen (55).
- Pass: every prerecorded video with audio has a working mechanism (`track`, `version`,
  `spoken-track`, or `integrated` confirmed by captions or a transcript), or is `covered-by-audio`
  (Note 3, with the G203 static text for a talking head, and not several speakers named only on
  screen), or is a labelled media alternative for text (ab4d13, both expectations met).
- Not present: no prerecorded video with an audio track in any state of the sample.
- False positives to avoid: silent background or product loops (1.2.1, or decorative); live streams
  (1.2.4); a narrator who says everything shown, confirmed by captions; a labelled video alternative
  for visible page text; a missing `descriptions` track by itself (H96 is advisory); a described
  version offered as a separate video instead of a toggle (G173 is sufficient); an audio-track menu
  that lists only languages (not a description, but not the defect either).

## Reporting

- File under: 1.2.5 for a prerecorded video with audio whose important visuals are not described. A
  video with neither description nor transcript fails 1.2.3 (Level A) and 1.2.5 by one defect: file
  it under 1.2.3, name 1.2.5 in the body, record `fail` for both in the findings. With a full
  transcript only 1.2.5 fails and the issue goes here. Missing captions on the same video: a
  separate issue under 1.2.2. Unnamed player controls: 4.1.2; a player the keyboard cannot operate:
  2.1.1. One issue per video; the same video on other samples is one issue naming them.
- Title patterns: "Video has no audio description", "Description track is not played by the
  player", "Described version of the video does not load"
- Severity: High when the video is the only carrier of its content (a tutorial, a lecture with
  slides, a demonstration, instructions) or the described version is broken; Medium when the page
  text covers the essentials and the video adds unspoken detail, or every video on the product
  lacks description; Low when the unspoken visuals are marginal (a name caption, credits, a logo)
  or a description exists but is hard to find.
- Type: Content when the description has to be written and recorded (no track, no version, wrong
  or incomplete description). Technical when a described track or version exists and the player
  fails to expose it: a `descriptions` track nothing plays, a missing menu entry, a dead link.
- Evidence: a screenshot of the player with its controls or settings menu open, `highlight` on the
  player, plus one or two frames from step 4 with the undescribed visual information annotated. A
  GIF when the defect is a menu that lacks the entry or a toggle that does nothing.
- Recommendation: Provide the description as audio: a second, user-selectable audio track
  ([G78](https://www.w3.org/WAI/WCAG22/Techniques/general/G78)) or a described version linked next
  to the original ([G173](https://www.w3.org/WAI/WCAG22/Techniques/general/G173)); where the
  pauses are too short, an extended described version
  ([G8](https://www.w3.org/WAI/WCAG22/Techniques/general/G8)); for a video still in production,
  narration with the descriptions built in
  ([G226](https://www.w3.org/WAI/WCAG22/Techniques/general/G226)). For a talking head with one
  speaker, add the static text of
  [G203](https://www.w3.org/WAI/WCAG22/Techniques/general/G203). Use
  `track kind="descriptions"` ([H96](https://www.w3.org/WAI/WCAG22/Techniques/html/H96)) only with
  a player that speaks it. Cite [F113](https://www.w3.org/WAI/WCAG22/Techniques/failures/F113)
  when the soundtrack has pauses in which the visuals could have been described and were not.

  ```html
  <video controls src="/media/tour.mp4"></video>
  <p><a href="/media/tour-described.mp4">Watch the tour with audio description</a></p>
  ```

- Related: 1.2.3 (same defect at Level A when no text alternative exists, file there); 1.2.2
  (captions, separate issue); 1.2.8 (AAA, extended text alternative); 1.2.1 (silent video, file
  there instead); 1.1.1 (unnamed player or poster image); 4.1.2 and 2.1.1 (player controls).
