# 2.4.1 Bypass Blocks

Level A · WCAG 2.0+ · Guideline 2.4 Navigable · Group: `keyboard` (also `consistency`)

## Requirement

> A mechanism is available to bypass blocks of content that are repeated on multiple web pages.

Terms (WCAG 2.2 glossary): **mechanism**: "process or technique for achieving a result [...] Note 1:
The mechanism may be explicitly provided in the content, or may be relied upon to be provided by
either the platform or by user agents, including assistive technologies. Note 2: The mechanism needs
to meet all success criteria for the conformance level claimed." Note 2 is the clause that decides
step 6: a skip control that no key reaches (2.1.1) or that the accessibility tree never carries
(4.1.2) is not a mechanism, however well it works with a mouse. **web page**: "a non-embedded
resource obtained from a single URI using HTTP plus any other resources that are used in the
rendering or intended to be rendered together with it by a user agent [...] Example 2: A web mail
program built using Asynchronous JavaScript and XML (AJAX). The program lives entirely at
http://example.com/mail, but includes an inbox, a contacts area and a calendar. Links or buttons are
provided that cause the inbox, contacts, or calendar to display, but do not change the URI of the
page as a whole." Example 2 decides the single-page-app case: inbox, contacts and calendar are views
of **one** web page, so a header they share is not repeated "on multiple web pages" and its absence
of a skip mechanism is not a fail here (see the second Understanding note under "Applies when").
"Block" is not defined in the WCAG glossary; the Understanding and the ACT glossary below supply the
working definition.

Terms (ACT glossary, used by all five rules; quoted from cf77f2):

- **Block of content**: "a set of nodes from that page for which all the following are true:
  content: there is at least one node which is perceivable content in the block; and continuity: if
  two nodes are in the block, then any node between them (in tree order) is also in the block; and
  downward closure: if a node is in the block, then all its descendants are also in the block; and
  parent closure: if all children of a node are in the block, then this node is also in the block."
- **Block of repeated content**: "A block of content B, inside an HTML web page P, is a block of
  repeated content if both the following are true: distance 1: there exist an instrument in P which
  leads the user to another HTML web page P' whose URL has a different host, port (including default
  port for special URL), or path; and repeated: there exist a block of content in P' which is
  equivalent to B." Both halves matter: the comparison page must be reachable from this page by one
  instrument, and a differing query string or fragment alone does not make P' another page.
- **Equivalent resource**: "Non-identical resources can still be equivalent resources by equally
  complying to the expectation formed by the user when navigating to them, thus serving an
  equivalent purpose." A menu whose current item changes, or a header whose breadcrumb differs, is
  still equivalent.
- **Non-repeated content after repeated content**: "the node is perceivable content; and the node is
  not part of any block of repeated content; and the node is after (in tree order in the flat tree)
  at least one block of repeated content."
- **Perceivable content**: "the node is palpable content; and the node is either visible or included
  in the accessibility tree; and if the node is an element, it does not have a semantic role of none
  or presentation." Visible **or** in the tree: an off-screen paragraph still counts as content that
  a skip control must clear.
- **Just before a node**: "N and P are the same node; or N is not perceivable content and there is
  no node of perceivable content between N and P (in tree order in the flat tree)." This is why an
  empty `span` at the end of the header is a valid skip target (step 2).

## In plain terms

Every page of a site opens with the same header, navigation, search and banners; someone who reads
or tabs through a page in order meets all of it again before anything new. The goal, in the W3C's
own summary, is that "Users can more easily navigate by keyboard" by the author providing "a means
of skipping repeating content". That means a "skip to main content" link, a `main` landmark, a
heading where the content starts, or a control that collapses the block. It is not only keyboard
users: screen-reader users "can avoid having to hear all header content and dozens of navigation
links on every page", keyboard users "can reach content with fewer keystrokes" which otherwise "may
cause severe physical pain for some users", and magnifier users "do not have to search through the
same header content [...] to find where the main content begins each time they enter a new page".

## Applies when

- Present: a block of repeated content sits before the sample's primary content: a header, a `nav`,
  a search form, a sidebar, a cookie banner, an ad `iframe` or a filter panel that another page of
  the set shows too. The Understanding names the usual ones: "Examples of repeated blocks of content
  include but are not limited to navigation links, header content, and advertising frames." Found
  with `recon/<sample>-structure.json` and the outline comparison of step 1.
- Not present: no repeated block precedes the primary content in any state: a standalone login,
  error or print page whose shared parts are a logo, a single link or a footer after all content; or
  a page whose source order already puts the content first and positions the navigation with CSS
  ([C6](https://www.w3.org/WAI/WCAG22/Techniques/css/C6), advisory — see step 1, K = 0).
- Cannot tell: the comparison page P' cannot be opened (behind authentication the session does not
  hold, a paywall, a 403), so the "repeated" half of the definition cannot be checked; or the only
  candidate mechanism is a server-side or account-level setting the evaluator cannot exercise (a
  cf77f2 assumption: "a global 'settings' page, can provide a functionality similar to Block of
  repeated content is collapsible by serving a modified version of the page; in which case this rule
  would fail but Success Criterion 2.4.1 Bypass blocks could nonetheless be satisfied"). Record
  `cannot-tell` with the page that could not be reached and send it to the confirmation queue.
- Exceptions: none in the normative text. Five limits from the sources, each of which changes an
  outcome:
  - Size: "Small repeated sections such as individual words, phrases or single links are not
    considered blocks for the purposes of this provision." A repeated logo link, a language switch
    or a single "Contact" link is not a block.
  - User-agent redundancy: "It is not the intent of this success criterion to require authors to
    provide methods that are redundant to functionality provided by the user agent. Most web
    browsers provide keyboard shortcuts to move the user focus to the top of the page, so if a set
    of navigation links is provided at the bottom of a web page providing a 'skip' link may be
    unnecessary." cf77f2 assumes the same for the end of the page: "repeated content that is at the
    end of the page (and not followed any non-repeated content) can be bypassed by means provided by
    user agents (such as pressing the 'End' key to scroll to the bottom of the page). Therefore,
    they do not need any other way of being bypassed and are ignored by this rule." A footer after
    all content is therefore never the finding.
  - Within a set only: "Although the success criterion does not specifically use the term 'within a
    set of web pages', the concept of the pages belonging to a set is implied. An author would not
    be expected to avoid any possible duplication of content in any two pages that are not in some
    way related to each other, and are not 'web pages that share a common purpose and that are
    created by the same author, group or organization'." Repetition shared with an unrelated
    third-party site is out of scope.
  - Within one page only: "Even for web pages that are not in a set, if a web page has blocks of
    text that are repeated within the page it may be helpful (but not required) to provide a means
    to skip over them." A block that repeats inside this one page, and on no other page of the set,
    is recorded as an observation, never as a fail of this criterion.
  - Structure on a single page belongs to 1.3.1: "Although this success criterion deals with blocks
    of content that are repeated on multiple pages, we also strongly promote structural markup on
    individual pages as per Success Criteria 1.3.1." Missing headings or landmarks that were never
    the bypass mechanism are filed under 1.3.1, not here.
- Not this procedure: [PDF9](https://www.w3.org/WAI/WCAG22/Techniques/pdf/PDF9) is the PDF
  equivalent of H69 and applies only when the sample is a PDF document. `agent-browser` renders a
  PDF in the browser's plugin viewer, where neither axe nor any probe reaches its tag tree: record
  `cannot-tell`, name the file, and send it to the confirmation queue with PDF9 as the fix to check
  by hand. A `frame`/`frameset` sample is the other case cf77f2 steps around — it assumes framesets
  are not used, so a frameset that groups repeated material into titled frames
  ([H64](https://www.w3.org/WAI/WCAG22/Techniques/html/H64)) fails the rule while the criterion can
  still be satisfied; check the frame titles with `frame` and record `pass` with that reason.

## axe-core

| Rule     | Decides                                  | Result → outcome                   |
| -------- | ---------------------------------------- | ---------------------------------- |
| `bypass` | in-page link, heading or `main` landmark | incomplete → step 2; pass → step 2 |

`bypass` is page-level, in the default WCAG 2.0 A & AA set, tagged `cat.keyboard`, and needs review
only: its `issueType` is `needs review`, so it never reports a violation and never produces a
certainty-100 fail on its own. Incomplete means none of the three exists, the strongest automated
signal here; pass proves existence only. The data pack maps this one rule to all five ACT rules
(cf77f2, 047fe0, b40fd1, 3e12e1, ye5d6e), so an incomplete is a direct pointer at a cf77f2 failure,
while a pass says nothing about which of the four mechanisms actually works.

Settles: nothing on its own. Leaves open: whether any block is in fact repeated on another page of
the set (axe never opens a second page); whether the skip control is focusable, reachable early in
the Tab order and lands just before the non-repeated content; whether a heading is visible and in
the accessibility tree and sits in non-repeated content; whether a landmark's first perceivable
content is non-repeated; whether a control before a block both hides it and removes it from the
tree; whether a second, interleaved block can be skipped; and every state other than the one axe ran
on (cookie banner, open menu, mobile layout).

## Manual procedure

Mode: keyboard only. No screen reader is involved. The accessibility tree (`agent-browser snapshot`)
shows what a screen reader would be given — the headings, landmarks and names that exist — but it
cannot show heading-to-heading or landmark-to-landmark navigation actually happening; record what
exists and never claim an AT behaviour you did not observe. Every `eval --stdin` body is wrapped in
`(() => { ... })()`, because a top-level `const` stays declared for the life of the page and a
second run then throws "Identifier ... has already been declared".

1. Map the blocks of repeated content and the non-repeated content (cf77f2 applicability). Read
   `recon/<sample>-structure.json` (`landmarks`, `mainCount`, `headings`, `skipLinks`, `iframes`,
   `visuallyStyledHeadings`) and `recon/<sample>-tree.txt`. Pick P' by the ACT "distance 1" rule: a
   page this sample links to whose URL differs in host, port or path — in practice another sample
   from `index.md` that the header links to. Open it in a second tab, snapshot it, and mark as
   repeated every block whose equivalent appears in both outlines. Then locate the primary content
   (the `main` landmark, else the first heading or paragraph in no repeated block) and count K, the
   Tab stops before it:

   ```bash
   agent-browser tab new
   agent-browser open <url of P'>
   agent-browser wait --load networkidle
   agent-browser snapshot -d 3 > .notes/audit/recon/<sample>-2.4.1-pprime.txt
   agent-browser tab close
   diff .notes/audit/recon/<sample>-tree.txt .notes/audit/recon/<sample>-2.4.1-pprime.txt
   agent-browser eval --stdin <<'EOF'
   (() => {
     const main = document.querySelector('<primary content css>');
     const q = 'a[href],button,input,select,textarea,[tabindex]';
     const before = [...document.querySelectorAll(q)].filter(e => !e.disabled && e.tabIndex >= 0
       && e.getClientRects().length && main && (e.compareDocumentPosition(main) & 4));
     return { K: before.length, stops: before.slice(0, 15).map(e => e.localName
       + (e.id ? '#' + e.id : '') + ' "'
       + (e.getAttribute('aria-label') || e.textContent || '').replace(/\s+/g, ' ').trim()
       .slice(0, 30) + '"') };
   })()
   EOF
   ```

   Lines common to both files are the repeated blocks; lines only in this sample are its own
   content. `compareDocumentPosition(main) & 4` is DOCUMENT_POSITION_FOLLOWING, so `before` is every
   Tab stop that precedes the primary content. A worked line for the findings file: `header > nav
"Home Products Support" (repeated, 1 of 2 samples) · main#content · K=23 · first stop a#logo
"Acme"`. K = 0 with the content first in the source and the navigation moved by CSS is
   [C6](https://www.w3.org/WAI/WCAG22/Techniques/css/C6) in use: there is no block of repeated
   content before non-repeated content, every ACT rule passes vacuously (cf77f2 passed example 7,
   047fe0 passed example 9, b40fd1 passed example 4) and the outcome is `pass`, not `not-present`,
   when a repeated block still exists later on the page. Done when the findings file lists every
   repeated block in DOM order (selector, role, first words, whether it was seen on P'), the primary
   content selector and K; when no repeated block precedes the primary content in any state, record
   `not-present` and end here.

2. Instrument that moves focus to the non-repeated content (ye5d6e;
   [G1](https://www.w3.org/WAI/WCAG22/Techniques/general/G1),
   [G123](https://www.w3.org/WAI/WCAG22/Techniques/general/G123),
   [G124](https://www.w3.org/WAI/WCAG22/Techniques/general/G124)). ye5d6e has one expectation: "For
   each test target, there exists at least one instrument inside it to move focus just before a node
   of non-repeated content after repeated content." Gather the candidates from three places, because
   no single one is complete: `skipLinks` in `structure.js` only collects `a[href^="#"]` with a
   fragment longer than `#`, caps the list at 12 and carries no `selector` (address one by its href,
   `a[href="#main"]`), so a skip `button`, a `div role="link"` and a control using `href="#"` with
   scripted focus never appear there; `order` from `focusables.js` carries every element with
   `tabIndex >= 0` in real Tab order (positive `tabindex` first), capped at 400; and
   `clickableNotFocusable` carries the mouse-only ones.

   ```bash
   agent-browser eval --stdin < <skill-dir>/scripts/probes/focusables.js
   agent-browser eval --stdin <<'EOF'
   (() => {
     const main = document.querySelector('<primary content css>');
     const sel = 'a[href],button,[role="link"],[role="button"],[tabindex],[onclick]';
     return [...document.querySelectorAll(sel)]
       .filter(e => main && (e.compareDocumentPosition(main) & 4))
       .map(e => ({ el: e.localName + (e.id ? '#' + e.id : ''), href: e.getAttribute('href'),
         tabindex: e.getAttribute('tabindex'), inTabOrder: e.tabIndex >= 0,
         name: (e.getAttribute('aria-label') || e.textContent || '')
           .replace(/\s+/g, ' ').trim().slice(0, 50) }))
       .filter(e => (e.href || '').startsWith('#')
         || /skip|jump|bypass|ga naar|direct naar|naar de inhoud/i.test(e.name));
   })()
   EOF
   ```

   A candidate is any of those whose name says where it jumps ("Skip to main content", "Direct naar
   de inhoud"); the name may come from `aria-label` on an icon (ye5d6e passed example 6) and the
   element may be a `button` (cf77f2 passed example 8) or a `div` with `role="link"` and
   `tabindex="0"` (ye5d6e passed example 5). Reload, Tab to it (at most K presses), note whether it
   shows while focused, and activate it:

   ```bash
   agent-browser reload
   agent-browser press Tab  # repeat until the candidate has focus
   agent-browser is visible "<skip control css>"
   agent-browser press Enter
   agent-browser wait 500
   agent-browser press Tab
   agent-browser eval --stdin <<'EOF'
   (() => {
     const main = document.querySelector('<primary content css>'), a = document.activeElement;
     const after = main && (main.contains(a) || !!(main.compareDocumentPosition(a) & 4));
     return (after ? 'IN CONTENT ' : 'BEFORE CONTENT ') + a.localName + (a.id ? '#' + a.id : '')
       + ' "' + (a.getAttribute('aria-label') || a.textContent || '').trim().slice(0, 40) + '"';
   })()
   EOF
   ```

   `IN CONTENT` on a control of the primary content: the instrument works. Chromium moves the
   sequential focus start to the fragment target, so the target needs no `tabindex="-1"` for this
   check to succeed — verified against `<a href="#main">` over a `<div id="main">` with no
   `tabindex`, where the next Tab landed on the first link inside it. `BEFORE CONTENT` on a link of
   a repeated block means one of three things, and the findings line says which: the target lies
   inside the block with perceivable content still between it and the content (ye5d6e failed example
   3), the href points at no such id (`targetExists: false`; failed example 2), or the control only
   scrolled (`href="#"` with no scripted `focus()`). Apply "just before a node" before calling it a
   fail: a target inside the repeated block still passes when no perceivable content follows it
   inside that block (passed example 7, an empty `span` at the end of the header), and a target that
   is not the first node of the content passes when only non-perceivable nodes precede it (passed
   example 8, `<hr>` then the `span`). ye5d6e sets no position limit — "Rather than trying to fix an
   arbitrary value (e.g. 'the skip link must be among the first 5 focusable elements') [...] this
   rule only checks its existence" — but it warns that "it is possible to pass this rule without
   satisfying Success Criterion 2.4.1 Bypass blocks if the skip link is too far away from the start
   of the page", so record the `order` index against K. Done when each candidate has "`order` index
   of N, shown on focus yes/no, IN CONTENT / BEFORE CONTENT with the reason" recorded, or the line
   "no instrument to move focus to the non-repeated content".

3. Heading for the non-repeated content (047fe0;
   [H69](https://www.w3.org/WAI/WCAG22/Techniques/html/H69)). The expectation is a conjunction of
   four conditions under a vacuous branch: "In each test target, either there is no non-repeated
   content after repeated content or there exists an element for which all the following are true:
   the element is non-repeated content after repeated content; and the element is a semantic
   heading; and the element is visible; and the element is included in the accessibility tree."
   Check them one by one against the `headings` list and the tree:

   ```bash
   agent-browser snapshot -s "<primary content css>" -d 2
   agent-browser get box "<heading css>"
   ```

   Semantic heading: `h1`–`h6` or any element with `role="heading"`; a `div role="heading"
aria-level="1"` counts (passed example 6) and a heading whose whole text is an image `alt` counts
   (passed example 7). It need not be the first node of the content — an `<hr>`, a decorative image
   or a numbering `span` before it is fine (passed examples 4, 5, 8), and 047fe0 accepts
   non-repeated content such as a breadcrumb before it. In the tree: an `aria-hidden` heading is
   absent from `snapshot -s` output (failed example 3) — confirmed, `snapshot -s` answers "✗ No
   accessibility node found for selector '...'" for an `aria-hidden` subtree. Visible: an off-screen
   heading stays in the snapshot and arrives in `headings` with `visible: true`, because the probe's
   visibility test is box size plus `visibility` plus `[hidden]`, so read its box — a negative `y`
   or `x` (measured: `y: -977` for `position:absolute; top:-999px`) is 047fe0 failed example 2.
   Semantic: a `strong`, `p` or `div` merely styled large is failed example 1; the
   `visuallyStyledHeadings` list finds the block-level ones (`p`, `div`), while an inline `strong`
   or `span` is filtered out of that list by its `display: inline`, so compare the full-page
   screenshot with `headings` as well. Inside a repeated block is failed example 4. Two
   Understanding qualifications go in the notes but not in this step's verdict: 047fe0 "does not
   expect the heading to accurately describe its corresponding section. However, having non
   descriptive headings fails Success Criterion 2.4.6", and "When headings are rendered without
   sufficient visual cues, they are not perceived as headings by sighted users. In this case,
   passing this rule might still fail Technique H69 [...] Additionally, this is likely a failure of
   Success Criterion 1.3.1". Done when the step records "heading <selector> level N: non-repeated
   yes/no, semantic yes/no, visible yes/no, in tree yes/no" for the best candidate, or "no heading
   in the non-repeated content".

4. Landmark with the non-repeated content (b40fd1;
   [ARIA11](https://www.w3.org/WAI/WCAG22/Techniques/aria/ARIA11),
   [H97](https://www.w3.org/WAI/WCAG22/Techniques/html/H97)). Three conditions under the same
   vacuous branch: "Within each test target, either there is no non-repeated content after repeated
   content or there exists an element for which all the following are true: the element is an
   inheriting semantic landmark; and the first perceivable content (in tree order in the flat tree)
   which is an inclusive descendant of the element is non-repeated content after repeated content;
   and the element is included in the accessibility tree." b40fd1 notes "Most of the time, this rule
   passes by enclosing the primary content of the page in a main landmark", and `<div role="main">`
   counts as well (passed example 2).

   ```bash
   agent-browser snapshot -c -d 2
   agent-browser snapshot -s "<landmark css>" -d 2
   ```

   Read `landmarks` and `mainCount` from `structure.js` first: the probe lists landmarks without
   checking `aria-hidden`, so a `main aria-hidden="true"` still appears there and only the `snapshot
-s` answer exposes it (b40fd1 failed example 3). `mainCount` above 1 is not a fail for this rule
   — several elements with role `main` pass as long as one is in the tree (passed example 3) — but
   it is a 1.3.1/4.1.2 note. The first-perceivable-content condition is what a `main` whose first
   child is the repeated `nav` fails (failed example 2 is its mirror: the landmark holds no
   non-repeated content at all); a breadcrumb or a decorative image first is fine. Visibility is not
   required: "This rule assumes that landmarks are intended to users of Assistive Technologies and
   are not necessarily rendered in a visible way. Therefore, it does not require the main landmark
   to be visible." Done when the step records "landmark <selector> role <role>: in tree yes/no,
   first perceivable descendant non-repeated yes/no", or "no landmark holding the non-repeated
   content".

5. Control that collapses each repeated block (3e12e1;
   [SCR28](https://www.w3.org/WAI/WCAG22/Techniques/client-side-script/SCR28)). This rule has two
   expectations that must both hold, for **every** block, not just one: "For each block of repeated
   content in each test target, which is before (in the flat tree) at least one node of non-repeated
   content after repeated content, all the following are true: there exists an instrument to make
   all nodes in this block not visible; and there exists an instrument to remove all nodes in this
   block from the accessibility tree." Usually one control does both. For each repeated block from
   step 1 that steps 2 to 4 left without a mechanism, and for every cookie banner and collapsed
   menu, find a control (`[aria-expanded]`, `[aria-controls]`, the banner's Accept, Reject or
   Close), operate it from the keyboard and test both halves separately:

   ```bash
   agent-browser focus "<control css>"
   agent-browser press Enter
   agent-browser wait 300
   agent-browser is visible "<block css>"
   agent-browser get box "<block css>"
   agent-browser snapshot -s "<block css>"
   ```

   Three readings, because `is visible` alone decides neither expectation — measured, it answers
   `true` both for a block with `aria-hidden="true"` and for a block moved to `top: -999px` (box `y:
-999`). Read them together: the block is not visible when `is visible` answers `false` or `get
box` puts it wholly off the page (a negative `y`/`x` larger than its height/width, or a zero
   size); the block is out of the tree when `snapshot -s` answers "✗ No accessibility node found".
   Both must hold after one control. A control that only moves the block off-screen meets the first
   expectation and fails the second, since `snapshot -s` still lists it (3e12e1 failed example 2); a
   control that only sets `aria-hidden` meets the second and fails the first, since the block is
   still on screen (failed example 3); `display: none` or the `hidden` attribute meets both.
   Position: the rule itself sets no requirement, but its background is explicit that "instruments
   located after (in reading order) the block they collapse are likely not satisfying Success
   Criterion 2.4.1 Bypass blocks, which this rule is designed for. Thus, it is possible to pass this
   rule without satisfying Success Criterion 2.4.1 Bypass blocks" — a toggle after its block is a
   fail of the criterion even when the rule passes. Restore the block afterwards (`press Enter`
   again, or `reload`). Done when each block has "collapsible by <control> (visible false, not in
   tree), control before/after the block" or "no collapse control".

6. Check that the winning mechanism is itself a mechanism (the glossary Note 2; cf77f2: "The
   instruments used to pass this rule (if any), must meet all level A Success Criteria in order to
   fully satisfy Success Criterion 2.4.1 Bypass Block"). For the control that passed step 2 or step
   5: it must be in the Tab order and in the accessibility tree.

   ```bash
   agent-browser eval --stdin < <skill-dir>/scripts/probes/focusables.js
   agent-browser snapshot -i | grep -i "<the control's name>"
   ```

   In `focusables.js`: absent from `order` means `tabindex="-1"` or not focusable at all; present in
   `clickableNotFocusable` means a mouse-only control (a `div[onclick]` with no `tabindex`), which
   fails 2.1.1 and cannot be the mechanism; present in `ariaHiddenFocusable` means it sits in an
   `aria-hidden` subtree, so the tree never carries it and it fails 4.1.2. cf77f2 adds the reason
   this matters even when a heading or landmark passes: "If the instruments used to pass some of the
   atomic rules are not keyboard accessible, or not included in the accessibility tree, passing this
   rule can still leave many users without a way to bypass blocks of repeated content." Done when
   the winning mechanism is recorded as keyboard-operable and present in the tree, or the failing
   half is named.

7. Interleaved blocks and the other states. cf77f2 warns that one mechanism is not enough: "This
   rule only checks if there is a way to bypass at least one section of repeated content. On pages
   with several interleaved repeated and non-repeated content, this is not sufficient to satisfy
   Success Criterion 2.4.1 Bypass blocks." Past the primary content start, look for a further block
   that step 1 marked repeated (a filter panel, an in-content promo, a repeated sidebar) sitting
   before more of the page's own content; count its stops with the step 1 eval using that block's
   following content as `main`, and look for a G123 link at its start or a heading right after it —
   the Understanding's own second example is exactly this: "An e-commerce website includes a long
   list of filters prior to the search results listing. A link above the list enables users to skip
   the filters and get to the product results quickly." A block that repeats only within this page
   is an observation, not a fail (the Understanding note under "Applies when"). Then repeat steps 2
   to 5 in each state of `recon/<sample>-states.md` that changes the top of the page:

   ```bash
   agent-browser reload            # cookie banner present: Tab to it, dismiss with Enter, re-walk
   agent-browser set viewport 320 900
   agent-browser reload
   agent-browser eval --stdin < <skill-dir>/scripts/probes/structure.js
   agent-browser set viewport 1280 900
   ```

   With the cookie banner on screen the skip control must still be reachable before the header; with
   a mega menu that opens on focus the skip control must precede it; in the mobile layout a menu
   behind a hamburger bypasses the block only when its toggle precedes it and hides it from both
   screen and tree (step 5's two halves). Done when every interleaved block and every state has a
   mechanism recorded or a defect line.

8. Evidence for every defect: a recording of the first presses and a page screenshot.

   ```bash
   agent-browser record start .notes/audit/evidence/<sample>-2.4.1-<slug>.webm
   agent-browser reload
   agent-browser press Tab
   agent-browser press Tab
   agent-browser wait 300
   agent-browser press Enter
   agent-browser wait 500
   agent-browser press Tab
   agent-browser wait 300
   agent-browser record stop
   agent-browser highlight "<skip control css or first stop css>"
   agent-browser screenshot .notes/audit/evidence/<sample>-2.4.1-<slug>.png
   ```

   Done when the recording shows where focus ends up and the screenshot is saved.

The `consistency` pass re-runs steps 2 to 4 on every sample and writes its rows to `consistency.md`:
a sample without the mechanism the others have fails here for that sample; a mechanism that moves or
changes name between samples goes to 3.2.3 / 3.2.4.

## Deciding

- Fail (certainty ≥ 90): a block of repeated content larger than a single link or phrase precedes
  the primary content and none of the four mechanisms holds — no instrument lands IN CONTENT, no
  visible in-tree semantic heading in the non-repeated content, no landmark whose first perceivable
  content is non-repeated, no collapse control before the block (cf77f2 failed example 1; axe
  `bypass` incomplete) — 95; the only skip link points to an id that does not exist (`targetExists:
false`; ye5d6e failed example 2) or does nothing on Enter — 95; the only skip control never takes
  focus in the Tab walk, or appears in `clickableNotFocusable` as a mouse-only control (2.1.1, so
  not a mechanism) — 90; `main` starts with the repeated `nav`, so its first perceivable content is
  not non-repeated content (b40fd1 failed example 2), and no other mechanism exists — 90; the only
  landmark holding the content is `aria-hidden` (b40fd1 failed example 3) — 90; the only heading in
  the non-repeated content is `aria-hidden` (047fe0 failed example 3) or sits outside the page box
  with a negative `get box` `y`/`x` (failed example 2) — 90; the only "heading" is a `strong`, `p`
  or `div` styled to look like one with no heading role (047fe0 failed example 1, seen in
  `visuallyStyledHeadings` or the screenshot) — 90; the only heading sits inside a repeated block
  (failed example 4) — 90.
- Fail (70–89): the only skip control lands BEFORE CONTENT on perceivable content inside a repeated
  block, with more perceivable content of that block after the target (ye5d6e failed example 3), or
  it only scrolled without moving focus — 85; the only collapse control hides the block from the
  screen but leaves it in the accessibility tree (3e12e1 failed example 2, `snapshot -s` still
  answers) — 85; the only collapse control sets `aria-hidden` but leaves the block on screen (failed
  example 3, `get box` still on the page) — 85; the only skip control sits after the block it should
  skip (`order` index ≥ K; ye5d6e: "too far away from the start of the page") — 80; the only
  collapse control comes after the block it hides (3e12e1 background: "likely not satisfying Success
  Criterion 2.4.1") — 80; the only skip control sits in an `aria-hidden` subtree
  (`ariaHiddenFocusable`), so the tree never carries it and it fails 4.1.2 — 75; a second,
  interleaved block of repeated content sits between the skip target or landmark start and more of
  the page's own content, with no G123 link and no heading past it (cf77f2: one bypassed section "is
  not sufficient") — 75; the only heading comes deep inside the non-repeated content, past a
  screenful of it (047fe0 background: the rule is lenient, H69 and the criterion are not) — 70; the
  winning heading is rendered with no visual cue that it is a heading (047fe0: "might still fail
  Technique H69 [...] and Success Criterion 2.4.1"; file the 1.3.1 issue too) — 70.
- Needs confirmation (50–69): a landmark or heading exists (ARIA11, H69) while the skip control is
  broken, unreachable or misplaced — 60; ask "does this audit accept landmarks and headings alone,
  or must a link-based mechanism work?", quoting cf77f2: "Techniques and solutions based on links
  will benefit all users (for example, sighted keyboard users with no other assistive technology)
  and are therefore recommended." A repeated group of two or three links and nothing else, with no
  mechanism — 60; ask whether it counts as a block, since "individual words, phrases or single links
  are not considered blocks". The only candidate mechanism is a server-side or account-level setting
  that serves a reduced page (a cf77f2 assumption) — 55; ask the client to demonstrate it. The
  sample is a frameset whose frames carry `title` attributes (H64) — 55; ask, since cf77f2 does not
  cover framesets.
- Pass: for every block of repeated content that precedes non-repeated content, in every state, at
  least one holds — a focusable, in-tree instrument before the block that lands just before the
  non-repeated content (G1, G123, G124), whether or not it shows while focused (that is 2.4.7); a
  semantic heading in the non-repeated content that is visible and in the tree (H69); a landmark in
  the tree whose first perceivable descendant is non-repeated content (ARIA11); or a control before
  the block that both hides it and removes it from the tree (SCR28). Also `pass` when the source
  order puts the content before every repeated block (C6) so no repeated block precedes it.
- Not present: no block of repeated content precedes the primary content in any state.
- Cannot tell: P' could not be opened, so "repeated" could not be verified; or the sample is a PDF
  whose tag tree the browser viewer does not expose (PDF9 is checked by hand).
- False positives to avoid: a skip link hidden until focused (G1; ye5d6e passed example 4, 3e12e1
  passed example 4); a skip link that is not the first focusable element (cf77f2 passed example 12 —
  it still passes the rule, it only stops passing G1); a `button` (cf77f2 passed example 8) or a
  `div role="link" tabindex="0"` (ye5d6e passed example 5) or an icon named by `aria-label` (passed
  example 6) as the instrument; a target that is an empty `span` at the end of the header or after
  an `<hr>` inside the content (passed examples 7, 8); a heading preceded by a breadcrumb, an
  `<hr>`, a decorative image or a numbering `span` (047fe0 passed examples 4, 5, 8); a
  `div role="heading" aria-level="1"` (passed example 6); a heading whose text is an `alt` (passed
  example 7); several `main` elements where one is in the tree (b40fd1 passed example 3); a landmark
  that is not visually rendered (b40fd1 assumption); a footer or any repeated block after all
  content (End key; cf77f2 assumption); a block repeated only within this page; repetition shared
  with pages outside the set; a `nav` without an accessible name (that is 1.3.1 at most);
  `mainCount` above 1 on its own.

## Reporting

- File under: 2.4.1 for a missing, broken, unreachable or misplaced bypass mechanism and for an
  interleaved block that cannot be skipped. The site-wide header or navigation is one issue naming
  every sample it was seen on; a page-specific block (a filter panel, an in-content promo) gets its
  own. A skip link named "Skip" or "Link" with no destination in the name is 2.4.4; one with no
  visible focus style is 2.4.7; a mouse-only skip control is filed here, naming 2.1.1 as the cause,
  when it is the only mechanism, and under 2.1.1 otherwise; missing landmarks or headings as page
  structure are 1.3.1 unless they were the sole mechanism; a fake heading is 1.3.1 as well as here;
  a mechanism present on some samples and absent on others is this criterion for the samples that
  lack it, and 3.2.3 / 3.2.4 when it merely moves or changes name.
- Title patterns: "No way to skip the navigation to the main content", "The skip link points to a
  target that does not exist", "The skip link is not reachable with the keyboard", "The skip link
  lands inside the navigation instead of the content", "The main content has no heading or landmark
  to jump to", "Hiding the menu leaves it readable for screen readers", "The filter panel cannot be
  skipped"
- Severity: High when no mechanism exists at all and the block holds the site navigation or the
  header that every page carries, so every keyboard and screen-reader user pays for it on every page
  — the Understanding's own example sizes this cost: "a keyboard user needs to tab through
  approximately 40 links to reach the main story; the screen reader user has to listen to 200
  words". Medium when the block is smaller, when only landmarks or headings work while the skip link
  is broken (AT users get past it, sighted keyboard users do not), or when an interleaved block on a
  key task page cannot be skipped. Low when a working mechanism sits a few stops later than it
  should.
- Type: Technical (a link and its target id, `main` and `nav` markup, a heading element, a toggle
  script). Design when the mechanism works but is never shown while focused (file with 2.4.7).
  Content when the only defect is the wording of the skip link (file under 2.4.4 instead).
- Evidence: the full-page screenshot with `highlight` on the first Tab stop, or on the skip link
  when there is one, and K named in the body; the recording of Tab, Tab, Enter, Tab for a broken or
  misplaced skip link, since the defect is where focus goes; the first entries of `order` as the
  list of what a keyboard user meets first; for a collapse defect, two element screenshots of the
  block, before and after the control, beside the `snapshot -s` answer.
- Recommendation: [G1](https://www.w3.org/WAI/WCAG22/Techniques/general/G1): put the skip link first
  in `body` and target the content wrapper —

  ```html
  <body>
    <a class="skip-link" href="#main">Skip to main content</a>
    <header>…</header>
    <main id="main" tabindex="-1">…</main>
  </body>
  ```

  with the link off-screen until focused (`.skip-link { position: absolute; left: -9999px }` and
  `.skip-link:focus { left: 0 }`), which keeps 2.4.7 satisfied.
  [ARIA11](https://www.w3.org/WAI/WCAG22/Techniques/aria/ARIA11) and
  [H97](https://www.w3.org/WAI/WCAG22/Techniques/html/H97): wrap the content in `main` so its first
  perceivable content is the page's own, and each menu in a named `nav` (`<nav aria-label="Main">`).
  [H69](https://www.w3.org/WAI/WCAG22/Techniques/html/H69): start the content with its `h1`, as a
  real heading element, visible and not `aria-hidden`.
  [G123](https://www.w3.org/WAI/WCAG22/Techniques/general/G123) for a block inside the content:
  `<a href="#results">Skip the filters</a>` directly above the filter list, with
  `<div id="results">` wrapping the results. Use
  [G124](https://www.w3.org/WAI/WCAG22/Techniques/general/G124) when the page has several areas
  worth their own link.
  [SCR28](https://www.w3.org/WAI/WCAG22/Techniques/client-side-script/SCR28) for a collapsible
  block, with the toggle placed **before** the block and the block hidden from screen and tree
  together —

  ```html
  <button aria-expanded="true" aria-controls="menu" onclick="toggleMenu()">Menu</button>
  <nav id="menu">…</nav>
  ```

  where `toggleMenu()` sets `hidden` (or `display: none`) on `#menu`, not `aria-hidden` and not an
  off-screen class. [H64](https://www.w3.org/WAI/WCAG22/Techniques/html/H64): a `title` on every
  repeated `iframe` so it can be identified and passed over.
  [PDF9](https://www.w3.org/WAI/WCAG22/Techniques/pdf/PDF9) when the sample is a PDF: tag its
  section openings as headings. [C6](https://www.w3.org/WAI/WCAG22/Techniques/css/C6) as an advisory
  addition: keep the primary content early in the source and place the navigation visually with CSS,
  which shrinks K for everyone; on its own it does not satisfy the criterion, so pair it with one of
  the sufficient techniques above.

- Related: 2.4.3 (a skip link far down the focus order, or focus that does not follow the link);
  2.4.7 (the focused skip link cannot be seen); 2.4.4 (the skip link does not say where it goes);
  1.3.1 (landmarks and headings as page structure, and text styled to look like a heading); 2.4.6 (a
  heading that does not describe its section); 2.1.1 (a mouse-only skip or collapse control); 4.1.2
  (a skip control the accessibility tree does not carry); 3.2.3 / 3.2.4 (the mechanism differs
  between samples).
