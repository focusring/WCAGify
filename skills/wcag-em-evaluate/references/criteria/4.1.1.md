# 4.1.1 Parsing (Obsolete and removed)

Level A · WCAG 2.0 and 2.1 only, removed in 2.2 · Guideline 4.1 Compatible · Group: `structure`

Sources: [Understanding](https://www.w3.org/WAI/WCAG22/Understanding/parsing.html) ·
[Spec](https://www.w3.org/TR/WCAG22/#parsing) ·
[Techniques](https://www.w3.org/WAI/WCAG22/quickref/#parsing) (WCAG 2.2 lists none) ·
[Plain English](https://aaardvarkaccessibility.com/wcag-plain-english/4-1-1-parsing/) ·
ACT: [3ea0c8](https://www.w3.org/WAI/standards-guidelines/act/rules/3ea0c8/) (deprecated, via axe),
[e6952f](https://www.w3.org/WAI/standards-guidelines/act/rules/e6952f/) (deprecated, source only)

## Requirement

> Note:
> This criterion was originally adopted to address problems that assistive technology had directly
> parsing HTML. Assistive technology no longer has any need to directly parse HTML. Consequently,
> these problems either no longer exist or are addressed by other criteria. This criterion no
> longer has utility and is removed.

Terms (WCAG 2.2 glossary): none. The criterion text links no glossary term, so no defined term
decides this outcome; the wording that decides it is the notes below, quoted in full.

On a 2.0 or 2.1 target the criterion reads: "In content implemented using markup languages,
elements have complete start and end tags, elements are nested according to their specifications,
elements do not contain duplicate attributes, and any IDs are unique, except where the
specifications allow these features." Four defects, then one exception clause that swallows most of
them. Its own note fixes what "complete" means: "Start and end tags that are missing a critical
character in their formation, such as a closing angle bracket or a mismatched attribute value
quotation mark are not complete." An omitted optional end tag is therefore complete markup.

WCAG 2.1 adds two notes and both decide the outcome. Note 1, in full: "This success criterion
should be considered as always satisfied for any content using HTML or XML." Note 2, in full:

> Since this criterion was written, the HTML Living Standard has adopted specific requirements
> governing how user agents must handle incomplete tags, incorrect element nesting, duplicate
> attributes, and non-unique IDs. [HTML] Although the HTML standard treats some of these cases as
> non-conforming for authors, it is considered to "allow these features" for the purposes of this
> success criterion because the specification requires that user agents support handling these
> cases consistently. In practice, this criterion no longer provides any benefit to people with
> disabilities in itself. Issues such as missing roles due to inappropriately nested elements or
> incorrect states or names due to a duplicate ID are covered by different success criteria and
> should be reported under those criteria rather than as issues with 4.1.1.

The middle clause is the one that does the work: markup the HTML checker calls non-conforming is
still "allowed" for 4.1.1, so a validator error list is never on its own a 4.1.1 finding. The last
sentence is the routing rule steps 3 to 5 implement, and it names the two effects to look for: a
missing role from inappropriately nested elements, a wrong state or name from a duplicate ID.

WCAG 2.0 carries neither note. Both ACT rules read 2.0 the same way, in the same words: "This rule
has been deprecated because success criterion 4.1.1 has been removed in WCAG 2.2 and for WCAG 2.1
and 2.0 should be considered to always pass."

The Understanding's Intent states the same split and is the second half of the routing rule: "Many
issues that would have failed this criterion will fail Info and Relationships or Name, Role, Value.
Other issues are excepted by the 'except where the specification allow these features' part of the
criterion." One further Understanding note keeps validity out of scope entirely: "Because the term
'well formed' is only defined in XML, and (because end tags are sometimes optional) valid HTML does
not require well formed code, the term is not used in this success criterion."

## In plain terms

The In Brief framing is the historical one: the goal was that "Assistive technology can properly
present page content", the instruction "Create web pages according to specifications", the benefit
that "People can browse web content more easily with their assistive technology". Concretely the
author had to close every tag, nest elements the way their specification says, write each attribute
once and keep every id unique, because assistive technology used to parse the markup itself and
"repair techniques vary among user agents". Assistive technologies now read the browser's DOM and
the HTML Living Standard defines how every browser must repair each of these errors, so W3C removed
the criterion in 2.2 and declares it always satisfied in 2.1. Parsing defects are still worth
finding, but they are judged by their effect and reported under the criterion that effect breaks.

## Applies when

- Present: `evaluation.targetWcagVersion` is `2.0` or `2.1` and the sample is delivered as markup,
  which every browser sample is (`document.contentType` is `text/html`, `application/xhtml+xml`,
  `image/svg+xml` or another XML type; step 1 reads it). One outcome per sample, shared by all its
  states, because the criterion is about the document, not about a widget's behaviour.
- Present for 3ea0c8 (duplicate ids), its applicability verbatim: "any id attribute whose value is
  not an empty string (""), specified on a HTML or SVG element", with the note "Elements that are
  neither included in the accessibility tree nor visible are still considered for this rule". An
  `id` on an element in another namespace, for example MathML, is outside the rule.
- Present for e6952f (duplicate attributes), its applicability verbatim: "any starting tag in an
  HTML or SVG document". Its note is why step 4 reads the source and not the DOM: "This rule cannot
  be tested on the DOM Tree because the browser removes duplicates of any attribute that is already
  present on an element."
- Not present: on a 2.0 or 2.1 target, a sample the browser does not parse as markup (a PDF in
  Chrome's viewer, a plain-text or JSON response). On a 2.2 target the criterion is outside the
  target: `plan-audit.mjs` plans no unit for it and the findings file has no line for it.
- Inapplicable for the rules but still `pass` for the criterion: a document with no `id` attribute
  at all (3ea0c8 Inapplicable Example 1), a response that is XML but neither HTML nor SVG, such as
  an RDF or Atom feed (e6952f Inapplicable Example 1), and a JavaScript response (e6952f
  Inapplicable Example 2). Record `not-present` only when nothing is markup at all; an inapplicable
  ACT outcome maps to "success criterion needs further testing", never to a criterion-level pass.
- Exceptions: "except where the specifications allow these features". Under Note 2 all four named
  cases — incomplete tags, incorrect element nesting, duplicate attributes, non-unique IDs — are
  allowed, because "the specification requires that user agents support handling these cases
  consistently" even though "the HTML standard treats some of these cases as non-conforming for
  authors". Recognise the exception by asking only whether HTML defines the repair, not whether the
  markup validates. Well-formedness is not the bar either: optional end tags, void elements written
  without a slash and unquoted attribute values are all allowed.

## axe-core

| Rule                  | Decides                                            | Result → outcome   |
| --------------------- | -------------------------------------------------- | ------------------ |
| `duplicate-id-active` | one `id` on two elements, one focusable (3ea0c8)   | violation → step 3 |
| `duplicate-id`        | two non-focusable elements share one `id` (3ea0c8) | violation → step 3 |

Impacts Serious and Minor. Both are Deprecated Rules (tags `cat.parsing`, `wcag2a-obsolete`,
`wcag411`, `deprecated`; `enabled: false`), so they are off by default, absent from the
`scripts/axe-page.mjs` run and absent from the sample's axe JSON: that script builds its tags from
the target level and version (`wcag2a`, `wcag2aa`, `wcag21a`, …) and `wcag2a-obsolete` is never
among them. axe's default `tagExclude` is `['experimental', 'deprecated']`, and a tag named in
`--tags` is dropped from that exclusion list, so `--tags deprecated` runs both rules while
`--tags wcag411` still yields nothing even though both carry `wcag411`. Step 2 therefore asks for
`deprecated` by name.

A violation is never a 4.1.1 fail on its own: it rates the defect at 100, Note 1 makes the
criterion outcome `pass`, and Note 2 routes the effect to another criterion. A clean run settles
nothing either — 3ea0c8's outcome mapping records "All passed outcomes: success criterion needs
further testing" and "An inapplicable outcome: success criterion needs further testing" — so steps
3 to 5 run whatever axe returned.

Settles: repeated `id` values on elements that no ARIA IDREF attribute and no `label[for]`
references, hidden elements included (`excludeHidden: false`), compared within one document tree or
shadow tree per frame, empty and whitespace-only `id` values skipped.

Leaves open, and this list is what steps 3 to 5 do:

- A repeated `id` that _is_ the target of an accessible reference. Both rules require
  `!isAccessibleRef(node)`, where an accessible reference is any of the eight ARIA IDREF
  attributes — `aria-activedescendant`, `aria-controls`, `aria-describedby`, `aria-details`,
  `aria-errormessage`, `aria-flowto`, `aria-labelledby`, `aria-owns` — or a `label` with `for`.
  These are precisely the duplicates that change a name or a state, and axe files them under 4.1.2
  instead, so step 3 holds the complete list.
- A repeated `id` referenced by `headers`, `href="#id"`, `usemap`, `list`, `form` or
  `popovertarget`: axe reports the duplicate but says nothing about where the reference lands.
- Duplicate attributes: no axe rule exists and none can, because the browser drops the repeat
  before axe sees the DOM (e6952f's own note). Source only, step 4.
- Incomplete start tags and misnesting: repaired by the parser before axe runs. Source and DOM,
  steps 3 and 4.
- What each defect does to a name, role, state, relationship or in-page link — the question Note 2
  asks, answered in step 5.
- Whether the report is asked for the historical reading of the criterion at all.

## Manual procedure

Structure mode, once per sample as loaded, then once per recorded state that inserts or replaces
markup by script. 1.3.1, 4.1.2, 3.3.1, 3.3.2, 2.4.1, 1.1.1 and 3.1.2 take the findings. `snapshot`
shows the repaired DOM only, so steps 3 and 5 read the DOM and step 4 reads the source; between
them nothing here is `cannot-tell`.

1. Fix the outcome from the target version and the content type:

   ```bash
   agent-browser get url
   agent-browser eval --stdin <<'EOF'
   (() => ({ type: document.contentType, root: document.documentElement.localName,
     parserError: !!document.querySelector('parsererror'),
     idCount: document.querySelectorAll('[id]').length }))()
   EOF
   ```

   Target `2.2`: stop, record nothing for 4.1.1, and give any parsing defect met in this pass to
   the criterion it breaks (Reporting). Target `2.0` or `2.1`: a `type` of `text/html`,
   `application/xhtml+xml`, `image/svg+xml` or another XML type is "content using HTML or XML", so
   write `pass` with the evidence line "always satisfied (WCAG 2.1 Note 1; 3ea0c8 and e6952f read
   2.0 as always passing)", and run steps 2 to 5 for the sibling criteria. `parserError: true` (an
   XML document the browser refused to parse) goes to Needs confirmation. A PDF or plain-text
   sample is `not-present`. `idCount: 0` means 3ea0c8 is inapplicable and step 3 only checks
   nesting. Done when the outcome line for this sample is written and steps 2 to 5 are either
   queued or explicitly skipped.

2. Run the two deprecated axe rules on the loaded state:

   ```bash
   agent-browser a11y --tags deprecated --json
   ```

   Read the `data.violations` entries whose `id` is `duplicate-id` or `duplicate-id-active`; each
   `nodes[]` entry gives `target`, `html` and a `failureSummary` naming the repeated value. The
   result is an ACT 3ea0c8 outcome per `id` attribute: failed where the value repeats within the
   element's own document or shadow tree, passed otherwise. Re-run the command in every recorded
   state that inserts content by script, because a component rendered twice is the usual cause;
   hidden content needs no separate state, as the rules keep hidden elements. Done when every
   repeated `id` value is listed with its selectors and its state, or the list is written as "none".

3. Read the DOM for the duplicates axe skips, for where each reference actually lands, and for the
   nesting the parser left in place. 3ea0c8's expectation is the test this step applies by hand:
   "The value of the attribute is unique across all other id attributes specified on HTML or SVG
   elements that exist within the same document tree or shadow tree as the element on which the
   applicable id attribute is specified."

   ```bash
   agent-browser eval --stdin <<'EOF'
   (() => {
     const ariaRefs = ['aria-activedescendant', 'aria-controls', 'aria-describedby',
       'aria-details', 'aria-errormessage', 'aria-flowto', 'aria-labelledby', 'aria-owns'];
     const htmlRefs = ['for', 'headers', 'list', 'form', 'popovertarget'];
     const hashRefs = ['href', 'usemap'];
     const path = el => { const p = [];
       for (let e = el; e && e.nodeType === 1 && e !== document.documentElement;
         e = e.parentElement ?? e.getRootNode().host) {
         let i = 1, s = e; while ((s = s.previousElementSibling))
           if (s.tagName === e.tagName) i++;
         p.unshift(`${e.localName}:nth-of-type(${i})`) }
       return p.join(' > ') || 'html' };
     const nsOf = el => el.namespaceURI === 'http://www.w3.org/2000/svg' ? 'svg'
       : el.namespaceURI === 'http://www.w3.org/1999/xhtml' ? 'html' : 'other';
     const roots = []; const walk = r => { roots.push(r);
       for (const el of r.querySelectorAll('*')) if (el.shadowRoot) walk(el.shadowRoot) };
     walk(document);
     const refSel = [...ariaRefs, ...htmlRefs].map(a => `[${a}]`).join(', ') +
       ', [href^="#"], [usemap]';
     const duplicates = [];
     for (const root of roots) {
       const byId = new Map();
       for (const el of root.querySelectorAll('[id]'))
         if (el.id.trim()) byId.set(el.id, [...(byId.get(el.id) ?? []), el]);
       const referrers = id => [...root.querySelectorAll(refSel)].flatMap(el => {
         const out = [];
         for (const a of [...ariaRefs, ...htmlRefs])
           if ((el.getAttribute(a) ?? '').split(/\s+/).includes(id))
             out.push({ path: path(el), attr: a, axeSkips: ariaRefs.includes(a) ||
               (a === 'for' && el.localName === 'label') });
         for (const a of hashRefs)
           if ((el.getAttribute(a) ?? '') === '#' + id)
             out.push({ path: path(el), attr: a, axeSkips: false });
         return out });
       for (const [id, els] of byId) {
         if (els.length < 2) continue;
         duplicates.push({ id, tree: root === document ? 'document' : path(root.host),
           resolvesTo: path(els[0]), referrers: referrers(id),
           elements: els.map(el => ({ path: path(el), tag: el.localName, ns: nsOf(el),
             hidden: !el.checkVisibility(), text: (el.textContent ?? '').trim().slice(0, 60) })) });
       }
     }
     const checks = {
       'interactive inside interactive': 'label label, a[href] button, button a[href], ' +
         'a[href] a[href], :is(a[href], button) :is(input:not([type=hidden]), select, textarea, ' +
         '[tabindex]:not([tabindex="-1"]))',
       'child the content model forbids': ':is(ul, ol) > :not(li, script, template), ' +
         'dl > :not(dt, dd, div, script, template), tr > :not(td, th, script, template)',
       'option outside a list owner': ':not(select, optgroup, datalist) > option' };
     const nesting = Object.entries(checks).flatMap(([reason, s]) =>
       [...document.querySelectorAll(s)].map(el => ({ path: path(el), reason,
         html: el.outerHTML.slice(0, 120) })));
     return { duplicates, nesting };
   })()
   EOF
   ```

   `duplicates` holds every repeat, including the ones step 2 could not report: an entry whose
   `referrers` contains `axeSkips: true` is exactly the case axe hands to 4.1.2. `tree` separates
   the document tree from each shadow tree, so a repeat listed under one `tree` is a real 3ea0c8
   failure and the same value appearing under two different `tree` values is not. `ns: 'other'` is
   outside 3ea0c8's applicability (neither HTML nor SVG) and is noted, not routed.

   Compare the element at `resolvesTo` with the one the author meant — the browser resolves an
   IDREF to the first element in tree order, so `resolvesTo` is what assistive technology gets.
   3ea0c8 Failed Example 1 is the canonical shape and is worth recognising by sight:

   ```html
   <div id="label">Name</div>
   <div id="label">City</div>
   <input aria-labelledby="label" type="text" name="city" />
   ```

   The city field is announced "Name". Failed Example 2 is the same defect across namespaces (a
   `div` and an `svg` sharing `id="label"`) and Failed Example 3 the same defect with the first
   element `display: none`, which still wins because it still comes first in tree order.

   Route each entry by the attribute that points at it: `aria-labelledby`, `aria-activedescendant`,
   `aria-controls`, `aria-owns` → 4.1.2; `aria-errormessage` → 3.3.1; `for` on a `label`,
   `headers`, `aria-describedby`, `aria-details`, `list`, `form`, `popovertarget` → 1.3.1 (a field
   that loses its visible label is also 3.3.2); `href="#id"` → 2.4.1 when the link is the bypass
   mechanism, otherwise a plain bug: note it and file nothing; `usemap` → 1.1.1. An entry whose
   intended element is already first, or that has no `referrers` at all, is "no effect".

   `nesting`: `interactive inside interactive` → 4.1.2 for the lost or merged role, and the
   `keyboard` pass checks whether the inner control is still operable (2.1.1); `child the content
model forbids` and `option outside a list owner` → 1.3.1, the "missing roles due to
   inappropriately nested elements" Note 2 names. Done when every `duplicates` and every `nesting`
   entry carries a routed criterion or the word "no effect".

4. Read the source for duplicate attributes and unreadable tags. The parser drops a repeated
   attribute and swallows a tag that lost its `>` or a quote, so only the source shows them; e6952f
   is a source-code rule for that reason, and its expectation is the whole test: "For each test
   target, there are no duplicated attributes."

   ```bash
   agent-browser eval --stdin <<'EOF'
   (async () => {
     if (!['text/html', 'image/svg+xml'].includes(document.contentType))
       return { applicable: false, type: document.contentType };
     let src;
     try { src = await (await fetch(location.href, { credentials: 'include' })).text() }
     catch (e) { return { fetched: false, error: String(e) } }
     const body = src.replace(/<!--[\s\S]*?-->/g, '')
       .replace(/<(script|style)\b[^>]*>[\s\S]*?<\/\1\s*>/gi, '');
     const v = `"[^"]*"|'[^']*'|[^\\s"'<>\`=]+`;
     const tag = new RegExp(
       `<([a-zA-Z][\\w:-]*)((?:\\s+[^\\s"'<>/=]+(?:\\s*=\\s*(?:${v}))?)*)\\s*/?>`, 'g');
     const attr = new RegExp(`([^\\s"'<>/=]+)(?:\\s*=\\s*(${v}))?`, 'g');
     const unq = x => (x ?? '').replace(/^(["'])([\s\S]*)\1$/, '$2');
     const duplicateAttributes = [], ranges = [];
     for (let m; (m = tag.exec(body)); ) {
       ranges.push([m.index, m.index + m[0].length]);
       const seen = {};
       for (let a; (a = attr.exec(m[2])); ) (seen[a[1].toLowerCase()] ??= []).push(unq(a[2]));
       for (const [name, values] of Object.entries(seen)) if (values.length > 1)
         duplicateAttributes.push({ tag: m[1].toLowerCase(), attr: name, kept: values[0],
           dropped: values.slice(1), snippet: m[0].slice(0, 160) });
     }
     const unreadTags = [...body.matchAll(/<[a-zA-Z][\w:-]*/g)]
       .filter(m => !ranges.some(([s, e]) => m.index >= s && m.index < e))
       .map(m => ({ tag: m[0].slice(1).toLowerCase(),
         snippet: body.slice(m.index, m.index + 120) }));
     return { applicable: true, fetched: true, duplicateAttributes, unreadTags };
   })()
   EOF
   ```

   `applicable: false` records an e6952f inapplicable outcome for a document that is neither HTML
   nor SVG (Inapplicable Example 1, an RDF document) and closes the step. `fetched: false` records
   "source not fetched" — a page reached by POST or behind a one-time token returns different
   markup on a second GET, so treat a mismatch between `unreadTags` and the DOM as unproven. A
   `file://` sample always lands here, because the browser blocks `fetch` on that scheme: take the
   delivered markup from the project directory the sample was served from and apply the same
   reading by hand.

   `duplicateAttributes`: `kept` is the value the browser uses (HTML keeps the first occurrence),
   `dropped` is what the author also wrote. Route a dropped value that carries meaning the kept one
   lacks to the attribute's own criterion: `alt` → 1.1.1; `aria-label`, `aria-labelledby`, `title`,
   `role` and the `aria-*` state attributes → 4.1.2; `lang` → 3.1.2; `for` and `id` → 1.3.1. The
   same value twice, and repeats of `class`, `style` or `data-*`, are "no effect". e6952f's failed
   examples show the three shapes to expect: a duplicated `alt` on an `img`
   (`alt="" alt="W3C logo"`, where the accessible name is lost to the empty first value), a
   duplicated boolean attribute (`disabled="disabled" disabled readonly`, which the probe reports
   as `kept: "disabled"`, `dropped: [""]` and which is still a failure), and duplicated geometry
   attributes on an inline SVG (`<line x1="0" y1="0" x1="200" y1="200">`). Duplicates written
   inside a `script` body are not failures (Passed Example 5) and the probe already strips `script`
   and `style` content for that reason.

   `unreadTags`: a `<` in running text is noise. A start tag that lost its `>` or carries a
   mismatched quote swallows the markup that follows it, so confirm each candidate against the DOM
   before recording it:

   ```bash
   agent-browser get count "<tag from unreadTags>"
   agent-browser get html "body"
   ```

   A `tag` present in the source list and absent from `get count` is an incomplete start tag and
   whatever it swallowed is missing from the page; route that missing content by what it was (a
   heading or list → 1.3.1, a control → 4.1.2, an image → 1.1.1). Done when every
   `duplicateAttributes` entry and every `unreadTags` candidate is routed or dismissed.

5. Confirm the effect before routing anything, because Note 2 files the effect, not the markup.
   For each referrer from step 3 and each dropped attribute from step 4:

   ```bash
   agent-browser snapshot -i -s "<referrer selector>"
   agent-browser get attr "<referrer selector>" aria-labelledby
   agent-browser eval --stdin < <skill-dir>/scripts/probes/forms.js
   ```

   The scoped snapshot prints the computed name, role and state the browser actually exposes: a
   name that matches the text of `resolvesTo` rather than the intended element confirms the wrong
   label. `get attr` reads back the IDREF the referrer actually carries, which distinguishes a
   duplicate id from a plain typo in the reference, and `forms.js` gives the same field's `name`
   and `nameSource` (`nameSource: 'none'` or a `name` that belongs to another field is the
   confirmation). The accessibility tree shows names,
   roles, states and relationships; it does not show reading order in a screen reader, table header
   association as announced, or what a braille display renders, so where the effect depends on
   those, record the observation under the routed criterion and let that criterion's own procedure
   decide. Done when every routed entry carries either a confirmed effect (the name, role, state or
   target that is wrong) or the note "markup defect, no exposed effect".

## Deciding

- Fail (certainty ≥ 90): none under the WCAG 2.1 text (Note 1: "always satisfied for any content
  using HTML or XML") or under either ACT rule's reading of 2.0 ("should be considered to always
  pass"); the defects found in steps 2 to 5 fail their own criteria instead. Only after the human
  confirms the historical reading (see Needs confirmation) do these become 4.1.1 fails:
  - a non-empty `id` on two or more HTML or SVG elements of one document tree or shadow tree —
    axe `duplicate-id` or `duplicate-id-active` violation: 100; step 3 alone, because an accessible
    reference made axe skip it: 95;
  - the same attribute name twice on one start tag in the source, e6952f failed (step 4): 95;
  - a start tag without its `>` or with a mismatched attribute value quotation mark, confirmed by a
    source snippet in `unreadTags` and a missing element in `get count` (step 4): 90.
- Fail (70–89), historical reading only: nesting the HTML content model forbids that the parser
  left in place (step 3) — a `label` inside a `label`, a `button` inside an `a`, an `a` inside an
  `a`, a form control inside a `button`, a `div` child of `ul` or `ol`, a `p` child of `dl`, an
  `option` outside a `select`, `optgroup` or `datalist`: 85. A repeated `id` inside one shadow tree
  (step 3, with `tree` naming the host), which 3ea0c8 counts as a failure but which the author may
  not control when the shadow root belongs to a third-party component: 80.
- Needs confirmation (50–69):
  - The commissioner requires the criterion as written — the brief, a legal framework or `index.md`
    says so: 55. Ask whether the audit follows WCAG 2.1 Note 1 or the original 2.0 text. Until the
    answer arrives the outcome stays `pass` and every finding above stays a note.
  - An XML sample with `parserError: true` from step 1: 60. Ask whether that is a 4.1.1 failure
    under the historical reading or a sample that cannot be evaluated at all (`cannot-tell`).
  - `fetched: false` in step 4 on a sample whose markup is known to be generated per request: 50.
    Ask for a saved copy of the delivered source, or record duplicate attributes as untested.
- Pass: the target is 2.0 or 2.1, the sample is HTML or XML content, and the human has not asked
  for the historical reading. Steps 2 to 5 ran on the loaded state and on every recorded state, and
  each of their findings sits under the criterion whose effect it breaks. A pass here says nothing
  about those criteria: an ACT passed or inapplicable outcome maps to "success criterion needs
  further testing", so the sibling criteria still decide on their own evidence.
- Not present: a 2.0 or 2.1 target with a sample that is not markup (a PDF, a plain-text or JSON
  response). On a 2.2 target the criterion is not evaluated at all.
- False positives to avoid:
  - The same `id` in the page and in an `iframe`, or in the page and a shadow root: different
    document trees, both pass (3ea0c8 Passed Examples 3 and 4). The step 3 probe keeps them apart
    with `tree`.
  - `xml:id` and `id=""` or a whitespace-only `id`: outside 3ea0c8 (Inapplicable Examples 2 and 3),
    and axe's own check lets empty ids pass.
  - An `id` on an element that is neither HTML nor SVG (`ns: 'other'`, for example MathML):
    outside the rule's applicability.
  - `script` and `template` children of `ul`, `ol`, `dl` and `tr`, and any `select` child, which
    customizable select now allows.
  - Different attributes that merely look alike on one tag: `<input type="checkbox" disabled
readonly>` has three distinct attributes and passes e6952f (Passed Example 3). Only the same
    name twice fails.
  - Duplicate attributes inside a `script` body or in a JavaScript file (e6952f Passed Example 5,
    Inapplicable Example 2), and duplicate attributes in an XML document that is not HTML or SVG
    (Inapplicable Example 1).
  - Optional end tags, void elements written without a slash, `<div/>`, unquoted attribute values,
    boolean attributes written without a value, custom elements, `data-*` and framework
    attributes, a repeated word inside one `class` value: well-formedness and validity were never
    the requirement. A boolean attribute written twice on the same tag is a different matter and is
    still an e6952f failure (Failed Example 2).
  - A W3C HTML checker error list treated as a finding: Note 2 allows the non-conforming cases it
    names, so a checker error only matters once step 5 confirms an exposed effect.

## Reporting

- File under: never 4.1.1 on a 2.2 report (WCAGify drops the criterion from a 2.2 score and
  `check-audit.mjs` turns such an issue into a tip). On a 2.0 or 2.1 report the effect goes to the
  criterion it breaks, as Note 2 directs and as steps 3 to 5 routed it: 4.1.2, 1.3.1, 3.3.1, 3.3.2,
  2.4.1, 1.1.1 or 3.1.2. Under the historical reading, after the human confirms it: 4.1.1, one
  issue per defect kind (ids, attributes, tags, nesting), naming every sample it appears on.
- Title patterns: "Element ids are repeated within the page", "Attributes are repeated on one
  element", "Start tags are incomplete", "Elements are nested against the HTML specification",
  "A label points at the wrong element"
- Severity: Low when the browser's repair leaves no trace in the accessibility tree — an
  unreferenced repeated id, a repeated `class`, a dropped `data-*`. Medium when a reference or a
  dropped attribute changes a name, label, state or relationship, or when a shared component
  repeats the defect on every page of the sample (the routed effect issue then carries its own
  severity under its own criterion). High when the swallowed content of an incomplete tag removes a
  control or a whole region from the page for everyone. Not High for a markup defect alone.
- Type: Technical in almost every case — the fix is in a template, a component or the build output.
  Content when an editor pasted the markup into a rich-text field and the CMS stores it as written,
  which is the usual source of duplicate ids in article bodies.
- Evidence: the offending markup quoted in the issue body — `nodes[].html` from step 2, `html` from
  step 3, `snippet` from step 4 — together with the scoped accessibility-tree line from step 5 that
  shows the wrong name or role. Add a page screenshot with `highlight "<css>"` on the affected
  control whenever the defect has a visible or announced effect. No GIF: nothing here is motion,
  focus movement or a sequence.
- Recommendation: give each element one `id` that is unique per document, generated from the
  component instance rather than hard-coded in the template — `useId()` in Vue or React, or the
  record key in a loop. Write each attribute once, close every start tag with `>` and every value
  with its matching quote, and nest elements as the HTML content model allows. Add the W3C HTML
  checker to CI with duplicate ids, duplicate attributes and unclosed tags as blockers. A minimal
  fix for the duplicate-id case:

  ```html
  <!-- before: both labels have id="label", so the field is announced "Name" -->
  <div id="label">Name</div>
  <div id="label">City</div>
  <input aria-labelledby="label" type="text" name="city" />

  <!-- after -->
  <div id="label-name">Name</div>
  <div id="label-city">City</div>
  <input aria-labelledby="label-city" type="text" name="city" />
  ```

  And for the duplicate-attribute case, where the first value wins and the second is dropped:

  ```html
  <!-- before: alt="" is kept, alt="W3C logo" is dropped, the image has no name -->
  <img src="/logo.png" alt="" alt="W3C logo" />

  <!-- after -->
  <img src="/logo.png" alt="W3C logo" />
  ```

- Related: 1.3.1 (structure the parser rearranged, `for`/`headers`/`list`/`form` references landing
  on the wrong element), 4.1.2 (names and states from repeated ids, controls nested inside
  controls), 3.3.1 (a broken `aria-errormessage`), 3.3.2 (a field that lost its visible label),
  2.4.1 (a skip link whose `#id` lands on the wrong element), 1.1.1 (a dropped `alt` or a broken
  `usemap`) and 3.1.2 (a dropped `lang`). Split them by the exposed effect, not by the markup: the
  effect is filed once, under the criterion it breaks, and 4.1.1 carries an issue only under the
  historical reading.
