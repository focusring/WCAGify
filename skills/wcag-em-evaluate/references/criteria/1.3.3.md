# 1.3.3 Sensory Characteristics

Level A · WCAG 2.0+ · Guideline 1.3 Adaptable · Group: `structure`

Sources: [Understanding](https://www.w3.org/WAI/WCAG22/Understanding/sensory-characteristics.html)
· [Spec](https://www.w3.org/TR/WCAG22/#sensory-characteristics) ·
[Techniques](https://www.w3.org/WAI/WCAG22/quickref/#sensory-characteristics) ·
[Plain English](https://aaardvarkaccessibility.com/wcag-plain-english/1-3-3-sensory-characteristics/)
· ACT: [9bd38c](https://www.w3.org/WAI/standards-guidelines/act/rules/9bd38c/)

## Requirement

> Instructions provided for understanding and operating content do not rely solely on
> sensory characteristics of components such as shape, color, size, visual location, orientation,
> or sound.
>
> Note:
> For requirements related to color, refer to Guideline 1.4.

Terms (WCAG 2.2 glossary): none linked from the criterion text. ACT 9bd38c defines the sensory cue
as "visual reference words": its lists for location, shape, size, orientation and colour, in "the
programmatically determinable language of the text node"; "this list is not exhaustive".

## In plain terms

An instruction that tells the user how to find, understand or operate something ("press the green
button", "see the sidebar on the left", "wait for the beep") must also identify that thing in a way
that needs neither sight nor hearing: its visible label, accessible name, heading or place in the
reading order. The sensory cue may stay; it must not be the only identification. It matters for
people who are blind or have low vision and for people who are deaf or hard of hearing (sound).

## Applies when

- Present: a text node that is visible or included in the accessibility tree (ACT 9bd38c
  applicability) identifies content by a visual reference word (the ACT 9bd38c lists: visual
  location, shape, size, orientation, any single-word X11 colour name) or by a sound; or an
  instruction or legend refers to a glyph, icon or symbol image whose meaning is stated nowhere in
  text ([F26](https://www.w3.org/WAI/WCAG22/Techniques/failures/F26)). Detect with the scan in
  step 2 and `images.js` in step 4.
- Not present: after step 2 no text node identifies content by a sensory word, no instruction or
  legend refers to a symbol and no instruction relies on a sound. Record `not-present`.
- Exceptions: none in the normative text; three W3C readings narrow it. (1) "if the content being
  referenced is in the appropriate place in the reading order and the references are unambiguous,
  statements such as 'choose one of the links below' or 'all of the above' would conform". (2) A
  sensory cue beside a textual identification conforms: "select the green arrow icon labeled
  'Next' in the lower right corner" passes because it "also refers to the label". (3) Tactile cues
  for physical hardware controls (a kiosk's "round key on the right side") are out of scope.
  Colour used in the content itself, without an instruction, is 1.4.1 (the Note).

## axe-core

No axe-core rule is tagged with this criterion; everything below is manual (`a11y` stays silent).

## Manual procedure

Structure mode: read the sample as loaded. Repeat steps 2 to 5 for every state in
`recon/<sample>-states.md` (a dialog open on load, an expanded help panel, the error state); run
`snapshot` again after each.

1. Establish the language. Run `structure.js`; read `lang` and `langParts`. Visual reference words
   are the ACT 9bd38c lists in the language of each text node; the scan in step 2 carries the
   complete English list and a Dutch one and picks the list from the nearest `lang` (both lists
   when it is neither). For any other language on the page (`lang` of the root or of a `langParts`
   entry), translate the English list into it and add it to `lists` under its two-letter code
   before running the scan. Done when the root `lang` and every `langParts` entry has a list in
   `lists`.

2. Find candidate text nodes (ACT 9bd38c applicability: text nodes visible or in the tree) and
   lone symbol glyphs.

   ```bash
   agent-browser eval --stdin <<'EOF'
   (() => {
     const lists = {
       en: `above below beneath beside bottom diagonal down left near(by)? parallel right top
         under(neath)? up box circ(le|ular) crescent cross diamond disc ellipse heart hexagon(al)?
         kite oval parallelogram pentagon(al)? polygon(al)? rectang(le|ular) round squared? star
         trapezoid(al)? triang(le|ular) wave big large little narrow small tiny wide angled askew
         atilt crooked listing lopsided off-kilter pitched rotated sideways skewed slant(ed|ing)
         straight tilt(ed)? tipped almond aqua(marine)? azure beige bisque black blue brown
         burlywood chartreuse chiffon chocolate coral cornsilk cream crimson cyan firebrick fuchsia
         gold(enrod)? gr[ae]y green honeydew indigo ivory khaki lace lavender lemon lime linen
         magenta maroon mint moccasin olive orange orchid pink purple red rose salmon turquoise
         violet white yellow sound beep chime hear`,
       nl: `boven(aan)? onder(aan)? beneden links rechts naast diagonaal parallel ronde? cirkel
         vierkante? driehoek(ig|ige)? ster kruis ruit ovaal zeshoek vijfhoek hart golf gro(ot|te)
         kleine? bre(ed|de) smal(le)? schuine? scheve? gekantelde? gedraaide? rechte? zwarte?
         blauwe? bruine? grij(s|ze) groene? oranje roze paarse? ro(od|de) wit(te)? ge(el|le)
         goud(en)? zilveren? turkooi(s|ze) beige lila indigo cyaan magenta limoen mint ivoor
         lavendel koraal zalm olijf geluid piep toon`,
     }
     const list = (lang) => (lists[lang] || `${lists.en} ${lists.nl}`).trim().split(/\s+/)
     const regex = (lang) => new RegExp(`\\b(${list(lang).join('|')})\\b`, 'gi')
     const langOf = (el) => (el.closest('[lang]')?.lang || '').slice(0, 2).toLowerCase()
     const glyph = /^[\p{So}\p{Sm}*†‡]{1,2}$/u
     const blockSel =
       'p,li,dt,dd,td,th,h1,h2,h3,h4,h5,h6,figcaption,label,legend,caption,summary,blockquote'
     const sel = (el) => {
       if (el === document.body) return 'body'
       if (el.id) return `#${CSS.escape(el.id)}`
       const p = el.parentElement, kin = [...p.children].filter((s) => s.tagName === el.tagName)
       return `${sel(p)} > ${el.localName}:nth-of-type(${kin.indexOf(el) + 1})`
     }
     const hits = [], glyphs = []
     const walker = document.createTreeWalker(document.body, NodeFilter.SHOW_TEXT)
     while (walker.nextNode()) {
       const node = walker.currentNode
       const text = node.data.replace(/\s+/g, ' ').trim()
       const el = node.parentElement
       if (!text || !el || ['script', 'style', 'noscript'].includes(el.localName)) continue
       if (!el.getClientRects().length || getComputedStyle(el).visibility === 'hidden') continue
       const block = el.closest(blockSel) || el
       const context = block.textContent.replace(/\s+/g, ' ').trim().slice(0, 240)
       const entry = { selector: sel(el), text: text.slice(0, 200), context, lang: langOf(el) }
       entry.ariaHidden = !!el.closest('[aria-hidden="true"]')
       if (glyph.test(text)) { glyphs.push(entry); continue }
       const words = text.match(regex(entry.lang)) || []
       if (!words.length) continue
       hits.push({ ...entry, words: [...new Set(words.map((w) => w.toLowerCase()))] })
     }
     return { lang: document.documentElement.lang, count: hits.length, hits, glyphs }
   })()
   EOF
   ```

   Skipped: `display: none` and `visibility: hidden` text. Kept: off-screen and visible
   `aria-hidden` text (both applicable per ACT 9bd38c). Judge each hit and each glyph on `context`
   (the enclosing block); `text` is the node the ACT rule targets. Several hits with the same
   `context` are one candidate. Drop a hit whose words identify no web content ("a square has four
   right angles"), that gives no instruction ("this circle is nice"), or whose word has a
   non-sensory meaning ("right after", "sign up", "below" for later in reading order). Done when
   every hit is dropped with a reason or listed as a candidate with its target.

3. Test each candidate against the ACT 9bd38c expectation. Locate the identified content in the
   tree; the first condition met passes the candidate. Count the elements that carry the name the
   instruction gives:

   ```bash
   agent-browser snapshot
   agent-browser snapshot -s "<css of the identified component>"
   agent-browser eval --stdin <<'EOF'
   (() => {
     const norm = (s) => (s || '').replace(/\s+/g, ' ').trim().toLowerCase()
     const want = norm('<the name the instruction gives>')
     return [...document.body.querySelectorAll('*')].filter((e) =>
       norm(e.getAttribute('aria-label') || e.textContent) === want).length
   })()
   EOF
   ```

   - Non-visual reference: the same sentence, or another instruction on the page, also names the
     content by its label, heading, landmark name or link text ("the button labelled 'Howdy', on
     the right"), and that name matches exactly one element in `snapshot` (the count is 1); two
     unnamed `nav` landmarks for "the navigation on the right" is ambiguous (ACT failed example 2).
   - Non-sensory meaning: "below" / "above" where the content follows / precedes the instruction
     in `snapshot` order and nothing else matches the description.
   - Visible words: every visual reference word of the candidate is in the visible text of the
     identified content ("Round button"); `get text`.
   - Accessible words: every visual reference word of the candidate is in its accessible name
     shown by `snapshot -s` ("Wide photo").
   - No instruction: the sentence uses the word without telling the user to do anything with it.

   Content on another page of the site still counts: open it with `read <url>` and look for the
   word or a heading there. Content in an iframe: `frame "<css>"`, `snapshot`, `frame main`. An
   alternative visible but missing from the tree passes here (ACT background: that is 1.3.1).
   Done when every candidate has one condition met or a recorded fail.

4. Symbol-only cues ([F26](https://www.w3.org/WAI/WCAG22/Techniques/failures/F26)). Run
   `images.js` and read `images`. For every entry whose `nearbyText`, `controlText` or
   `figcaption` reads as an instruction or legend ("marked with", "indicates", "click the"), check
   that the symbol's meaning is in text: its `name` says the meaning ("Next", "In stock"), not the
   shape ("arrow", "circle"), or adjacent text says it. Do the same for each `glyphs` entry of
   step 2 (★ ▲ ✓ → ● ■ *) from its `context`; a glyph that instructs nothing is dropped. Done when
   each symbol an instruction or legend uses has its meaning in text.

5. Sound cues. Run `media.js`; read `media` entries with `kind` `audio`. For step 2 hits with
   `sound`, `beep`, `chime`, `hear`, `geluid` or `piep` that instruct ("wait for the beep"), find a
   visible message, timer or status text with the same information (`liveRegions` from
   `structure.js` shows announcements). When the equivalent would appear only after an interaction
   (a status message on completion, a `liveRegions` entry that is empty as loaded), record
   `cannot-tell`, name the interaction, and hand it to the `forms` or `keyboard` pass. When no
   equivalent exists in any walked state and the page plays the sound as loaded (`media.js` entry
   with `autoplay`) or the instruction names no interaction, record a fail. Done when every sound
   cue has an equivalent, a `cannot-tell` or a fail.

6. Tree limits and evidence. `snapshot` settles the visible-words, accessible-words and
   non-visual-reference conditions because it shows names and reading order; it cannot show
   content inside `canvas`, an image, a PDF or an image of text: when the identified content or
   the instruction lives there, record `cannot-tell` with a screenshot. For each fail run
   `highlight "<css of the instruction>"`, then `screenshot <path>` with the referenced component
   in frame, and keep the `snapshot -s` excerpt. Done when every fail has both and none is open.

## Deciding

- Fail (certainty ≥ 90):
  - A candidate meets none of the five ACT 9bd38c conditions: the instruction points at a
    component only by a visual reference word, the component's visible text and accessible name
    lack that word, and no label, heading or landmark name is given — 95
    ([F14](https://www.w3.org/WAI/WCAG22/Techniques/failures/F14)).
  - The non-visual reference matches more than one element (two unnamed `nav` landmarks, three
    unnamed buttons for "the round button") — 90.
- Fail (70–89):
  - A legend or table note distinguishes categories only by colour, shape or an icon and the
    markers carry no text ("events marked with a blue diamond are on field A") — 85
    ([F26](https://www.w3.org/WAI/WCAG22/Techniques/failures/F26)).
  - The instruction points at an icon-only control ("select the arrow") whose accessible name
    repeats the shape, not the meaning — 80 (F26); the missing name itself is filed elsewhere.
  - "Above" / "below" used where the content is not in that place in the reading order (the "form
    below" precedes the instruction in `snapshot`, moved by CSS) — 75.
  - An instruction relies on a sound and no text or visual equivalent exists in any walked state
    where one could appear — 70.
- Needs confirmation (50–69):
  - The word may carry a non-sensory meaning in this language yet the sentence still reads as an
    instruction — 60; ask: "Does this sentence send the reader to a component, and which one?"
  - The identified content is on a page outside the sample or in a frame the session cannot
    enter — 60; ask the human to open it and look for the word or a heading.
  - The identified content or the instruction is inside an image, `canvas` or embedded document
    — 50; record `cannot-tell` and queue it.
- Pass: every candidate text node meets one ACT 9bd38c condition, every symbol used in an
  instruction or legend has its meaning in text, every sound cue has a text or visual equivalent.
- Not present: the scan yields no candidate after filtering and no symbol-only or sound-only cue
  is used in an instruction.
- False positives to avoid: words that identify nothing or give no instruction; a sensory cue next
  to a name ("the green Next button"); "below" / "above" in reading order; the word in the
  component's own text ("Round button"); an alternative visible but not in the tree (1.3.1, per
  ACT 9bd38c); colour-only status in content (1.4.1); "links" on an English page (Dutch list).

## Reporting

- File under: 1.3.3 for the wording of the instruction. When the pointed-at component also lacks
  a name, file that separately under 4.1.2 (a control) or 1.1.1 (an image). A marker in content
  that uses colour alone with no instruction is 1.4.1. One issue per instruction or legend;
  repeated site-wide help text is one issue naming the other samples.
- Title patterns: "Instruction identifies the menu only by position", "Instruction refers to the
  button by colour only", "Legend marks venues by shape alone", "Next step shown by an arrow only"
- Severity: High when the instruction is needed to complete a task and the referenced component
  offers no other route; Medium when the component has a label the instruction fails to name, so
  it can be found with effort, or the text is site-wide; Low when structure already makes it clear.
- Type: Content by default (reword the instruction to name the component). Technical when the fix
  is markup: give the component the name, heading or landmark label the instruction can refer to.
  Design when the pattern itself is symbol-only (icon-only pagination, colour-coded legend).
- Evidence: page screenshot with `highlight` on the instruction's element and the referenced
  component in frame; for a legend, the legend and one marked row; plus the `snapshot -s` excerpt
  showing the component's name. No GIF: the defect is static.
- Recommendation: keep the sensory cue and add the textual identification
  ([G96](https://www.w3.org/WAI/WCAG22/Techniques/general/G96)): name the component as its label
  names it, or give the component a heading or label and refer to that. Example:
  `<p>Select the green arrow labelled <strong>Next</strong> after the last question.</p>` with
  `<button>Next</button>`. Cite [F14](https://www.w3.org/WAI/WCAG22/Techniques/failures/F14) for
  position or shape, [F26](https://www.w3.org/WAI/WCAG22/Techniques/failures/F26) for symbols.
- Related: 1.4.1 (colour alone conveys information in the content); 1.1.1 (the symbol image has
  no or a shape-only alt); 4.1.2 (the referenced control has no name); 1.3.1 (the alternative is
  visual only); 3.3.2 (form labels). Split: wording → 1.3.3, missing name/alt → 4.1.2 or 1.1.1.
