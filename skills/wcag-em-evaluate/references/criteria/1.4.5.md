# 1.4.5 Images of Text

Level AA · WCAG 2.0+ · Guideline 1.4 Distinguishable · Group: `visual`

Sources: [Understanding](https://www.w3.org/WAI/WCAG22/Understanding/images-of-text.html)
· [Spec](https://www.w3.org/TR/WCAG22/#images-of-text)
· [Techniques](https://www.w3.org/WAI/WCAG22/quickref/#images-of-text)
· [Plain English](https://aaardvarkaccessibility.com/wcag-plain-english/1-4-5-images-of-text/)
· ACT: [0va7u6](https://www.w3.org/WAI/standards-guidelines/act/rules/0va7u6/)

## Requirement

> If the technologies being used can achieve the visual presentation, text is used to convey
> information rather than images of text except for the following:
>
> - Customizable: The image of text can be visually customized to the user's requirements;
> - Essential: A particular presentation of text is essential to the information being conveyed.
>
> Note:
> Logotypes (text that is part of a logo or brand name) are considered essential.

Terms (WCAG 2.2 glossary): **images of text**: "text that has been rendered in a non-text form
(e.g., an image) in order to achieve a particular visual effect [...] This does not include text
that is part of a picture that contains significant other visual content." **text**: "sequence of
characters that can be programmatically determined, where the sequence is expressing something in
human language". **visually customized**: "the font, size, color, and background can be set".
**essential**: "if removed, would fundamentally change the information or functionality of the
content, and information and functionality cannot be achieved in another way that would conform".

## In plain terms

Words rendered as pixels cannot be reflowed, recoloured, resized sharply or set in another
typeface, so people with low vision, visual tracking problems or reading disabilities lose the
settings they depend on. When HTML and CSS can produce the look, the author presents the words as
text; an image of text stays allowed when the user can customise it, when the exact rendering is
the point (a logo, by the note) or when the same words are also shown as real text beside it.

## Applies when

- Present: a rendered image on the sample shows readable words in a human language: an `img`, an
  `input type="image"`, an `object` or `embed` holding an image, an inline `svg` with an `<image
href>` inside, an SVG file loaded through `img` (its `<text>` becomes pixels), a CSS
  `background-image`, a `role="img"` element over a background image, or a `canvas` that draws
  words. Detect with `images.js` (step 1) and the screenshots of step 2, never from the name.
- Not present: no rendered image in any state or frame shows words. Inline SVG `<text>`, icon
  fonts, web fonts, `text-transform`, `text-shadow`, CSS gradients on text and emoji never count.
- Exceptions: (1) Customizable: "the font, size, color, and background can be set" by a control on
  the page or site ([C30](https://www.w3.org/WAI/WCAG22/Techniques/css/C30)); all four, not some.
  (2) Essential: logotypes by the note; ACT 0va7u6 adds text in "a digitized image of a physical
  object", in "a free-form digital illustration", in an image "with other graphical objects, where
  its relationship is informative", and text where "changing part of the presentation would alter
  the meaning". (3) Not an image of text: text in "a picture that contains significant other
  visual content" (graphs, screenshots, diagrams). (4) "Where images of text are used in addition
  to text to convey the same information, and where both are presented to the user, this success
  criterion is met." (5) The technology cannot achieve the presentation, or the font is one "the
  author doesn't have the right to redistribute": a claim to confirm, never a default for HTML.

## axe-core

No axe-core rule is tagged with this criterion; everything below is manual. ACT 0va7u6 (rendered
image resources with no visible text unless decorative, incidental or essential) is the base.

## Manual procedure

Visual mode at `set viewport 1280 900`, the sample as loaded, then every recorded state (cookie
dialog, menu open, each carousel slide, expanded section); `snapshot` again after each change.

1. Inventory the rendered images: switch every lazy image to eager and wait for the network, run
   `images.js`, count `<image>` children of inline SVG, and read the `<text>` of every SVG file
   loaded as an image. Scrolling to the bottom leaves the lazy images in between unloaded, and an
   unloaded image reports a 0 box that the filter below drops.

   ```bash
   agent-browser eval --stdin <<'EOF'
   (() => {
     for (const i of document.querySelectorAll('img[loading="lazy"]')) i.loading = 'eager'
     return document.querySelectorAll('img[loading="eager"]').length
   })()
   EOF
   agent-browser wait --load networkidle
   agent-browser eval --stdin < <skill-dir>/scripts/probes/images.js
   agent-browser get count "svg image"
   agent-browser eval --stdin <<'EOF'
   (async () => {
     const out = []
     for (const el of document.querySelectorAll('img[src], input[type="image"][src]')) {
       const src = el.getAttribute('src') || ''
       if (!el.getClientRects().length || !/\.svg([?#]|$)|^data:image\/svg/i.test(src)) continue
       const entry = { src: src.slice(0, 120), alt: el.getAttribute('alt') }
       try { const markup = await (await fetch(el.currentSrc || el.src)).text()
         entry.words = [...markup.matchAll(/<text[^>]*>([\s\S]*?)<\/text>/gi)]
           .map((m) => m[1].replace(/<[^>]+>/g, '').trim()).filter(Boolean)
       } catch (error) { entry.error = String(error) }
       out.push(entry) }
     return { svgAsImage: out }
   })()
   EOF
   ```

   Keep every `images.js` entry with `width` and `height` above 0 and `kind` `img`, `input-image`,
   `object`, `css-background`, `canvas` or `role-img`, including `visible: false` ones with a
   non-zero box (`aria-hidden` images count as invisible and still render); keep an inline `svg`
   only when the `svg image` count is above 0 and the `<image>` sits inside it. Match `svgAsImage`
   by `src`; an `error` entry (cross-origin fetch) is judged from its screenshot in step 2, which
   also looks for words behind real text, where the probe skips background images. Done when every
   kept image has its fields, no `img` entry with a `src` has `width` 0, and every SVG file has
   `words` or `error`.

2. Find the words. Take the full-page screenshot and read it; mark every image region that shows
   readable words. Then screenshot each such region and each entry whose fields suggest words too
   small to read there: `src` containing heading, title, banner, hero, button, btn, cta, nav, menu,
   quote, promo, slogan or text; `alt` or `name` reading as a sentence, label, price or date; a
   wide, short box; `inLink` or `inButton` with an empty `controlText`; `svgAsImage[].words` set.

   ```bash
   agent-browser screenshot .notes/audit/evidence/<sample>-145-page.png --full
   agent-browser scrollintoview "<css>"
   agent-browser screenshot "<css>" .notes/audit/evidence/<sample>-145-<n>.png
   ```

   Read each element screenshot; note the words it shows and what else the image holds (photo,
   drawing, brand mark, chart, nothing). Done when every candidate is "no words" or has its list.

3. Classify every image with words; the first class that fits wins (ACT 0va7u6 expectation and
   glossary). Not text: characters expressing nothing in a human language ("B", "I", "ABC" on an
   editor toolbar, a lone "A" on a font-size button); drop the image. Essential: a logotype, brand
   mark, product name or slogan set as a brand; a digitised physical object (scanned letter,
   street sign, handwriting, signature); free-form illustration with lettering; a chart, diagram,
   map or infographic whose words label graphics; a font specimen; a presentation whose change
   would alter the meaning. Incidental: the words are not a significant part of the picture
   (signage in a street photo, spines on a bookshelf, a name tag). Decorative: the image carries
   no information; `alt=""` or `presentational: true` does not decide this: "Welcome to our
   website" as an image with `alt=""` is still an image of text (ACT 0va7u6 failed example 4).
   Candidate: everything else: headings, paragraphs, quotes, button and menu labels, banners, price
   lists, schedules, posters, flyers, `canvas` labels. Done when every image with words has a class.

4. Apply the 1.4.5 exceptions to each candidate. In addition to text: the same words appear as
   visible text next to the image (`nearbyText`, `figcaption`, `controlText`, `get text "<css>"`
   on the surrounding block) → pass here (ACT 0va7u6 and 1.4.9 still fail it); words only in
   `alt`, `aria-label`, `title` or a visually hidden span are not "presented to the user" and the
   candidate stays. Customizable: look for a control that switches the image to text or its style.

   ```bash
   agent-browser eval --stdin <<'EOF'
   (() => ({
     alternateStyles: [...document.querySelectorAll('link[rel~="alternate"][rel~="stylesheet"]')]
       .map((l) => l.title || l.href),
     switches: [...document.querySelectorAll('a, button, [role="button"], select')]
       .map((el) => (el.textContent || el.getAttribute('aria-label') || '').trim().slice(0, 60))
       .filter((t) => /text.only|text version|plain text|font|display setting|readab/i.test(t)),
   }))()
   EOF
   ```

   When a control is found, `click "<css>"`, `wait 500`, `snapshot -s "<css>"` and screenshot the
   image again: it is replaced by text ([C30](https://www.w3.org/WAI/WCAG22/Techniques/css/C30))
   or the user can set "the font, size, color, and background". All four settable → pass; one to
   three → fail (see Deciding); nothing found → the candidate stays. Technology limit: HTML and
   CSS achieve typefaces (`@font-face`), colour, gradients, shadows, outlines and rotation, so a
   display typeface is no limit; the Understanding still allows an image for a font "the author
   doesn't have the right to redistribute" or where "the author cannot format the text to get the
   same effect" (hand-drawn, textured or 3D lettering): those go to the confirmation queue with
   the question written down. Done when every candidate is pass, fail or a queued question.

5. Frames, states and swaps. `get count "iframe"`; `eval` and `get count` always read the main
   document, so list each frame's images from the main frame:

   ```bash
   agent-browser eval --stdin <<'EOF'
   (() => [...document.querySelectorAll('iframe')].map((f) => {
     try { const d = f.contentDocument
       return { frame: f.id || f.src, images: [...d.images]
         .map((i) => ({ src: i.currentSrc, alt: i.alt, w: i.width, h: i.height })) }
     } catch (error) { return { frame: f.id || f.src, error: String(error) } }
   }))()
   EOF
   ```

   A frame with `images` goes through steps 2 to 4 with `screenshot "<iframe css>"` as its pixels; a
   frame with `error` (cross-origin) is read with `frame "<css>"`, `snapshot` (image names only) and
   `frame main` — only `snapshot` and `get attr` honour the selected frame — its pixels again from
   the iframe screenshot; a third-party frame (ad, widget, map) is noted as such. Advance a carousel
   with `click` on its next control and `wait 500`; open menus and dialogs; `hover "<css>"` an image
   button that swaps its image and screenshot it. Done when each state and frame is through 1 to 4.

6. Tree limits. `snapshot` shows role and name, never whether pixels hold words: the screenshot is
   the only evidence, no screen reader is involved. Record `cannot-tell`, selector in the notes, for
   an unloaded image, an unreadable `canvas` or a frame `frame` rejects. Done when none is open.

7. Evidence per fail: `highlight "<css>"`, then a region `screenshot <path>`, plus the element
   screenshot of step 2; for words too small to read at 1280, `set viewport 640 900`, a second
   element screenshot, then `set viewport 1280 900`. Done when every fail has its screenshot paths.

## Deciding

- Fail (certainty ≥ 90):
  - An `img` or `input type="image"` whose SVG source holds `<text>` with words in a human
    language (`svgAsImage[].words` non-empty), not a logotype, with no visible text equivalent and
    no customisation control — 90 (ACT 0va7u6 failed example 5).
  - An image whose pixels show nothing but words in an ordinary typeface (a heading, paragraph,
    quote, button or menu label, price list), no brand mark, photo or drawing, and the words exist
    at most in `alt`, `aria-label`, `title` or a hidden span — 90 (0va7u6 failed examples 1–3).
- Fail (70–89):
  - Words over a photo, gradient or background art where the words carry the message (hero
    banner, promo, call to action) and no visible text repeats them — 85.
  - A poster, flyer, schedule, table, price list or infographic that is mostly words and whose
    pictures carry no information of their own — 80.
  - Words set in a display typeface (headings, menu or button labels) that `@font-face` would
    reproduce — 75; a licence claim ("font not redistributable") moves it to the queue.
  - A `canvas` that draws headings, labels or sentences and is not a chart or diagram — 75.
  - A customisation control that sets one to three of font, size, colour and background — 75.
- Needs confirmation (50–69):
  - Hand-drawn, textured or 3D lettering that is not a brand — 60; ask "Is this presentation
    essential to the content, and could a web font or CSS effect reproduce it?"
  - An image that may be a logotype, campaign mark or product name — 60; ask if it is a brand.
  - A screenshot or photo shown for the words in it (a quoted post, a chat, a form the user must
    read) — 65; ask whether the other visual content is significant.
  - Image text inside a third-party iframe — 55; ask whether the conformance claim covers it.
- Pass: every rendered image with words, in every state and frame, is a logotype, essential,
  incidental, in a picture with significant other visual content, decorative without information
  or non-language characters; or its words are visible text beside it; or all four are settable.
- Not present: no rendered image on the sample, in any state or frame, shows readable words.
- False positives to avoid: logos and wordmarks; inline SVG `<text>` (ACT 0va7u6 assumption);
  icon fonts and toolbar characters such as "B" and "ABC"; charts, maps, diagrams, screenshots,
  scans, photographed signs and font specimens; incidental words in a photo; words visibly repeated
  beside the image (met here, a fail only under 1.4.9); a missing `alt` (1.1.1); low contrast in
  the image (1.4.3); blur at zoom (1.4.4 exempts images of text); web fonts and effects are text.

## Reporting

- File under: 1.4.5 for the words rendered as an image; a missing or wrong `alt` on the same image
  is 1.1.1, low contrast inside it is 1.4.3, and at target level AAA it is also judged under
  1.4.9. One issue per pattern (all headings, the whole menu), naming the other samples it is on.
- Title patterns: "Headings are images of text", "Navigation labels are images", "Button label is
  an image of text", "Banner text exists only as an image", "Price list is a scanned image"
- Severity: High when the image holds content the task needs or the sample's main content
  (prices, opening hours, instructions, terms, a form, long paragraphs), or the pattern is
  site-wide (every heading or menu label); Medium when headings, banners, buttons or quotes carry
  the message in short, large words; Low for one short, large label that nearby text also explains.
- Type: Technical by default (rebuild the words as HTML text with CSS and a web font). Content
  when an editor uploaded the image (poster, flyer, scanned price list) and the fix is adding the
  words as text or replacing the upload. Design when the lettering treatment itself must change.
- Evidence: the region screenshot with `highlight` on the image, plus the element screenshot of
  the words (and the zoomed one where taken); rest and hover shots for a swap. No GIF: it is static.
- Recommendation: present the words as text styled with CSS
  ([C22](https://www.w3.org/WAI/WCAG22/Techniques/css/C22)) and a web font, keeping structure and
  presentation apart ([G140](https://www.w3.org/WAI/WCAG22/Techniques/general/G140)), e.g.
  `<h2 class="hero-title">Summer sale</h2>` with `.hero-title { font-family: 'Brand Display' }`.
  Where the image must stay, show the same words as visible text beside it or add a switch to a
  text rendering ([C30](https://www.w3.org/WAI/WCAG22/Techniques/css/C30)); OCR a linked scanned
  document ([PDF7](https://www.w3.org/WAI/WCAG22/Techniques/pdf/PDF7)).
- Related: 1.1.1 (alt of the same image); 1.4.3 (contrast of the words); 1.4.9 (AAA, only
  decoration and essential excepted); 2.4.4 and 4.1.2 (an image link or button with no name).
