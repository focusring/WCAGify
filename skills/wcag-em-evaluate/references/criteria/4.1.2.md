# 4.1.2 Name, Role, Value

Level A · WCAG 2.0+ · Guideline 4.1 Compatible · Group: `structure` (also `keyboard`, `forms`)

Sources: [Understanding](https://www.w3.org/WAI/WCAG22/Understanding/name-role-value.html) ·
[Spec](https://www.w3.org/TR/WCAG22/#name-role-value) ·
[Techniques](https://www.w3.org/WAI/WCAG22/quickref/#name-role-value) ·
[Plain English](https://aaardvarkaccessibility.com/wcag-plain-english/4-1-2-name-role-value/)
· ACT rules (`https://www.w3.org/WAI/standards-guidelines/act/rules/<id>/`): 97a4e1, m6b1q3, c487ae,
59796f, e086e5, 2t702h, cae760, 4b1c6c, 674b10, 5f99a7, 6a7281, 5c01ea, 4e8ab6, 6cfa84, 307n5z

## Requirement

> For all user interface components (including but not limited to: form elements, links and
> components generated by scripts), the name and role can be programmatically determined; states,
> properties, and values that can be set by the user can be programmatically set; and
> notification of changes to these items is available to user agents, including assistive
> technologies.
>
> Note: This success criterion is primarily for web authors who develop or script their own user
> interface components. For example, standard HTML controls already meet this success criterion
> when used according to specification.

Terms (WCAG 2.2 glossary): **user interface components**: "a part of the content that is perceived
by users as a single control for a distinct function [...] what the user perceives as separate
controls". **name**: "text by which software can identify a component within web content to the user
[...] may be hidden and only exposed by assistive technology". **states**: "dynamic property [...]
that may change in response to user action [...] focus, hover, select, press, check, [...]
expand/collapse".

## In plain terms

Every control tells assistive technology what it is called (name), what it is (role) and what state
or value it has now (open, checked, selected, a slider's value), and the browser is told when that
changes. Native HTML controls used as specified do this on their own; a `div` scripted into a
button, custom checkboxes, tabs, menus and comboboxes must say it with ARIA and keep it current, or
a screen reader hears only "clickable" and voice control has no name to call.

## Applies when

- Present: anything a user perceives as one control: `a[href]`, `area[href]`, `button`, `input`,
  `select`, `textarea`, `summary`, `iframe`, and anything scripted into a control (a widget `role`,
  or a `div`/`span` with a click handler or `tabindex`). Step 1 lists them per state; a control
  shown only in a state (open menu, dialog, error) counts there.
- Not present: no link, form control, `iframe` or scripted control in any state; check header,
  footer and cookie dialog first.
- Exceptions: none in the text. Out of scope: static text, decorative images, an element out of
  the tree in every state, an `iframe` with `tabindex="-1"` or marked decorative (cae760), a
  `menuitem` or `summary` not perceived as a control (m6b1q3, 2t702h). Disabled fields count.

All rows but the last run by default (WCAG 2.0 A/AA set). Settles: a non-empty name on every button,
link, field, tab, menu item, `summary` and `iframe`; valid, permitted and complete ARIA; nothing
focusable behind `aria-hidden` or in a widget. Incomplete means a name or reference points at hidden
or missing content: go to the step named. Leaves open: a scripted control with no role (F59, F42); a
name that says nothing; a role that contradicts the function; states that follow operation (F15,
ARIA5); custom field values; names changing with state (F20); emulated focus (F79); multi-part
fields (F86); same-named `iframe`s (4b1c6c); states without an axe run, frames, shadow roots.

## Manual procedure

Steps 1 to 6 are the `structure` pass, step 7 what the `keyboard` pass adds while operating and
step 8 what the `forms` pass adds on the widgets it fills. Run the axe pass on each state first.

1. Inventory the controls per recorded state (re-run in each state; refs and selectors go stale):

   ```bash
   agent-browser wait --load networkidle
   agent-browser snapshot -i
   agent-browser eval --stdin < <skill-dir>/scripts/probes/focusables.js
   agent-browser eval --stdin < <skill-dir>/scripts/probes/forms.js
   agent-browser eval --stdin < <skill-dir>/scripts/probes/links.js
   agent-browser eval --stdin < <skill-dir>/scripts/probes/structure.js
   ```

   Keep per state: `order[]` (`tag`, `role`, `name`), `fields[]` (`role`, `name`, `nameSource`,
   `value`), `ariaHiddenFocusable[]`, `clickableNotFocusable[]`, `emptyLinks[]`, `iframes[]`
   (`name`, `src`) and the snapshot. Done when every state has its inventory.

2. Names (F68, F111, F86; 97a4e1, c487ae, e086e5, 59796f, m6b1q3, 2t702h, cae760, 4b1c6c). The name
   that counts is the quoted string on the node in `snapshot -i`; `order[]` and `fields[]` point at
   the candidates but compute no name from content, so a conforming `<div role="checkbox">Buy</div>`
   reads `''` there. Run `snapshot -s "<sel>"` on every empty candidate and on every axe incomplete:
   no quoted name, in a state without an axe run, is a fail (95), and F111 (95) when the screen
   shows label text beside it. A name that identifies nothing ("button", "icon", a file name, a
   `summary` named only by its `::marker`, the browser default "Submit"/"Submit Query" on an
   `input[type="image"]` without `alt`): fail (85). A multi-part field (date, phone) with
   `nameSource: 'none'` on a later box: F86 (90). `nameSource: 'title'` passes with a note
   ([H65](https://www.w3.org/WAI/WCAG22/Techniques/html/H65)). An `iframes[]` entry with `name` null
   and no negative `tabindex`: fail (95); two sharing a name: enter each with `frame <@ref>` and
   fail (80) only when the resources are neither the same nor equivalent (4b1c6c). `emptyLinks[]`
   and unnamed image links: `fail` here, the issue goes under 2.4.4 or 1.1.1. Done when every
   control of every state has a name verdict.

3. Roles (F59, F42; 674b10, 4e8ab6; [ARIA4](https://www.w3.org/WAI/WCAG22/Techniques/aria/ARIA4)).
   `focusables.js` writes the tag into `role` when no `role` attribute is set, so a scripted control
   without a role is an `order[]` entry whose `role` repeats its `tag` (`div`, `span`, `li`) and a
   `generic` node in `snapshot -i`. One that acts as a control (a click changes the page, a pointer
   cursor, an `onclick`): fail (95; F59); a `tabindex="0"` scrollable region or route-change focus
   target is no control and passes. A `clickableNotFocusable[]` entry that visibly acts as a control
   with no role: F59 (90); its keyboard access is 2.1.1. An `a` whose `role` reads `generic`, acting
   as a link or button: F42 (90). A `role="link"` that toggles or submits, a `role="button"` whose
   `href` opens a page, a `role="tab"` on a link that navigates away: fail (80). Without an axe run,
   `get html "<selector>"` on each custom widget: a `role` outside WAI-ARIA, an `aria-*` of the
   wrong type or a required state missing (`checkbox` without `aria-checked`): fail (95). Done when
   each role matches its function.

4. Hidden and nested controls (6cfa84, 307n5z). `ariaHiddenFocusable[]` non-empty in a state
   without an axe run: fail (95); focus lands on a node the tree does not have. In `snapshot -i`,
   a node whose role takes presentational children (`button`, `checkbox`, `radio`, `switch`, `tab`,
   `option`, `menuitemcheckbox`, `menuitemradio`, `slider`, `meter`, `progressbar`, `img`; not a
   plain `menuitem`) with a focusable descendant, such as a link inside a button: fail (85; browsers
   differ). Done when both lists are empty or recorded.

5. States and values as shown ([ARIA5](https://www.w3.org/WAI/WCAG22/Techniques/aria/ARIA5),
   G108). For each custom widget in each recorded state read its node in `snapshot -i` against the
   screenshot. The tree writes `[expanded=true|false]` and `[checked=true|false]` with the value,
   `[selected]` and `[disabled]` only when true, and a slider's or combobox's value after the colon;
   it never writes `pressed`, so read that one with `get attr "<sel>" aria-pressed` (selector first,
   attribute second). An open menu whose button reads `[expanded=false]` or carries no `expanded`, a
   ticked custom checkbox without `[checked=true]`, an active tab without `[selected]`, a toggle
   drawn "on" whose `aria-pressed` is not `true`: F15 (85). Native controls carry their state by
   spec (H91): pass. Done when every widget's state has a matching flag or a recorded fail.

6. Cannot-tell. The tree shows names, roles and attribute values, not what a screen reader announces
   or whether an API event fires. Record `cannot-tell` and queue a screen-reader check for a custom
   element with a closed shadow root or a canvas-drawn control whose node is bare, a control in a
   cross-origin `iframe` that `frame <@ref>` cannot enter, and a PDF sample (PDF10, PDF12). Enter
   each same-origin frame with `frame <@ref>`, repeat steps 1 to 5 and return with `frame main`; an
   open shadow root is already in the snapshot, though the probes stop at its boundary. Done when
   every unsettled control carries `cannot-tell` with its reason and every reachable frame has been
   walked.

7. `keyboard` pass, states while operating (F79, F20, F15). After each operation run
   `snapshot -s "<selector>"` and compare with the screen: `Enter` on a disclosure or menu button
   flips `[expanded=false]` to `[expanded=true]`; `Space` on a custom checkbox or switch flips
   `[checked=...]` and on a toggle button flips `aria-pressed`; `ArrowDown` in a tab list moves
   `[selected]`. The screen changes and the value does not: fail (85). `eval --stdin` with an IIFE
   returning `document.activeElement.tagName` (wrap every heredoc body in `(() => { ... })()`, or a
   top-level `const` throws on its second run) giving `BODY` or a wrapper while a child is drawn as
   focused: F79 (80). An icon that flips (play to pause) while the name stays: F20 (80); an
   `aria-pressed` flip with a fixed name passes. Done when every widget has been operated.

8. `forms` pass, widgets it fills. Re-run `forms.js` after `fill`, after `select` and after a submit
   with errors. Its `value` is the DOM `value` property, which a custom `textbox` or `combobox`
   never has, so read those from `snapshot -s "<sel>"`, which prints the value after the colon:
   nothing there while the screen shows a value: fail (85). A field drawn as invalid with
   `ariaInvalid` null and no `describedbyText` naming the error: fail (75); required only visually,
   no `required` or `ariaRequired`: note for 3.3.2. Done when every filled widget shows its value
   and validity in the tree.

## Deciding

- Fail (certainty ≥ 90): a violation from any `failure` rule in the table (100); in a state without
  an axe run: no name on a button, link, field, tab, menu item, `summary` or `iframe` (95; F68,
  F111, cae760); a focusable `div`/`span` acting as a control with no role (95; F59); a clickable
  one acting as a control with no role (90; F59); an `a` without `href` acting as a link or button
  (90; F42); a focusable element inside `aria-hidden="true"` (95; 6cfa84); an invalid `role`,
  undefined `aria-*`, wrong value type, attribute not permitted or required state missing (95;
  674b10, 5f99a7, 6a7281, 5c01ea, 4e8ab6); unnamed multi-part boxes (90; F86).
- Fail (70–89): a custom widget whose visible state or value is absent from the tree or does not
  follow operation (85; F15, ARIA5); a name that identifies nothing (85); a focusable child in a
  widget node (85; 307n5z); a role contradicting the function (80); a name that stays while the
  meaning flips (80; F20); emulated focus (80; F79); same-named `iframe`s whose resources are not
  equivalent (80; 4b1c6c); a visually invalid field with no programmatic invalid state (75); an
  unnamed disabled field (75; e086e5).
- Needs confirmation (50–69): a bare node for a closed shadow root or canvas control (60), ask for a
  screen-reader check; a pattern browsers implement differently (60), ask which assistive
  technologies count; an `aria-label` in a language you cannot judge (55), ask a speaker.
- Pass: every component in every recorded state has a name that identifies it, a valid role matching
  its function, states and values that follow each operation, and nothing focusable that the tree
  hides.
- Not present: no link, form control, `iframe` or scripted control in the sample or any state.
- False positives to avoid: native controls used as specified need no ARIA (H91, H88); the default
  "Submit" name on `input[type="submit"]` (97a4e1); a name from `aria-label` (ARIA14),
  `aria-labelledby` (ARIA16), `title` (H65) or hidden text, though invisible; a visible label unlike
  the name (2.5.3); a decorative image inside a link or button with text; `role="presentation"` on a
  focusable element (the native role stands); a `tabindex="0"` scrollable region or focus target,
  which is no control; a probe `name` of `''` on a widget named from its own content; a hidden
  dialog background whose controls are unfocusable; `aria-current` missing; landmark ARIA (1.3.1).

## Reporting

- File under: 4.1.2 for unnamed buttons, fields, tabs, menu items, `summary` and `iframe`s, missing
  or wrong roles, missing or stale states, invalid ARIA, hidden focusables and emulated focus. An
  unnamed image link or image button: one issue under 1.1.1 (F89); an empty text link: 2.4.4; a
  visible label not in the name: 2.5.3; a control the keyboard cannot operate: 2.1.1, its missing
  role goes here. One issue per component, naming every state and sample it fails on.
- Title patterns: "Icon button has no name", "Menu button does not expose its open state",
  "Custom checkbox is a div without a role", "Tabs do not expose the selected tab"
- Severity: High when a control on the main task path (navigation, search, submit, cookie consent,
  dialog close, a required field) has no name, no role or a state that never updates; Medium when a
  secondary control (share icon, carousel dots, sort toggle) is affected or a component's ARIA is
  invalid throughout; Low when the name is only weak ("Submit Query").
- Type: Technical (markup, ARIA, script); Content only when the missing name is editorial text
  entered in a CMS, such as an image button's alt.
- Evidence: the page screenshot with `highlight` on the control and its `snapshot -s` line quoted;
  for a state defect a GIF from `record start` of the widget toggling, with the node's line before
  and after; for an `iframe`, a screenshot of the embedded content.
- Recommendation: use the native element ([H91](https://www.w3.org/WAI/WCAG22/Techniques/html/H91),
  [H88](https://www.w3.org/WAI/WCAG22/Techniques/html/H88)): `<button type="button">Menu</button>`;
  name it with visible text, a `label` (H44), `aria-label`
  ([ARIA14](https://www.w3.org/WAI/WCAG22/Techniques/aria/ARIA14)) or `aria-labelledby`
  ([ARIA16](https://www.w3.org/WAI/WCAG22/Techniques/aria/ARIA16)); give an `iframe` a `title`
  (H64). For a custom widget set the role (ARIA4) and state (ARIA5) and update it in the script that
  changes the view: `<button aria-expanded="false" aria-controls="nav">Menu</button>`, `"true"` on
  open; `<div role="checkbox" tabindex="0" aria-checked="false">` (G108).
- Related: 1.1.1 (image buttons, image links); 2.4.4 (link text); 2.5.3 (label in name); 1.3.1
  (label relationships, F111); 3.3.2 (visible label); 2.1.1 (operable); 4.1.3 (status messages).
