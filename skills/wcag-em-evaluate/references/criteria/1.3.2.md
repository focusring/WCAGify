# 1.3.2 Meaningful Sequence

Level A · WCAG 2.0+ · Guideline 1.3 Adaptable · Group: `structure`

Sources: [Understanding](https://www.w3.org/WAI/WCAG22/Understanding/meaningful-sequence.html) ·
[Spec](https://www.w3.org/TR/WCAG22/#meaningful-sequence) ·
[Techniques](https://www.w3.org/WAI/WCAG22/quickref/#meaningful-sequence) ·
[Plain English](https://aaardvarkaccessibility.com/wcag-plain-english/1-3-2-meaningful-sequence/) ·
ACT: none mapped to this criterion

## Requirement

> When the sequence in which content is presented affects its meaning, a correct reading sequence
> can be programmatically determined.

Terms (WCAG 2.2 glossary): **correct reading sequence**: "any sequence where words and paragraphs
are presented in an order that does not change the meaning of the content". **programmatically
determinable**: "determined by software from author-supplied data provided in a way that different
user agents, including assistive technologies, can extract and present [...]".

## In plain terms

Screen readers, braille displays and text-to-speech read the DOM order (the accessibility tree),
never the rendered layout. The author keeps every sequence whose order carries meaning in that
order in the code: sentences, steps, tables, a heading before its section, a label with its field,
a name with its price. Independent regions (navigation, main, sidebars) may come in any order, and
one correct order is enough. Screen reader and speech users depend on it; the fix is in the code.

## Applies when

- Present: the sample renders text. W3C: "in HTML, text is always a meaningful sequence"; "Tables
  and ordered lists are meaningful sequences, but unordered lists are not." The programmatic order
  goes wrong through CSS that moves content away from its DOM position (positioning, `float`,
  flex `order`, reversed direction, grid placement), layout tables, white-space formatting (spaced
  letters, `<pre>` columns, `<br>` letters) and mixed-direction text; steps 3 to 6 detect them.
- Not present: the sample renders no text at all (an image-only or player-only page). Every other
  sample ends in `pass`, `fail` or `cannot-tell`.
- Exceptions: none in the criterion text. The opening clause limits the scope: "Providing a
  particular linear order is only required where it affects meaning", "There may be more than one
  order that is 'correct'" and "Only one correct order needs to be provided". Main before or after
  navigation, sidebars beside an article and independent cards in any order all conform.

## axe-core

No axe-core rule is tagged with this criterion; everything below is manual. The `a11y` output for
the sample carries nothing for 1.3.2: treat its silence as untested, never as a pass.

## Manual procedure

Structure mode: read the sample as loaded. Repeat steps 2 to 6 for every recorded page state (an
open menu, a dialog, an expanded section, the error state); run `snapshot` again after each.

1. Record the visual reading order. Desktop viewport, full-page screenshot as the reference:

   ```bash
   agent-browser set viewport 1280 900
   agent-browser screenshot .notes/audit/evidence/<sample>-reading-order.png --full
   ```

   Read the screenshot and list the sequences whose order carries meaning: running text, steps,
   ordered lists, tables, headings with their content, labels with their fields, cards with name,
   price and button, captions, multi-column text. Done when that list is in the findings file.

2. Record the programmatic reading order:

   ```bash
   agent-browser snapshot
   agent-browser snapshot -s "<css of one region>"
   ```

   The tree is in DOM order, the order assistive technology reads; CSS placement does not change
   it. Walk each sequence of step 1 through the tree: heading before its section, label before its
   field, step 1 before step 2, one column complete before the next starts. Done when every
   sequence is marked "same meaning" or "changed", with both orders noted for a changed one.

3. Find content that CSS moves away from its DOM position
   ([F1](https://www.w3.org/WAI/WCAG22/Techniques/failures/F1)):

   ```bash
   agent-browser eval --stdin <<'EOF'
   (() => {
     const id = e => e.tagName.toLowerCase() + (e.id ? '#' + e.id : ''), out = []; let prev
     for (const e of document.querySelectorAll('body *')) {
       const c = getComputedStyle(e), r = e.getBoundingClientRect()
       if (c.display === 'none' || c.visibility === 'hidden' || !r.height) continue
       if (!e.innerText?.trim()) continue
       const p = getComputedStyle(e.parentElement), y = r.top + scrollY, flags = []
       if (/absolute|fixed/.test(c.position)) flags.push('positioned')
       if (c.order !== '0') flags.push('order')
       if (/reverse/.test(p.flexDirection)) flags.push('reverse')
       if (c.float !== 'none') flags.push('float')
       if (p.display === 'grid' && (c.gridRowStart !== 'auto' || c.gridColumnStart !== 'auto'))
         flags.push('grid')
       const hasText = [...e.childNodes].some(n => n.nodeType === 3 && n.textContent.trim())
       const movesUp = hasText && !!prev && y < prev.y - prev.h / 2
       if (flags.length || movesUp)
         out.push({ sel: id(e), text: e.innerText.trim().slice(0, 60), y: y | 0, flags, movesUp })
       if (hasText) prev = { y, h: r.height }
     }
     return out
   })()
   EOF
   ```

   Each entry is a container or element placed by CSS (its text is everything inside it), or a text
   element that renders above the element before it in the DOM (`movesUp`; the first item of every
   horizontal row and every table fires it). Find it in the screenshot and the tree: `movesUp` at
   the top of a second column or at the navigation keeps the meaning; `reverse` or `order` on the
   steps of a process, or a `positioned` heading read after its section, changes it. Done when
   every entry is judged.

4. Find text drawn with white space ([F32](https://www.w3.org/WAI/WCAG22/Techniques/failures/F32),
   [F33](https://www.w3.org/WAI/WCAG22/Techniques/failures/F33),
   [F34](https://www.w3.org/WAI/WCAG22/Techniques/failures/F34)):

   ```bash
   agent-browser eval --stdin <<'EOF'
   (() => {
     const id = e => e.tagName.toLowerCase() + (e.id ? '#' + e.id : '')
     const spaced = [], columns = [], nbsp = String.fromCharCode(160).repeat(3)
     const w = document.createTreeWalker(document.body, NodeFilter.SHOW_TEXT)
     for (let n; (n = w.nextNode()); ) {
       const t = n.textContent, el = n.parentElement, c = el && getComputedStyle(el)
       if (!t.trim() || !c || c.display === 'none' || c.visibility === 'hidden') continue
       const hit = t.trim().slice(0, 80)
       if (/(?:^|\s)(?:\S\p{Zs}){3,}\S(?=\s|$)/u.test(t)) spaced.push({ sel: id(el), hit })
       const pre = /pre/.test(c.whiteSpace) && t.includes('\n') && /\S[\p{Zs}\t]{3,}\S/u.test(t)
       if (pre || t.includes(nbsp)) columns.push({ sel: id(el), hit })
     }
     const br = [...document.querySelectorAll('h1,h2,h3,h4,h5,h6,th,td,p,span,div')]
       .filter(e => /^(?:\S<br\s*\/?>\s*){2,}\S$/i.test(e.innerHTML.trim()))
       .map(e => ({ sel: id(e), hit: e.innerHTML.trim().slice(0, 60) }))
     return { spaced, columns, br }
   })()
   EOF
   ```

   `spaced`: single characters separated by spaces or `&nbsp;`; F32 when the run is a word
   (W e l c o m e), correct for an initialism or one-letter list items. `columns`: three or more
   spaces on several preformatted lines, or three `&nbsp;` in a row in normal text; F33 when they
   draw columns of prose, F34 a table of data, correct for source code and ASCII art. `br`: one
   character per line (F32). Done when every hit is checked in the screenshot and judged.

5. Linearize layout tables ([F49](https://www.w3.org/WAI/WCAG22/Techniques/failures/F49)). Run
   `structure.js`; take every entry of `tables` with `layoutLike: true` or `thCount: 0` (a
   multi-row, multi-column layout table has neither `th` nor `role="presentation"`):

   ```bash
   agent-browser eval --stdin < <skill-dir>/scripts/probes/structure.js
   agent-browser get text "<table selector>"
   ```

   The text comes out in source order, cell by cell, row by row. Compare it with the screenshot.
   F49 is a meaningful sequence split or interleaved by the row order: a sentence spread over cells
   out of order, navigation links alternating with an article's paragraphs, a label in one row and
   its value two rows down. Done when every candidate table is marked correct or listed with text.

6. Mixed text direction ([H34](https://www.w3.org/WAI/WCAG22/Techniques/html/H34),
   [H56](https://www.w3.org/WAI/WCAG22/Techniques/html/H56)), only when the sample mixes a
   right-to-left script (Arabic, Hebrew, Persian, Urdu) with left-to-right text or numbers:

   ```bash
   agent-browser eval --stdin <<'EOF'
   (() => [...document.querySelectorAll('body *')].filter(e => [...e.childNodes].some(n =>
     n.nodeType === 3 && /[A-Za-z0-9]/.test(n.textContent) &&
     /[\p{Script=Hebrew}\p{Script=Arabic}]/u.test(n.textContent)))
     .map(e => e.tagName + '[direction=' + getComputedStyle(e).direction +
       (e.dir ? ', dir attr' : '') + ']: ' + e.textContent.trim().slice(0, 80)).slice(0, 40))()
   EOF
   ```

   Each hit is one element that holds a mixed run; `direction=rtl` without `dir attr` means it
   inherits from an ancestor, correct when the whole passage is right-to-left. In the screenshot,
   numbers, punctuation or the LTR fragment on the wrong side of the run point to a missing `dir` or
   RLM/LRM mark. Neither the tree nor the screenshot shows how a screen reader voices the run:
   record `cannot-tell` for a run the evaluator cannot read and queue it for a reader of that
   language. Done when every hit is judged.

Evidence for each changed sequence: `highlight "<css>"` on the region, `screenshot <path>`, and the
`snapshot -s` excerpt or the linearized table text in the findings file with both orders numbered. A
bidirectional run the evaluator cannot read is `cannot-tell` (step 6). A PDF sample is outside this
procedure ([PDF3](https://www.w3.org/WAI/WCAG22/Techniques/pdf/PDF3)): record `cannot-tell` and
queue it.

## Deciding

- Fail (certainty ≥ 90): a word whose letters are separated by spaces, `&nbsp;` or `<br>` and that
  is not an initialism (F32) — 90; prose in columns or data in a table drawn with white space in
  plain or preformatted text (F33, F34) — 90; a layout table whose linearized text interleaves two
  meaningful sequences or splits a sentence across cells out of order (F49) — 90.
- Fail (70–89): the tree reads a heading after its section, a label after its field, a caption
  away from its figure or a name next to another product's price because CSS moved it (F1) — 80;
  the steps of a process reordered by CSS — 80; two-column text whose DOM interleaves them — 75.
- Needs confirmation (50–69): DOM and visual order differ and whether the order carries meaning is
  a matter of intent (cards in a grid, a timeline) — 60; ask "does the visual order of <region>
  carry meaning?". A mixed-direction run that looks misordered — 55; ask a reader of the language.
- Pass: every sequence from step 1 reads with the same meaning in the tree; steps 4 and 5 found no
  failing hit; every mixed-direction run is judged correct, or there is none; every state holds.
- Not present: the sample renders no text at all.
- False positives to avoid: main, navigation and aside in any order; a DOM that flows column by
  column through a multi-column layout (Understanding, Example 1); positioned regions whose order
  carries no meaning (Example 2); a skip link or hidden text first in the DOM; a modal or menu at
  the end of the DOM; a spaced initialism ("W C A G"); CSS `letter-spacing` (C8); code and ASCII
  art in `<pre>`; a decorative element moved with `order`; an unordered list; a data table without
  headers (1.3.1); focus order alone (2.4.3); a whole page in `dir="rtl"`.

## Reporting

- File under: 1.3.2 for a reading order the tree gets wrong (F1, F49, F32) and for bidi runs;
  white-space tables and columns (F33, F34) fail 1.3.1 too: one issue under 1.3.1, naming 1.3.2;
  focus jumping with the DOM order is 2.4.3. One issue per pattern, naming every sample it is on.
- Title patterns: "Steps of <process> are read out of order", "Reading order of <region> differs
  from the visual order", "Heading of <section> is read after its content", "Letters of '<word>'
  are separated by spaces", "Layout table interleaves the navigation with the article"
- Severity: High when the scrambled sequence is instructions, a process, a form, a table or a
  product listing whose meaning is lost (wrong step order, a price under the wrong product); Medium
  when the meaning is recoverable with effort or the pattern sits in a site-wide template (heading
  after its section, interleaved sidebar); Low when a spaced word or passage stays understandable.
- Type: Technical (CSS order, positioning, layout tables, missing `dir`); Content when an editor
  typed the spaced letters, the `<br>` letters or the white-space table into a rich-text field.
- Evidence: the full-page screenshot with `highlight "<css>"` on the region, the visual order and
  the tree order numbered in the body, plus the `snapshot` excerpt or the table text; no GIF.
- Recommendation: put the content in the DOM in the order it is read and position it with CSS from
  that order ([C27](https://www.w3.org/WAI/WCAG22/Techniques/css/C27),
  [C6](https://www.w3.org/WAI/WCAG22/Techniques/css/C6)); remove `order` and `*-reverse` from
  meaningful sequences; replace the layout table with grid or flex, or reorder its cells so they
  linearize; space letters with CSS ([C8](https://www.w3.org/WAI/WCAG22/Techniques/css/C8)): `<h1
class="spaced">Welcome</h1>` with `.spaced { letter-spacing: 0.3em }`; wrap a mixed run in `<span
dir="rtl">` ([H56](https://www.w3.org/WAI/WCAG22/Techniques/html/H56)) or insert an RLM/LRM
  ([H34](https://www.w3.org/WAI/WCAG22/Techniques/html/H34)); replace a white-space table with a
  `<table>` and white-space columns with normal paragraphs
  ([G57](https://www.w3.org/WAI/WCAG22/Techniques/general/G57)).
- Related: 1.3.1 Info and Relationships (white-space tables, data in layout tables, fake lists);
  2.4.3 Focus Order (the same DOM/visual mismatch on focusable elements; reading is filed here).
