# 2.4.5 Multiple Ways

Level AA · WCAG 2.0+ · Guideline 2.4 Navigable · Group: `consistency`

Sources: [Understanding](https://www.w3.org/WAI/WCAG22/Understanding/multiple-ways.html) ·
[Spec](https://www.w3.org/TR/WCAG22/#multiple-ways) ·
[Techniques](https://www.w3.org/WAI/WCAG22/quickref/#multiple-ways) ·
[Plain English](https://aaardvarkaccessibility.com/wcag-plain-english/2-4-5-multiple-ways/) ·
ACT: none

## Requirement

> More than one way is available to locate a web page within a set of web pages except where the
> web page is the result of, or a step in, a process.

Terms (WCAG 2.2 glossary).

**web page**: "a non-embedded resource obtained from a single URI using HTTP plus any other
resources that are used in the rendering or intended to be rendered together with it by a user
agent". The single URI is what makes a page countable here. Example 2 of the definition settles
applications: "A web mail program built using Asynchronous JavaScript and XML (AJAX). The program
lives entirely at http://example.com/mail, but includes an inbox, a contacts area and a calendar.
Links or buttons are provided that cause the inbox, contacts, or calendar to display, but do not
change the URI of the page as a whole." Inbox, contacts and calendar are one web page, not three
pages that each need two ways. Note 2: "For the purposes of conformance with these guidelines, a
resource must be "non-embedded" within the scope of conformance to be considered a web page." — a
document loaded in an `iframe` is not a web page of the set.

**set of web pages**: "collection of web pages that share a common purpose and that are created by
the same author, group or organization". Its examples fix three splits. A publication "split across
multiple web pages, where each page contains one chapter or other significant section of the work"
is one set: "The publication is logically a single contiguous unit, and contains navigation
features that enable access to the full set of pages." An e-commerce site's checkout is a set apart
from its product pages because "the template changes; the navigation and other elements are
removed, so the pages in that process are functionally and visually different. The checkout pages
are not part of the set of product pages." A blog on a sub-domain "which has a different navigation
and is authored by a distinct set of people" is a set of its own. Note: "Different language
versions would be considered different sets of web pages."

**process**: "series of user actions where each action is required in order to complete an
activity". Its Example 2 — "An account registration page requires successful completion of a Turing
test before the registration form can be accessed." — puts a page reachable only through a CAPTCHA
inside a process.

## In plain terms

Every page of a site (or of another set of pages with one purpose and one author) can be found in
at least two different ways: a navigation menu and a site search, a site map and links between
pages, a category list box and a search. Which two is the author's choice. The Intent sets the
floor for small sites: "Even small sites should provide users some means of orientation. For a
three or four page site, with all pages linked from the home page, it may be sufficient simply to
provide links from and to the home page where the links on the home page can also serve as a site
map." Screen reader and magnifier users often prefer a search to a long navigation bar, people with
cognitive disabilities a table of contents or site map that gives an overview, people with limited
mobility the route with the fewest repeated actions. Readers of digital publications navigate by
table of contents, by index and by static page break locations.

## Applies when

- Present: the scope in `index.md` covers more than one web page — more than one URI — sharing a
  purpose and an author, which is every website audit. Every non-exempt sample is a page to be
  located; the mechanisms come from the `structure`, `links` and `forms` probe outputs and from the
  browser (step 2).
- Not present: the scope is one web page (one URI: a single document, or a one-page application
  whose views do not change the URI of the page as a whole and that has no other pages under
  audit), or every sample is exempt under the process exception. Record `not-present` for the
  report.
- Exceptions: "except where the web page is the result of, or a step in, a process". The result of
  a process exists only after a user action produced it. The Understanding gives two: a search
  results page ("There is no other way to locate the search results except to perform the search
  process itself.") and a funds transfer confirmation on a banking site ("There is no other way to
  locate the confirmation of fund transfer until the account owner completes the transfer."). A
  step in a process is one of a required sequence: a checkout, registration or wizard step, a form
  behind a CAPTCHA. Recognise both from the "Processes" section of `.notes/sample.md` and the
  sample's description in `index.md`; a template that drops the site navigation is a further sign.
  Exempt pages take no part in the count.
- Separate sets: a sub-domain with its own navigation and authors, another language version, and
  checkout pages on their own template are each judged on their own, with the samples inside them.
  A set whose samples are all exempt is `not-present` for that set.
- Small sites: a set of three or four pages where the home page links every page and every page
  links back to the home page is the Intent's small-site case
  ([G185](https://www.w3.org/WAI/WCAG22/Techniques/general/G185) with
  [G125](https://www.w3.org/WAI/WCAG22/Techniques/general/G125)); check both directions in step 3
  before passing it.

## axe-core

No axe-core rule is tagged with this criterion in any rule set — not in WCAG 2.x A/AA, AAA,
experimental, deprecated or best-practice — so everything below is manual. The `axe-page.mjs`
results contribute nothing here, and no rule tagged with another criterion applies.

## Manual procedure

Consistency mode, once per report, after every `recon` unit. Inputs: `index.md`, `.notes/sample.md`,
the `structure`, `links` and `forms` probe outputs in `.notes/audit/recon/`, the full-page
screenshots, and one browser session. Outcome and findings go to `consistency.md`.

1. Sort the samples into sets and mark the exempt ones. For every sample record its set (the main
   site, unless it matches a separate-set case under "Applies when") and whether it is the result
   of or a step in a process, with the reason. A URL with a search query (`?q=`, `?s=`, `?zoek=`),
   a step number, `/checkout/`, `/bestellen/` or `/confirm` is a candidate; the description in
   `index.md` and the "Processes" section of `.notes/sample.md` decide. Samples that share one URI
   and differ only by an in-page view, a tab or a fragment are one web page: merge them into one
   row. A PDF or other non-embedded document in the sample set is a web page of the set and keeps
   its own row; a document loaded in an `iframe` does not. Done when a table
   `sample · url · set · exempt (reason)` is in the notes of `consistency.md`, and every set has a
   non-exempt sample or is `not-present`.

2. Inventory the candidate ways per set. Read `<id>-structure.json` (`landmarks` with `role`
   `navigation` or `search`), `<id>-links.json` (`links` whose `text`, `name` or `href` holds
   site map, sitemap, plattegrond, contents, inhoud, index, next, previous, volgende, vorige) and
   `<id>-forms.json` (`fields` with `type` `search` or `role` `searchbox`; `forms` whose `action`
   holds search or zoek) of every sample. Confirm in the browser, on the entry sample and on
   every other non-exempt sample of the set (`snapshot -s` scopes to its first match, so a footer
   drops out of a `"nav, footer"` snapshot; this eval reads them all):

   ```bash
   agent-browser open <sample url>
   agent-browser wait --load networkidle
   agent-browser eval --stdin <<'EOF'
   (() => {
     const q = s => [...document.querySelectorAll(s)];
     const t = a => (a.textContent || '') + ' ' + a.getAttribute('href');
     return {
       navs: q('nav, [role=navigation]').map(n => ({
         name: n.getAttribute('aria-label') || '', links: n.querySelectorAll('a[href]').length })),
       search: q('input[type=search], [role=searchbox], [role=search], '
         + 'form[action*="search" i], form[action*="zoek" i]').length,
       searchPageLinks: q('a[href]').filter(a => /search|zoek/i.test(t(a))).map(a => a.href),
       sitemapLinks: q('a[href]')
         .filter(a => /site\s?-?map|plattegrond/i.test(t(a))).map(a => a.href),
       tocLinks: q('a[href]')
         .filter(a => /contents|inhoud|index|a-z/i.test(t(a))).map(a => a.href),
       selects: q('select').filter(s => s.options.length > 1)
         .map(s => ({ name: s.name || s.id || '', options: s.options.length })),
       pageList: q('[role=doc-pagelist]').length
         + q('nav').filter(n => (n.getAttribute('epub:type') || '').includes('page-list')).length,
       breadcrumbs: q('[class*="breadcrumb" i], nav[aria-label*="breadcrumb" i], '
         + 'nav[aria-label*="kruimel" i]').length,
       repeated: [...new Set(q('header a[href], nav a[href], [role=navigation] a[href], '
         + 'footer a[href]').map(a => a.href))]
     };
   })()
   EOF
   ```

   When a navigation is collapsed, `click` the menu button and run the eval again: a menu that
   opens counts; one that cannot be opened is a 2.1.1 finding, not a missing way. Label each
   candidate with its sufficient technique:

   - navigation menu, or next/previous links between pages:
     [G125](https://www.w3.org/WAI/WCAG22/Techniques/general/G125)
   - a list of links to all the other pages, on every page:
     [G126](https://www.w3.org/WAI/WCAG22/Techniques/general/G126)
   - a home page that links every page:
     [G185](https://www.w3.org/WAI/WCAG22/Techniques/general/G185)
   - a site map page: [G63](https://www.w3.org/WAI/WCAG22/Techniques/general/G63)
   - a table of contents of the document or publication:
     [G64](https://www.w3.org/WAI/WCAG22/Techniques/general/G64)
   - a site search: [G161](https://www.w3.org/WAI/WCAG22/Techniques/general/G161)

   A mechanism outside that list that locates pages all the same is a candidate too: the
   Understanding's own example is a food site with "a search mechanism to search for recipes using
   a particular ingredient" and, "in addition, a list box that lists several categories of foods",
   so a `selects` entry whose options are sections of the site, an A–Z index or a tag listing
   counts. `pageList` above 0 marks a digital publication: test it in step 6. `breadcrumbs` is a
   position marker, not a way to locate a page (2.4.8); record it for the confirmation queue only.
   Done when each set has its candidate list, empty or not, and a `repeated` list per sample.

3. Test the navigation ways (G125, G126, G185). A sample is reached by navigation when another
   sample's `repeated` list holds its URL or the URL of a page that lists it (a category page).
   Get the page list of the set once, so that "all other pages" has a value:

   ```bash
   curl -sL <origin>/sitemap.xml | grep -o '<loc>[^<]*' | sed 's/<loc>//'
   ```

   G126 asks three things: every page carries a list of links to the other pages, those links lead
   to the corresponding pages, and the list holds a link for every page of the set. It is "only
   effective for small sets of web pages; if the list of links is longer than the rest of the
   content in the web page, it may make the web page more difficult for users to understand and
   use", and G126 notes that "Success Criterion 2.4.1 Bypass Blocks requires a technique for
   skipping this list of links" — a missing skip mechanism is a 2.4.1 finding, not a 2.4.5 one.
   G185 has two checks and both must hold: the home page contains links to all other pages in the
   website, and all other pages contain a link to the home page; a three or four page site whose
   pages do not link home does not meet G185 even when the home page lists them all. The header
   menu repeated in the footer is the same way, not a second one. Done when every non-exempt sample
   is marked reached or not reached by navigation, and G125, G126 and G185 are marked present or
   absent per set.

4. Test the search way (G161). G161's first check is that the page "contains a search form or a
   link to a search page", so a `searchPageLinks` entry counts: open it first. Take the level 1
   `headings` text of up to three non-exempt samples of the set from `<id>-structure.json` and
   search each from the entry sample:

   ```bash
   agent-browser fill "input[type=search], [role=searchbox]" "<two distinctive words of the h1>"
   agent-browser press Enter
   agent-browser wait --load networkidle
   agent-browser get url
   agent-browser snapshot -i -u -s "main"
   agent-browser screenshot .notes/audit/evidence/<sample>-search-results.png --full
   ```

   G161 expects check #1 to be true and either check #4 or check #5, not both: the user is taken to
   a page that contains the search term, or the user is taken to a page that contains a list of
   links to pages containing the search term. Both count as the sample being reached, so record
   which one happened: `get url` returning the sample's own URL is the direct landing (#4); a
   results list whose links include the sample is #5. A search that returns no hit and no landing
   for any of the queries is not a way for the set. A search that finds products and none of the
   information pages covers the product set only. A search behind a magnifier button counts once it
   opens (`click` it first); `back` between queries. What the index holds stays invisible: these
   queries are the proxy, so every query, the URL it produced and the result goes in the notes.
   Done when the search is marked works (for which samples), partial or absent.

5. Test the site map and the table of contents (G63, G64). Open every `sitemapLinks` address from
   step 2; when none was found, try the usual address:

   ```bash
   agent-browser open <origin>/sitemap
   agent-browser wait --load networkidle
   agent-browser snapshot -i -u
   agent-browser screenshot .notes/audit/evidence/<sample>-sitemap.png --full
   ```

   G63 has four checks: the site contains a site map; the links in the site map lead to the
   corresponding sections of the site; "for each link in the site map, check that the target page
   contains a link to the site map"; and every page of the site can be reached by following some
   set of links that start at the site map. An outline that shows links to each section or sub-site
   is "the simplest and most common kind of site map" and counts even when the top menu holds the
   same items. A page is not a valid site map "when any one of the following is true: it does not
   link to all the sections of a site, or it presents an organization that is different from the
   site's organization, or it contains links that are no longer valid" — test the third by opening
   two or three of its links. A `sitemap.xml` for crawlers and an address that answers 404 are not
   site maps. A sample is reached by the site map when it links the sample, or a section from which
   the sample is reachable. G64 covers the publication case and asks three things: a table of
   contents, or a link to one, exists in the document; "the values and order of the entries in the
   table of contents correspond to the names and order of the sections of the document"; and the
   entries link to the correct sections. A table of contents links sections of one document, which
   may be spread over several web pages; a site map links sections of the site. Done when site map
   and table of contents are marked works, partial or absent per set.

6. Test a digital publication's page-selection mechanism and record the PDF samples. When step 2
   reported `pageList` above 0, or the set is a publication with static page break locations,
   snapshot the page list and read its entries:

   ```bash
   agent-browser snapshot -i -u -s "[role=doc-pagelist]"
   agent-browser eval --stdin <<'EOF'
   (() => {
     const list = document.querySelector('[role=doc-pagelist]');
     const links = list ? [...list.querySelectorAll('a[href]')] : [];
     return {
       entries: links.length,
       targets: links.map(a => a.getAttribute('href')),
       breaksOnThisPage: document.querySelectorAll('[role=doc-pagebreak]').length
     };
   })()
   EOF
   ```

   [H99](https://www.w3.org/WAI/WCAG22/Techniques/html/H99) asks that a page-selection mechanism
   exists, that all the static page break locations in the publication are represented in it, and
   that its entries link to the correct location; a "go to page" input that repositions the reader
   is the other form it takes. H99 is advisory, not a sufficient technique: record a working page
   list as an extra way in the inventory and cite it in the recommendation for a publication, and
   base the pass on the sufficient techniques of steps 3 to 5. H99 also warns that "user agents may
   provide a specialized interface to the page list rather than render it directly, especially in
   ebook formats", so a publication sample with no `pageList` in the DOM is not evidence that the
   reader offers none. For a PDF sample, the bookmarks that
   [PDF2](https://www.w3.org/WAI/WCAG22/Techniques/pdf/PDF2) asks for live in the document's
   outline, which the browser's PDF viewer draws in native UI that `snapshot`, `eval` and the
   probes cannot read: do not test PDF2 in the browser. Judge the PDF like any other sample, by
   whether the set's ways of steps 3 to 5 reach its URL, and put "open <file> in a PDF reader and
   check the Bookmarks panel" in the confirmation queue as advice. Done when a publication's page
   list is marked works, partial, absent or unreadable, and every PDF sample is marked reached or
   not reached by the set's ways.

7. Count and decide per set: the distinct ways marked works, and for each non-exempt sample the
   ways that reach it. Two distinct ways are needed, not two instances of one way. Worked example
   from the Understanding: a salon site of five pages with "links on each web page to sequentially
   move forward or backward through the web pages" and, "in addition", "a list of links to reach
   each of the other web pages" on every page has two ways (G125 and G126), both reaching every
   sample — pass. A site with a header menu, the same menu repeated in the footer, no search, no
   site map and no index has one way — fail for every non-exempt sample of the set. Fewer than two
   for one sample is a finding naming that sample; fewer than two for the set is one finding naming
   every non-exempt sample. Evidence: the entry sample with the single mechanism highlighted, plus
   the step 4, 5 or 6 screenshot of the failing mechanism:

   ```bash
   agent-browser open <entry sample url>
   agent-browser highlight "nav, [role=navigation]"
   agent-browser screenshot .notes/audit/evidence/<sample>-multiple-ways.png --full
   ```

   Done when the 2.4.5 row in `consistency.md` has its outcome and samples, and every finding has
   its evidence.

## Deciding

- Fail (certainty ≥ 90): a non-exempt sample that no mechanism reaches: absent from every
  navigation and footer of the other samples, absent from the site map, and neither landed on nor
  listed by a search for its h1 — 95; a set whose complete inventory (header, footer, opened menus,
  site map addresses, search, category list boxes, A–Z index, page list) shows exactly one
  mechanism, on every sample — 90.
- Fail (70–89): two mechanisms exist and the second does not work for the set: the search returns
  no hit and no direct landing for any of the h1 queries — 80; the site map link answers 404, its
  page reaches only part of the sections, or its links are dead — 80; the site map presents an
  organisation the site does not have — 75; pages listed in the site map carry no link back to it,
  so G63's third check fails — 70; the "second way" is the header menu repeated in the footer —
  80; a three or four page site whose home page links every page but whose pages carry no link
  home, with nothing else — 75; a publication's table of contents whose entries do not match the
  names or the order of the sections, or link to the wrong sections — 75; a separate set
  (sub-domain, language version, checkout on its own template) with one mechanism of its own — 75.
- Needs confirmation (50–69): the second mechanism covers part of the set (a product search that
  skips the information pages; a site map that reaches some sections only) — 60; ask which pages
  the search and the site map are meant to cover. The only candidate second way is a breadcrumb
  trail or "related pages" links that reach a subset — 60; ask whether a site map or search is
  planned. A publication whose chapter pages carry a table of contents and nothing else, where the
  reading system may add a page list or a search the browser sample cannot show — 60; ask which
  reading system is in scope. A sample that may be a step in a process (an account dashboard, a
  filtered listing) — 55; ask what produces it. An area that may be a set of its own (a sub-domain,
  a section behind a login) — 55; ask who authors it.
- Pass: every non-exempt sample of every set is reached by at least two distinct mechanisms that
  worked when tried: a navigation that leads to the page or its section (G125), a list of all
  pages (G126), a home page that links every page while every page links home (G185), a site map
  that lists it (G63), a table of contents (G64), a search that lands on it or lists it (G161), or
  another mechanism that locates pages as well — a category list box, an A–Z index or a tag listing
  in the Understanding's own example; the six are sufficient techniques, not the only ways to meet
  this criterion.
- Not present: the scope holds one web page, or every sample is exempt under the process exception.
- False positives to avoid: search results, confirmations and checkout or wizard steps (exempt);
  checkout pages on another template (outside the product set); a three or four page site whose
  home page links every page and every page links home (the Intent's small-site case); a site map
  that lists sections rather than every page (G63's ordinary kind); a navigation behind a menu
  button or a search behind a magnifier icon (available once opened); a navigation that reaches a
  category page listing the sample (reached); a search that jumps straight to the page instead of
  showing a results list (G161 check #4); a category list box or an A–Z index (a way, not
  decoration); a missing `sitemap.xml` (a crawler file); a document inside an `iframe` (embedded,
  not a web page of the set); the views of a one-page application at a single URI (one web page); a
  publication whose page list the reading system renders rather than the document (H99's note); a
  PDF whose bookmarks cannot be read in the browser (PDF2 is advisory; judge the PDF by whether the
  set's ways reach it); a long list of links without a skip mechanism (2.4.1); a navigation whose
  order differs between pages (3.2.3); an unlabelled search field (3.3.2 or 4.1.2; it still counts
  as a way).

## Reporting

- File under: 2.4.5, one issue per set naming every sample of the set (the defect is the site's
  navigation design, not one page). A menu that cannot be opened by keyboard is 2.1.1; a
  navigation whose order differs between pages is 3.2.3; a search field without a label is 3.3.2
  or 4.1.2; a missing skip link over a long list of links is 2.4.1; breadcrumbs and "you are here"
  markers are 2.4.8. A PDF's in-document navigation goes to the confirmation queue as advice, not
  to an issue.
- Title patterns: "Only one way to find pages", "Site search does not find pages", "Site map is
  missing or empty", "Page cannot be reached from the navigation or the search", "Second way to
  find pages covers only part of the site"
- Severity: High when a page in scope cannot be reached by any mechanism (only by typing its
  address) or the single mechanism needs a mouse; Medium when the set has one working way (the
  whole product is affected, every page stays reachable); Low when the second way misses a few
  pages the first way reaches.
- Type: Technical when a mechanism exists and does not work (the search indexes nothing, the site
  map link answers 404 or its page is empty, the table of contents links to the wrong sections);
  Content when the site map or table of contents is out of date — it lists sections the site no
  longer has, omits sections, or shows an organisation the site does not have; Design when the site
  offers one way and a second mechanism has to be added to the layout (a site map page in the
  footer, a search in the header).
- Evidence: the full-page screenshot of the entry sample with the only mechanism highlighted; the
  search results for a sample's h1 with no hit; the site map page or its 404; for a publication,
  the page list or table of contents that misses entries. No GIF: nothing moves.
- Recommendation: add a second mechanism and link it from a component every page repeats: a site
  map page ([G63](https://www.w3.org/WAI/WCAG22/Techniques/general/G63)) in the footer, or a site
  search that indexes every page ([G161](https://www.w3.org/WAI/WCAG22/Techniques/general/G161)).
  On a small site link every page from the home page and every page back to it
  ([G185](https://www.w3.org/WAI/WCAG22/Techniques/general/G185)), list all pages in the footer
  ([G126](https://www.w3.org/WAI/WCAG22/Techniques/general/G126)) or add next/previous links
  ([G125](https://www.w3.org/WAI/WCAG22/Techniques/general/G125)); for a publication add a table
  of contents ([G64](https://www.w3.org/WAI/WCAG22/Techniques/general/G64)). Minimal site map at
  `/sitemap`: `<nav aria-label="Site map"><ul><li><a href="/about">About</a></li> ... </ul></nav>`,
  with `<a href="/sitemap">Site map</a>` in the footer of every page. As advice for a publication
  with static page break locations, add a page list
  ([H99](https://www.w3.org/WAI/WCAG22/Techniques/html/H99)):
  `<nav role="doc-pagelist" aria-labelledby="pglist"><h2 id="pglist">Page List</h2><ol>` with one
  `<li><a href="chapter01.xhtml#page001">1</a></li>` per break, each target marked
  `<span id="page001" role="doc-pagebreak" aria-label="page 1">`; for a PDF in the set, bookmarks
  in the document outline ([PDF2](https://www.w3.org/WAI/WCAG22/Techniques/pdf/PDF2)).
- Related: 3.2.3 Consistent Navigation (the repeated mechanism keeps its order; judge that there);
  2.4.1 Bypass Blocks (a skip link is not a way to locate a page, and a list of links to every page
  needs a skip mechanism); 2.4.8 Location (AAA: breadcrumb and "you are here" marker); 2.4.4 (link
  texts of navigation and site map); 1.3.1 (the navigation as a list inside a landmark).
