# 1.4.12 Text Spacing

Level AA · WCAG 2.1+ · Guideline 1.4 Distinguishable · Group: `visual`

Sources: [Understanding](https://www.w3.org/WAI/WCAG22/Understanding/text-spacing.html)
· [Spec](https://www.w3.org/TR/WCAG22/#text-spacing)
· [Techniques](https://www.w3.org/WAI/WCAG22/quickref/#text-spacing)
· [Plain English](https://aaardvarkaccessibility.com/wcag-plain-english/1-4-12-text-spacing/)
· ACT: none mapped to this criterion; the axe rule below implements 24afc2, 78fd32 and 9e45ec.

## Requirement

> In content implemented using markup languages that support the following text style properties, no
> loss of content or functionality occurs by setting all of the following and by changing no other
> style property:
>
> - Line height (line spacing) to at least 1.5 times the font size;
> - Spacing following paragraphs to at least 2 times the font size;
> - Letter spacing (tracking) to at least 0.12 times the font size;
> - Word spacing to at least 0.16 times the font size.
>
> Exception: Human languages and scripts that do not make use of one or more of these text style
> properties in written text can conform using only the properties that exist for that combination
> of language and script.
>
> Note 1: Content is not required to use these text spacing values. The requirement is to ensure
> that when a user overrides the authored text spacing, content or functionality is not lost.
>
> Note 2: Writing systems for some languages use different text spacing settings, such as paragraph
> start indent. Authors are encouraged to follow locally available guidance for improving
> readability and legibility of text in their writing system.

Terms (WCAG 2.2 glossary): **text**: "sequence of characters that can be programmatically
determined, where the sequence is expressing something in human language" — only human-language
text is in scope, so a rendering of glyphs that is not markup text is out. **human language**:
"language that is spoken, written or signed (through visual or tactile means) to communicate with
humans"; the exception is granted per language _and_ script, so read `lang` together with the script
the page is written in. **style properties**: "property whose value determines the presentation
(e.g. font, color, size, location, padding [...]) of content elements as they are rendered (e.g.
onscreen [...]) by user agents", with several origins, of which two decide this criterion — "Author
styles: Style property values that are set by the author as part of the content (e.g. in-line
styles, author style sheets)" and "User styles: Style property values that are set by the user (e.g.
via user agent interface settings, user style sheets)". The test is whether user styles for these
four properties can win over the author's without breaking the page.

## In plain terms

Readers with low vision "require increased space between lines, words, and letters" to read at all,
and readers with dyslexia widen the same spacing "to increase reading speed"; both do it with a user
stylesheet, a bookmarklet or an extension, not with a control the page offers. The author does not
have to ship these values and does not have to provide a way to set them — the author has to survive
them: with the four metrics applied, no text is cut off, covered or unreachable, and every control
still works. W3C adds that content which adapts to these four also "significantly increases the
likelihood other style preferences can be set by the user", such as the wider font family the same
reader picks next.

## Applies when

- Present: the sample renders human-language text through HTML and CSS (paragraphs, headings,
  navigation, labels, table cells, buttons, dialog and menu text). W3C: "If the markup-based
  technologies being used are capable of overriding text to the Success Criterion's metrics, then
  this SC is applicable" — HTML with CSS always is. `text-spacing.js` reports the count it scanned.
- Not present: the only visible text is an image of text, `canvas` ("For this SC, canvas
  implementations of text are considered to be images of text"), "Video captions embedded directly
  into the video frames and not provided as an associated caption file", or a PDF ("Currently, this
  SC does not apply to PDF, as the portable document format is not implemented using markup");
  `text-spacing.js` scanned zero text elements. Text inside a plugin document counts only where the
  plugin has "a built-in ability to modify styles to the specified metrics".
- Exception, language and script: a language or script that does not use one or more of the four
  properties (W3C example: Japanese, which uses no spacing following paragraphs and no spaces
  between words) conforms "using only the properties that exist for that combination of language and
  script". The other properties still apply — "authors are only required to ensure relevant
  properties do not break the layout". Recognise the language from `lang` on `html` (step 1); for
  any language other than Japanese record the unused property as a needs-confirmation question
  (step 2), because W3C tested "roughly 480 different languages and scripts" at these metrics and
  "No adverse effects occurred".
- Exception, truncation: text truncated only when spaced still conforms when "a mechanism is
  provided to reveal the truncated text on the page (for instance, the text appears on focus or on
  activation)", or when, "where the ellipsis is part of a section of content which includes a link,
  the truncated text is revealed on the linked page" (step 7).
- Exception, the user's own tooling: "It is not a failure of the content if a user agent or platform
  does not provide a way for users to do this", and a bookmarklet or extension that fails to set the
  properties is not a failure "provided that the content is not actively and purposely preventing
  the properties from being added" (step 3).

## axe-core

| Rule                   | Decides                                | Result → outcome       |
| ---------------------- | -------------------------------------- | ---------------------- |
| `avoid-inline-spacing` | inline `!important` spacing too narrow | violation → fail (100) |

Runs by default (WCAG 2.1 Level A & AA rule set); never incomplete. Settles the three ACT rules it
implements, each scoped to "any HTML element with one or more visible text node children" for which
the property's "specified value is declared in a style attribute" and "the computed value is
important": letter spacing under 0.12 times the computed font size (24afc2), word spacing under 0.16
times it (9e45ec), and a line height whose _used_ value is under 1.5 times it (78fd32). 78fd32
narrows further to elements whose text "includes a soft wrap break"; an `avoid-inline-spacing`
violation is a fail at 100 regardless, it is an axe `failure` rule.

Leaves open everything the metrics cause once applied: clipping by a fixed height, `overflow:
hidden` or a line clamp; text overlapping text or controls; text spilling past its box over the
block below; cut-off labels; controls that stop responding (all
[F104](https://www.w3.org/WAI/WCAG22/Techniques/failures/F104)); the paragraph-spacing metric, which
no rule covers; spacing that comes from a stylesheet or a script instead of a `style` attribute
(step 3); truncation (step 7); and every layout and state other than the one axe ran in.

## Manual procedure

Run steps 2 to 7 at 1280 by 900 and at 100 % zoom first
([C36](https://www.w3.org/WAI/WCAG22/Techniques/css/C36) tests at 100 %), then in the layouts this
group visits (`set viewport 640 900`, `set viewport 320 900`; C36: "Where a page has multiple
layouts (e.g. in a responsive design) text spacing should be tested in each layout"), and in every
state that carries text of its own: cookie dialog, open menu, modal, expanded accordion, selected
tab panel, tooltip, autocomplete list, validation errors, off-canvas navigation. A `reload` removes
the injected style: repeat step 2 after each one; end at 1280 by 900 with a `reload`.

1. Record the baseline, the page language and the writing direction.

   ```bash
   agent-browser set viewport 1280 900
   agent-browser reload
   agent-browser wait --load networkidle
   agent-browser screenshot .notes/audit/evidence/<sample>--1.4.12-base.png --full
   agent-browser get attr html lang
   agent-browser get styles body
   ```

   In `get styles body`, `writing-mode: vertical-rl` or `vertical-lr` means text grows sideways, not
   downwards, so the boxes at risk are the narrow ones: C36 requires paragraphs "to increase
   vertically for languages or scripts such as English which are read horizontally or to increase
   horizontally for languages or scripts which are read vertically". Done when the baseline
   screenshot exists and `lang` and the writing mode are written in the findings file.

2. Apply the four metrics and photograph the result.

   ```bash
   agent-browser eval --stdin < <skill-dir>/scripts/probes/text-spacing.js
   agent-browser screenshot .notes/audit/evidence/<sample>--1.4.12-spaced.png --full
   ```

   Read `applied: true` and `counts` (zero text elements scanned: `not-present`); keep the `clipped`
   list, each entry `{ selector, textSample, kind }` with `kind` one of `clipped`, `overlapping` or
   `overflowing` — for example `{ selector: ".card__title", textSample: "A cog in the wheel", kind:
"clipped" }`, judged in step 4. The paragraph metric (2 em after every paragraph) is the one that
   lengthens the page, so take the screenshot with `--full` and read its bottom as well.

   For an excepted language undo the unused property or properties (paragraph spacing and/or word
   spacing) with a later rule that wins over the probe's, then rerun the probe and judge that run
   only.

   ```bash
   agent-browser eval --stdin <<'EOF'
   (() => document.head.insertAdjacentHTML('beforeend',
     '<style>* { word-spacing: normal !important } p { margin-bottom: 0 !important }</style>'))()
   EOF
   ```

   Done when the spaced screenshot exists and the probe output is in the findings file.

3. Verify the metrics took effect: a stylesheet `!important`, a script that reapplies spacing or a
   content security policy that drops the injected style leaves elements below the metrics. For an
   excepted language drop the check for each property that language does not use.

   ```bash
   agent-browser eval --stdin <<'EOF'
   (() => { const below = [], num = (v) => (v === 'normal' ? 0 : parseFloat(v));
   const want = { 'line-height': '1.5', 'letter-spacing': '0.12em', 'word-spacing': '0.16em' };
   const path = (el) => (el.id ? '#' + el.id : [el.localName, ...el.classList].join('.'));
   for (const el of document.querySelectorAll('body *')) {
     const s = getComputedStyle(el), fs = parseFloat(s.fontSize), short = [];
     if (!el.getClientRects().length || s.visibility === 'hidden' || el.closest('svg, script')
       || ![...el.childNodes].some((n) => n.nodeType === 3 && n.data.trim())) continue;
     for (const [p, v] of Object.entries(want))
       if (num(s.getPropertyValue(p)) < parseFloat(v) * fs - 0.5) short.push(p);
     if (short.length) below.push({ selector: path(el), short, style: el.getAttribute('style') });
     for (const p of short) el.style.setProperty(p, want[p], 'important');
   }
   return below; })()
   EOF
   ```

   Each entry stayed under the metrics and is now forced inline: a `style` with `!important` on one
   of the three is the `avoid-inline-spacing` fail; a null `style` means a stylesheet or a script.
   Rerun step 2 and this script: `[]` now, else `cannot-tell`. A page that keeps stripping the
   declarations run after run is the "actively and purposely preventing the properties from being
   added" case of the Understanding — record it with the evidence of what removed them. Done when
   the list is recorded.

4. Verify each `clipped` entry against the text it should show (F104).

   ```bash
   agent-browser scrollintoview "<selector>"
   agent-browser highlight "<selector>"
   agent-browser screenshot .notes/audit/evidence/<sample>--1.4.12-<n>.png
   agent-browser get text "<selector>"
   agent-browser get styles "<selector>"
   ```

   Compare the screenshot against the baseline region and against `get text`, which still returns
   the full string. The three shapes W3C illustrates: the bottom of a line sliced off so the words
   are unreadable while the sentence is complete in `get text` (Understanding Figure 1, vertical
   cut); the end of a line gone, "A cog in the wheel" rendering as "A cog in the whe" (Figure 2,
   horizontal cut); one text drawn over another so either is unreadable (Figure 3, overlap). Clear
   an entry that scrolls (`overflow: auto`/`scroll` in `get styles`) or is hidden by design.
   Done when each entry is judged.

5. List what the probe cannot see: it inspects the element that holds the text node, so a
   fixed-height `overflow: hidden` box around a `<p>`, a box whose text spills past its border, an
   overlay that now covers text, and letters spaced with space characters never reach its `clipped`
   list. Write the script once and run it on both states, so only differences from the baseline are
   judged.

   ```bash
   cat > .notes/audit/1.4.12-containers.js <<'EOF'
   (() => { const out = [], abs = [], own = [];
   const sel = (e) => (e.id ? '#' + e.id : [e.localName, ...e.classList].join('.'));
   const owns = (e) => [...e.childNodes].some((n) => n.nodeType === 3 && n.data.trim());
   for (const el of document.querySelectorAll('body *')) {
     const s = getComputedStyle(el);
     if (!el.getClientRects().length || s.visibility === 'hidden') continue;
     const ov = s.overflow + ' ' + s.overflowY, grew = el.scrollHeight - el.clientHeight;
     if (grew > 2 && el.textContent.trim() && !/auto|scroll/.test(ov))
       out.push((/hidden|clip/.test(ov) ? 'clipped-container ' : 'spills-past-box ') + sel(el));
     if (!owns(el)) continue;
     if (/(?:\p{L}\s){3,}\p{L}/u.test(el.textContent))
       out.push('letters-spaced-with-spaces ' + sel(el));
     (/absolute|fixed|sticky/.test(s.position) ? abs : own).push([el, el.getBoundingClientRect()]);
   }
   for (const [a, r] of abs) for (const [b, q] of own)
     if (!a.contains(b) && !b.contains(a) && r.left < q.right && q.left < r.right
       && r.top < q.bottom && q.top < r.bottom)
       out.push('overlay-over-text ' + sel(a) + ' over ' + sel(b));
   return out.sort(); })()
   EOF
   agent-browser reload
   agent-browser wait --load networkidle
   agent-browser eval --stdin < .notes/audit/1.4.12-containers.js > .notes/audit/1412-base.json
   agent-browser eval --stdin < <skill-dir>/scripts/probes/text-spacing.js
   agent-browser eval --stdin < .notes/audit/1.4.12-containers.js > .notes/audit/1412-spaced.json
   diff <(tr ',' '\n' < .notes/audit/1412-base.json) <(tr ',' '\n' < .notes/audit/1412-spaced.json)
   ```

   Every line the `diff` adds is a candidate; judge it as a `clipped` entry in step 4.
   `clipped-container` and `spills-past-box` are F104's "Setting the overflow property of the
   enclosing element to hidden" and "Creating borders that are not large enough for the content when
   using the new font spacing"; `overlay-over-text` is its "Using absolutely positioned content",
   plus the sticky header, footer or cookie bar that now sits over text.
   `letters-spaced-with-spaces` marks a word written with blank characters between its letters
   ("M u s e u m"): the word-spacing metric widens each of those gaps, so check that word's box
   first. Done when every added line is recorded as harmless or as a candidate with a screenshot.

6. Operate the page while it is spaced, one state at a time: `click` the menu button, open the
   cookie dialog, expand an accordion, switch a tab, hover a tooltip, submit with a required field
   left empty to reach the error state (real values are the `forms` pass's job; `back` and rerun
   step 2 when the page navigates). Screenshot each state, rerun the probe and rerun step 5's
   script in it. A control that no longer opens, a label that has wrapped out of its button, a
   menu pushed onto a second row behind the next block and a dialog whose buttons have left the
   viewport are functionality losses, not layout taste. Done when every state that carries text has
   a spaced screenshot and a verdict.

7. Judge truncation (Understanding: "Use of ellipses"), which W3C expects "where text containers
   cannot expand due to design constraints (such as a maximum width for the left navigation or table
   column headers)" — look there first. For a `clipped` entry whose styles show `text-overflow:
ellipsis` or a line clamp, an ellipsis already in the baseline screenshot is not this criterion;
   for an ellipsis that appears only when spaced, run `hover "<selector>"`, `focus "<selector>"`,
   `get attr "<selector>" title` and `click "<selector>"` and look for the full text in a tooltip or
   on the linked page (`get url`, compare, `back`, step 2 again). Done when each truncation is
   classified as revealed on the page, revealed on the linked page, or not revealed.

## Deciding

- Fail (certainty ≥ 90): an `avoid-inline-spacing` violation (100); a `clipped` or container entry
  whose spaced screenshot shows characters or lines missing at the box edge that the `get text`
  output and the baseline contain, with no reveal mechanism (F104) (92); a line whose lower half is
  sliced off by its box so the words cannot be read although `get text` returns them in full
  (Figure 1) (90); an `overlapping` entry whose screenshot shows one text drawn over another so that
  either is unreadable (F104, Figure 3) (90).
- Fail (70–89): a control that stops responding, or whose label is cut or covered, while spaced
  though it works at baseline (85); an `overflowing` or `spills-past-box` entry covering the block
  below (F104) (82); an `overlay-over-text` line that the baseline run does not contain (82); an
  ellipsis only when spaced with no reveal on hover, focus, activation or the linked page — W3C:
  "Where text is not truncated but it is when text is spaced, if there is no mechanism to show the
  truncated text, it fails this success criterion" (80); text behind a sticky header, footer or
  cookie bar only when spaced (78).
- Needs confirmation (50–69): truncated text reachable only outside the sample set (60): ask where
  the full text lives; clipping or overlap inside a third-party iframe (55): ask whether the embed
  is in scope; spacing reset by a script after step 3 (55): ask whether the reset is intended; a
  non-Japanese language that may leave a property unused (55): ask which properties its script uses;
  a state the evaluator could not reach while spaced (50): ask for credentials or the path to it.
- Pass: `applied: true` with text elements scanned in every layout and state; every `clipped`,
  `overlapping`, `overflowing`, container and overlay entry cleared by its screenshot; in W3C's
  words, "Text fits within the bounds of its containing box without being cut off" and "without
  overlapping other boxes"; only taller and wider blocks against the baseline; controls respond;
  truncations meet the exception; no axe violation.
- Not present: the only visible text is in images, canvas, burned-in captions or a plugin document.
- False positives to avoid: authored spacing that is merely tight is not a defect here — "Content is
  not required to use these text spacing values", and the requirement is only that a user override
  costs nothing (tight authored line spacing is 1.4.8 at AAA). Breakage that appears only above the
  four values is the user's own affair: "If large changes in spacing reduce readability, or cause
  loss of content or functionality, the user can adjust or return to spacing within the bounds of
  the SC" — re-check with exactly the metric values before recording a fail. A browser or platform
  that offers no way to set them is not the content's failure. Word spacing having no visible effect
  in a language written without spaces between words is expected, not a failure to apply. Text in
  `overflow: auto` or `scroll` containers scrolls and is not clipped; a collapsed accordion, an
  inactive carousel slide and a visually hidden 1 px box hide text by design; a box whose text hangs
  past its border while the next block moved down loses nothing; clipping identical at baseline is
  1.4.4 or 1.4.10.

## Reporting

- File under: 1.4.12 for content or functionality lost only when the metrics are applied, and for an
  `avoid-inline-spacing` violation; clipping already present at baseline or at 640 is 1.4.4, at 320
  it is 1.4.10; hover or focus content that clips only when spaced stays under 1.4.12. One issue per
  container pattern (every card with the same fixed height), naming the samples it repeats on.
- Title patterns: "Card text is cut off when text spacing is increased", "Menu labels overlap when
  letter spacing is widened", "Table heading is truncated with no way to read the full text",
  "Sticky header covers the first line when line height is increased", "Inline !important spacing
  blocks user text-spacing overrides"
- Severity: High when a heading, primary content, a form field or a task control becomes unreadable
  or inoperable in the spaced state, or when a control stops responding; Medium when secondary
  content clips or overlaps, or the same component breaks on every sample; Low when a descender or
  an accent is trimmed without making the word unreadable, or a hover or focus reveals all of the
  truncated text but only with a pointer.
- Type: Technical when the fix is a CSS change (remove a fixed `height` or `overflow: hidden`, drop
  `!important`, switch to `min-height`); Design when the layout allots no room for text to grow (a
  fixed-width bar that needs a new arrangement) and a designer decides where it goes; Content when
  the fix is editorial — a label shortened to fit its box, or blank characters removed from between
  the letters of a word.
- Evidence: the spaced screenshot with `highlight "<selector>"` on the clipped container, placed
  beside the same region of the baseline screenshot so the reader sees the words that disappeared;
  an element screenshot when one card or button is the subject; a `--full` page screenshot when the
  defect is the whole layout pushed apart; a GIF when a control stops opening; the `style` attribute
  quoted for the axe finding.
- Recommendation: let text containers grow — remove fixed heights and `overflow: hidden` and size
  boxes in `em` with `min-height` ([C36](https://www.w3.org/WAI/WCAG22/Techniques/css/C36),
  [C28](https://www.w3.org/WAI/WCAG22/Techniques/css/C28)); for text that must not wrap, size the
  container above the text's default width or let it expand with the text
  ([C35](https://www.w3.org/WAI/WCAG22/Techniques/css/C35), which puts a safe fixed width at 20 %
  over the default maximum); set authored spacing in the stylesheet without `!important`
  ([C21](https://www.w3.org/WAI/WCAG22/Techniques/css/C21)); and space the letters of a word with
  `letter-spacing` instead of blank characters
  ([C8](https://www.w3.org/WAI/WCAG22/Techniques/css/C8)). Note that the four values are a floor:
  "Authors are encouraged to allow spacing to surpass the values specified, not see them as a
  ceiling."

  ```css
  .card {
    height: 160px;
    overflow: hidden;
  } /* clips once spaced (F104) */
  .card {
    min-height: 10em;
  } /* 160px at a 16px font, and free to grow */
  nav li {
    width: 10em;
  } /* C35: links under 8em, room to expand */
  nav li {
    display: inline-block;
  } /* C35: the box follows the text */
  ```

  ```html
  <p style="line-height:1.2 !important">…</p>
  <!-- avoid-inline-spacing violation -->
  <p class="lede">…</p>
  <!-- .lede { line-height: 1.2 } in the stylesheet -->
  ```

- Related: 1.4.4 and 1.4.10 when the same container also clips at 200 % or at 320 px, filed where it
  breaks without spacing; 1.4.13 when the hover or focus content cannot be dismissed, hovered or
  does not persist (separate defect); 1.4.5 for text in images; 1.4.8 at AAA for authored line and
  paragraph spacing that is too tight, which this criterion never asks for.
