## Requirement

> Information, structure, and relationships conveyed through presentation can be programmatically
> determined or are available in text.

Terms (WCAG 2.2 glossary), verbatim; these decide the verdict:

- **structure**: "- The way the parts of a web page are organized in relation to each other; and" /
  "- The way a collection of web pages is organized". Both halves count: the order and nesting
  inside this page, and this page's place in the set — breadcrumbs, the current menu item, the step
  the user is on.
- **relationships**: "meaningful associations between distinct pieces of content" — a label and its
  field, a cell and its header, a title and the section under it, an item and its list, a hint and
  the field it explains.
- **presentation**: "rendering of the content in a form to be perceived by users", so a
  relationship carried only by position, spacing, indentation, size, weight, colour or a sound is
  in scope; nothing has to be visible for it to count.
- **programmatically determinable**: "determined by software from author-supplied data provided in
  a way that different user agents, including assistive technologies, can extract and present this
  information to users in different modalities". Example 1: "Determined in a markup language from
  elements and attributes that are accessed directly by commonly available assistive technology."
  Example 2: "Determined from technology-specific data structures in a non-markup language and
  exposed to assistive technology via an accessibility API that is supported by commonly available
  assistive technology." The clause that decides is "extract and present this information to users
  in different modalities": a `class="heading"`, a CSS rule or a `data-` attribute is never enough,
  because nothing presents it in another modality. The accessibility tree (`snapshot`) is the
  evidence that the data was extracted and presented.

## In plain terms

W3C's intent is that "information and relationships that are implied by visual or auditory
formatting are preserved when the presentation format changes", for example "when the content is
read by a screen reader or when a user style sheet is substituted". So whatever the eye or the ear
reads from formatting — a title, a list, a table with headers, a label beside its field, radio
buttons under one question, an emphasised word, the current menu item, a chime that starts a new
section — has to be in the markup (`h1`–`h6`, `ul`/`ol`/`dl`, `table` with `th`, `label`,
`fieldset`, `optgroup`, `em`, `aria-current`, landmarks) or said in the text. Where the technology
cannot express a relationship, a text description near it does the job ("all required fields are
marked with an asterisk (*)"), and that is conforming, although "when technologies support
programmatic relationships, it is strongly encouraged that information and relationships be
programmatically determined rather than described in text". It matters for screen reader and
braille users, who get the tree and not the layout, and for anyone who replaces the author's style
sheet. Colour on its own is 1.4.1's.

## Applies when

- Present: the sample renders content with visual or auditory structure — lines styled as titles,
  bulleted or numbered items, a grid of rows and columns, fields with labels or grouped under one
  question, `select` options in visual groups, a highlighted current item, set-apart words, a font
  icon standing for a word, rows or cards grouped by background colour, blocks of related links,
  distinct page regions, a sound that marks a section or an outcome. Detect it from the `structure`
  and `forms` probe output written by `recon` (`headings`, `lists`, `tables`, `landmarks`,
  `liveRegions`, `visuallyStyledHeadings`, `fields`) together with the step 1 screenshot.
- Not present: no text, or one unformatted run with no field, list, table, title or region, in
  every state.
- Exceptions: none in the criterion text. Four scope limits decide outcomes:
  1. Colour, verbatim from the Understanding note: "It is not required that color values be
     programmatically determined. The information conveyed by color cannot be adequately presented
     simply by exposing the value. Therefore, Success Criterion 1.4.1 Use of Color addresses the
     specific case of color, rather than Success Criterion 1.3.1 Info and Relationships." Colour
     marking one item (this field is required, this row is an error) is 1.4.1's; colour grouping
     several items is structure and stays here, because the intent names "a different background
     color ... used to indicate that several items are related to each other".
  2. Available in text, verbatim: "Some technologies do not provide a means to programmatically
     determine some types of information and relationships. In that case then there should be a
     text description of the information and relationships. For instance, 'all required fields are
     marked with an asterisk (*)'. The text description should be near the information it is
     describing (when the page is linearized), such as in the parent element or in the adjacent
     element." Near means near after linearization: a legend at the top of the same `form` counts,
     a footnote at the foot of the page does not.
  3. Judgement, verbatim: "There may also be cases where it may be a judgment call as to whether
     the relationships should be programmatically determined or be presented in text. However, when
     technologies support programmatic relationships, it is strongly encouraged that information
     and relationships be programmatically determined rather than described in text." Strongly
     encouraged is not required: a correct text description passes even where markup was possible.
  4. Plain text (Situation B): a resource served as plain text has no markup to carry structure, so
     it meets the criterion through conventions —
     [T1](https://www.w3.org/WAI/WCAG22/Techniques/text/T1) for paragraphs,
     [T2](https://www.w3.org/WAI/WCAG22/Techniques/text/T2) for lists,
     [T3](https://www.w3.org/WAI/WCAG22/Techniques/text/T3) for headings. W3C's example: "A simple
     text document is formatted with double blank lines before titles, asterisks to indicate list
     items and other standard formatting conventions so that its structure can be programmatically
     determined." Step 9 judges these.

## axe-core

| Rule                     | Decides                                       | Violation      | Incomplete / off |
| ------------------------ | --------------------------------------------- | -------------- | ---------------- |
| `aria-hidden-body`       | `aria-hidden="true"` on `body`                | fail (100)     | —                |
| `aria-required-children` | required child roles present                  | fail (100)     | step 8           |
| `aria-required-parent`   | required context role present                 | fail (100)     | —                |
| `list`                   | `ul`/`ol` contain only list items             | fail (100)     | —                |
| `listitem`               | `li` sits inside a `ul`/`ol`                  | fail (100)     | —                |
| `definition-list`        | `dl` holds ordered `dt`/`dd` groups           | fail (100)     | —                |
| `dlitem`                 | `dt`/`dd` sit inside a `dl`                   | fail (100)     | —                |
| `td-headers-attr`        | `headers` tokens are other `th` of that table | fail (100)     | step 4           |
| `th-has-data-cells`      | each header cell has data cells               | fail (100)     | step 4           |
| `p-as-heading`           | `p` styled bold/italic/larger as a heading    | off by default | step 2           |
| `table-fake-caption`     | the table's title sits outside `caption`      | off by default | step 4           |
| `td-has-header`          | cells of a table larger than 3×3 have headers | off by default | step 4           |

Only `aria-required-children`, `td-headers-attr` and `th-has-data-cells` carry both `failure` and
`needs review`, so only those three can come back as `incomplete`; the other six default rules only
ever violate, and the last three are experimental, never run, and are decided by hand in the step
named.

Impact: `aria-hidden-body`, `aria-required-children`, `aria-required-parent` and `td-has-header`
critical, the rest serious — use impact for severity, never for the verdict.

Settles, within the ACT scopes it implements: `headers`/`id` chains on cells of a visible table in
the tree with a role of `table`, `grid` or `treegrid`
([a25f45](https://www.w3.org/WAI/standards-guidelines/act/rules/a25f45/)); visible header cells in
the tree inside a semantic table or grid that have no data cells
([d0f69e](https://www.w3.org/WAI/standards-guidelines/act/rules/d0f69e/)); explicit roles with a
required context role, except where the implicit role already equals the explicit one
([ff89c9](https://www.w3.org/WAI/standards-guidelines/act/rules/ff89c9/)); roles with required
owned elements, except under an `aria-busy="true"` ancestor
([bc4a75](https://www.w3.org/WAI/standards-guidelines/act/rules/bc4a75/)); well-formed `ul`, `ol`
and `dl`; `aria-hidden` on `body`.

Leaves open: styled text used as titles, heading markup on non-titles, fake lists, groups of links
with no list or `nav`, tables with no `th` or the wrong ones, white-space and `pre` tables,
`optgroup`-less option groups, label and group relationships, formatting and colour that carry
information, font icons, the current item, regions and their names, `role="presentation"` and
`aria-hidden` over semantic content, and plain-text resources. ARIA validity
([674b10](https://www.w3.org/WAI/standards-guidelines/act/rules/674b10/),
[5f99a7](https://www.w3.org/WAI/standards-guidelines/act/rules/5f99a7/),
[6a7281](https://www.w3.org/WAI/standards-guidelines/act/rules/6a7281/),
[5c01ea](https://www.w3.org/WAI/standards-guidelines/act/rules/5c01ea/),
[kb1m8s](https://www.w3.org/WAI/standards-guidelines/act/rules/kb1m8s/),
[4e8ab6](https://www.w3.org/WAI/standards-guidelines/act/rules/4e8ab6/)) is the 4.1.2 file's in
this same pass; count it here only when the broken ARIA removes a structural relationship that
steps 2 to 8 rely on.

## Manual procedure

`snapshot` is what a screen reader gets, the screenshot what the eye gets: fail where they differ.

1. Inventory the visible structure, default state first:

   ```bash
   agent-browser screenshot .notes/audit/evidence/<sample>--1.3.1-visual.png --full
   agent-browser eval --stdin < <skill-dir>/scripts/probes/structure.js
   agent-browser eval --stdin < <skill-dir>/scripts/probes/forms.js
   agent-browser snapshot
   ```

   `recon` has already written both probes to `.notes/audit/recon/<sample>-structure.json` and
   `<sample>-forms.json`; re-run them for every state of step 10. From the screenshot write one
   line per visual structure, in reading order, with the claim the eye makes and the step that
   settles it:

   ```
   title "Our products"             → headings            step 2
   bulleted benefits, 4 items       → lists / fakeLists   step 3
   price table 5 rows, header row   → tables              step 4
   "E-mail" beside a box            → fields              step 5
   "* required" legend above form   → fields              step 5
   "Sale" in red bold               → formatting          step 6
   current menu item underlined     → aria-current        step 6
   filter sidebar, related block    → landmarks           step 7
   ```

   Done when every visual structure in the screenshot has a line and a step.

2. Headings ([H42](https://www.w3.org/WAI/WCAG22/Techniques/html/H42),
   [ARIA12](https://www.w3.org/WAI/WCAG22/Techniques/aria/ARIA12); advisory
   [G141](https://www.w3.org/WAI/WCAG22/Techniques/general/G141)). Match every title of step 1 to a
   `headings` entry (`text`, `level`, `ariaLevel`, `visible`). `role="heading"` with `aria-level`
   satisfies the criterion exactly as `h1`–`h6` does (ARIA12), so a `div role="heading"
aria-level="2"` passes and shows up with `ariaLevel` set. A title with no entry, or one listed
   in `visuallyStyledHeadings` with a `fontSize` or `fontWeight` above the paragraph it introduces,
   is styled text ([F2](https://www.w3.org/WAI/WCAG22/Techniques/failures/F2)); `p-as-heading`
   would have caught the `p` cases but is experimental and off, so this comparison is the only
   check. A `headings` entry that titles nothing that follows — a price, a pull quote, a teaser
   line, a logo, a footer slogan sized for looks — is structural markup used for presentation
   ([F43](https://www.w3.org/WAI/WCAG22/Techniques/failures/F43)). Skipped levels, a missing `h1`
   and an off-screen heading that names the section it starts all pass here; a long sectioned page
   with no headings at all is a fail on the titles the eye reads, G141 being the fix. Done when
   every title has a heading and every heading a section.

3. Lists and groups of links ([H48](https://www.w3.org/WAI/WCAG22/Techniques/html/H48),
   [H97](https://www.w3.org/WAI/WCAG22/Techniques/html/H97),
   [H85](https://www.w3.org/WAI/WCAG22/Techniques/html/H85)). `lists.fakeLists` holds one entry per
   `p` or `div` whose text opens with a bullet, a number or a dash: two or more sibling entries
   that read as one list fail; a lone entry that is a sentence ("2025. A big year") passes. Walk
   the other visual lists of step 1 — menus, breadcrumbs, card grids, numbered steps, tag rows,
   footer link columns — through `snapshot -s "<css>"`: a `list` with `listitem` children passes,
   `generic` wrappers or bare text items fail. H48 covers "lists or groups of links", so a column
   of related links is a list case as well as a region case. A `select` whose options are visually
   grouped — indented, separated by a dashed line, sharing a repeated prefix — needs `optgroup`
   (H85):

   ```bash
   agent-browser get html "<select selector>"
   ```

   axe `list`, `listitem`, `definition-list` and `dlitem` have already decided the list markup that
   exists; they say nothing about list markup that is missing, which is this step's whole subject.
   A `ul` wrapped around unrelated blocks for layout is not a fail, it goes to confirmation.
   Done when each `fakeLists` entry, each visual list, each link group and each grouped `select`
   has a verdict.

4. Tables ([H51](https://www.w3.org/WAI/WCAG22/Techniques/html/H51),
   [H39](https://www.w3.org/WAI/WCAG22/Techniques/html/H39),
   [H63](https://www.w3.org/WAI/WCAG22/Techniques/html/H63),
   [H43](https://www.w3.org/WAI/WCAG22/Techniques/html/H43); ACT a25f45, d0f69e). Read the wiring
   of every table once:

   ```bash
   agent-browser eval --stdin <<'EOF'
   (() => {
     const sel = e => e.tagName.toLowerCase() + (e.id ? '#' + e.id : '')
     return [...document.querySelectorAll('table, [role=table], [role=grid]')].map(t => ({
       table: sel(t),
       summary: t.getAttribute('summary'),
       caption: (t.querySelector('caption')?.textContent || '').trim(),
       titleBefore: (t.previousElementSibling?.textContent || '').trim().slice(0, 60),
       headers: [...t.querySelectorAll('th, [role=columnheader], [role=rowheader]')].map(h => ({
         id: h.id, scope: h.getAttribute('scope'), text: h.textContent.trim().slice(0, 30),
         span: (h.colSpan > 1 ? 'col' + h.colSpan : '') + (h.rowSpan > 1 ? 'row' + h.rowSpan : ''),
         explicitRefs: [...t.querySelectorAll('td, [role=gridcell]')]
           .filter(c => (c.getAttribute('headers') || '').split(/\s+/).includes(h.id)).length,
       })),
       refs: [...t.querySelectorAll('[headers]')].map(c => ({
         cell: sel(c), headers: c.getAttribute('headers'),
         unresolved: (c.getAttribute('headers') || '').split(/\s+/).filter(Boolean).filter(i => {
           const n = t.querySelector('#' + CSS.escape(i))
           return !n || n === c || !n.matches('th, [role=columnheader], [role=rowheader]')
         }),
       })),
     }))
   })()
   EOF
   ```

   Decide per table, with `structure.js` `tables` (`thCount`, `scopeCount`, `headersAttrCount`,
   `rows`, `cols`, `layoutLike`) beside it:

   - `layoutLike: true` also covers any table with no `th` and fewer than two rows or columns, so
     confirm in the screenshot that a table really is layout before failing on it. A layout table
     that carries `th`, a `caption` or a non-empty `summary` fails
     ([F46](https://www.w3.org/WAI/WCAG22/Techniques/failures/F46)) — F46 names all three, and
     `summary` is invisible, so take it from the `summary` field above. A small captioned data
     table is correct: do not fail it for `layoutLike`.
   - `layoutLike: false` with `thCount: 0` while the screenshot shows a header row or column fails
     ([F91](https://www.w3.org/WAI/WCAG22/Techniques/failures/F91)); so does a `div role="table"`
     whose first row is styled as headers with no `columnheader`.
   - Headers that span, or a table with headers on both axes (`span` non-empty above), with
     `scopeCount: 0` and `headersAttrCount: 0` fail: the implicit association only walks straight
     rows and columns, so use `scope` (H63) or `id`/`headers` (H43).
   - ACT a25f45 has **two** expectations and both must hold for every `headers` attribute. One:
     "Each target's attribute value is a set of space separated tokens. Each token is the value of
     the id attribute of an element, that is a cell of the same table." Two: "Each target's
     attribute value is a set of space separated tokens, and none of these tokens is the id of the
     element on which the test target is specified." `refs[].unresolved` applies axe's stricter
     test (the token must land on a header cell of this table), so sort its entries: a token with
     no matching id anywhere, one whose id lives in another table, one on a `span` inside a `td`
     rather than on a cell, and the cell's own id all break expectation 1 or 2 and fail
     ([F90](https://www.w3.org/WAI/WCAG22/Techniques/failures/F90)); a token that lands on a plain
     `td` of this table passes a25f45 (a `td` is a cell) while axe `td-headers-attr` still reports
     it, so check the screenshot — that cell reads as a header, the defect is the missing `th`
     (F91); it does not, the reference is wrong (F90). Browsers silently ignore every broken
     reference, so nothing on screen shows the defect, W3C: "headers attribute referencing elements
     that are non-existent or not in the table are ignored when assigning header cells" and
     "headers attribute referencing to the cell itself are ignored".
   - ACT d0f69e applies to every visible `rowheader`/`columnheader` in the tree whose closest
     semantic `table` or `grid` ancestor is also in the tree, and expects: "Each target element is
     assigned to at least one element with an inheriting semantic cell", the inheriting roles being
     "columnheader, gridcell, and rowheader". `explicitRefs` above counts only cells that name the
     header in `headers`, so read it together with the screenshot: a header whose row or column
     holds no data cell fails. Its own assumption is the exception — "a table definition where
     there is only one header cell, or a table definition where there are multiple headers and no
     other cells. In such scenarios the rule fails, but success criterion 1.3.1 Info and
     Relationships could still be satisfied" — so pass a header-only table and an empty column's
     header, and record why.
   - `titleBefore` that names the table while `caption` is empty is the `table-fake-caption` case
     (experimental, off): fail when the text is the table's title, pass when it is a lead-in
     sentence; H39 is the fix either way.
   - A table larger than 3 by 3 whose non-empty cells have no header at all is `td-has-header`'s
     case (experimental, off) and collapses into the F91 decision above.

   Done when every table, every `headers` reference and every header cell has a verdict.

5. Labels, groups and option groups ([H44](https://www.w3.org/WAI/WCAG22/Techniques/html/H44),
   [H65](https://www.w3.org/WAI/WCAG22/Techniques/html/H65),
   [ARIA16](https://www.w3.org/WAI/WCAG22/Techniques/aria/ARIA16),
   [H71](https://www.w3.org/WAI/WCAG22/Techniques/html/H71),
   [ARIA17](https://www.w3.org/WAI/WCAG22/Techniques/aria/ARIA17), H85; advisory
   [G162](https://www.w3.org/WAI/WCAG22/Techniques/general/G162),
   [ARIA1](https://www.w3.org/WAI/WCAG22/Techniques/aria/ARIA1),
   [ARIA2](https://www.w3.org/WAI/WCAG22/Techniques/aria/ARIA2); ACT e086e5). e086e5 applies to
   "any element that is included in the accessibility tree, and that has one of the following
   semantic roles: checkbox, combobox (select elements), listbox, menuitemcheckbox, menuitemradio,
   radio, searchbox, slider, spinbutton, switch, textbox" and expects "Each target element has an
   accessible name that is not empty ("")". It leaves out `button` and `menuitem` by design, and it
   stays applicable to disabled fields. `visibleLabelText` in `forms.js` is filled only from a real
   `label`, so for every field in question read its block:

   ```bash
   agent-browser get html "<field selector>"
   agent-browser snapshot -s "<field selector>"
   ```

   - `nameSource: 'none'` with visible text beside the field is a control with visible label text
     and no accessible name: fail here
     ([F111](https://www.w3.org/WAI/WCAG22/Techniques/failures/F111)). `nameSource: 'none'` with no
     text anywhere is 4.1.2's (e086e5) and files there.
   - `visibleLabelText` non-empty while `name` comes from `aria-label` or `aria-labelledby` and
     differs from it: the tie the eye makes is not the tie the tree has — fail here, and route the
     name mismatch to 2.5.3 as well. An `aria-labelledby` pointing at that visible text passes
     (ARIA16); a `label` that is the name passes (H44).
   - `nameSource: 'title'` passes: H65 allows `title` "when the label element cannot be used".
     `nameSource: 'placeholder'` does not carry the relationship — the text vanishes on input; it
     is F111 when other text is visible beside the field, otherwise it goes to 3.3.2.
   - Radio or checkbox fields under one visible question with `inFieldset: false`, or
     `inFieldset: true` with an empty `legend`, and no named `group` or `radiogroup` in
     `snapshot -s "<css>"`: fail (H71 for `fieldset`/`legend`, ARIA17 for a named
     `role="group"`/`radiogroup`).
   - A `select` whose options are visually grouped with no `optgroup`: fail (H85, as in step 3).
   - Required fields: `required` or `ariaRequired` true passes, and so does an asterisk in the
     label text with a sentence that explains it, as long as that sentence is near after
     linearization — a legend at the top of the same `form` counts, a footnote at the foot of the
     page does not. An asterisk with nothing explaining it anywhere fails. ARIA2 (`aria-required`)
     is the advisory belt and braces.
   - `describedbyText` carries a hint the eye reads under the field (ARIA1). A hint that sits away
     from its field and is absent from `describedbyText` goes to confirmation, not to fail.
   - Label position: a label the eye reads for one field while the markup ties it to another
     (G162 is the fix) is a relationship defect — the `get html` block shows which.

   Done when every `fields` entry, every visual group, every grouped `select` and every
   required-field cue has a verdict.

6. Formatting, colour cues and the current item
   ([H49](https://www.w3.org/WAI/WCAG22/Techniques/html/H49),
   [G115](https://www.w3.org/WAI/WCAG22/Techniques/general/G115),
   [G117](https://www.w3.org/WAI/WCAG22/Techniques/general/G117),
   [G138](https://www.w3.org/WAI/WCAG22/Techniques/general/G138),
   [G140](https://www.w3.org/WAI/WCAG22/Techniques/general/G140),
   [ARIA24](https://www.w3.org/WAI/WCAG22/Techniques/aria/ARIA24),
   [ARIA26](https://www.w3.org/WAI/WCAG22/Techniques/aria/ARIA26); advisory
   [C22](https://www.w3.org/WAI/WCAG22/Techniques/css/C22)). For each set-apart word or phrase of
   step 1, read its paragraph with `agent-browser get html "<paragraph selector>"`. `em`, `strong`,
   `q`, `blockquote`, `cite`, `code`, `abbr`, `dfn`, `del`, `ins`, `sub`, `sup` or `mark` passes
   (H49, G115). A `span`, `b`, `i`, `u` or `font` carrying a class or an inline style is F2 when
   what the variation says — a quotation, a defined term, a warning, "sold out", a correction — is
   not also in the text, and passes as a typographic convention (a ship name in italics, a bolded
   lead-in) or as decoration. Saying the meaning in words is the other sufficient route (G117), and
   a correct text description passes even where markup was possible. A class or an inline style is
   never the defect by itself — styling text from CSS is what C22 and G140 ask for — so fail only
   on the meaning that no element and no words carry. Then three sweeps:

   - Text that points at formatting. Read the rendered text with `agent-browser get text "body"`
     and look for the sentences that only work with the formatting: "items in bold are in stock",
     "the fields in red are required", "highlighted rows are sold", "see the underlined terms". The
     distinction they name must be in markup or restated on each item (G138 makes colour cues
     semantic). Rows or cards grouped by background colour with nothing else saying what the
     grouping means fail here, because the intent names "a different background color ... used to
     indicate that several items are related to each other" as structure; colour marking a single
     item goes to 1.4.1.
   - The current item in a set: `snapshot` does not carry `aria-current`, so ask the element:

     ```bash
     agent-browser get attr "<current link selector>" aria-current
     ```

     A menu item, breadcrumb tail, step marker or pagination number highlighted by style alone,
     returning null, with no text saying it is the current one, fails (ARIA26 is the fix).

   - Font icons that stand for a word: a glyph with no text beside it needs `role="img"` and a name
     (ARIA24):

     ```bash
     agent-browser eval --stdin <<'EOF'
     (() => {
       const out = []
       for (const e of document.querySelectorAll('i, span, em, b')) {
         const c = getComputedStyle(e, '::before').content
         if (!c || c === 'none' || c === 'normal' || e.textContent.trim()) continue
         out.push({ sel: e.tagName + '.' + e.className, content: c,
           role: e.getAttribute('role'), label: e.getAttribute('aria-label'),
           hidden: e.getAttribute('aria-hidden'),
           near: (e.parentElement?.textContent || '').trim().slice(0, 40) })
       }
       return out
     })()
     EOF
     ```

     A hit with `role` null, `label` null, `hidden` null and an empty `near` carries its meaning by
     shape only: fail (ARIA24). A hit with `hidden: "true"` next to text that says the same thing
     passes. An icon that is the whole of a link or button belongs to 1.1.1 and 4.1.2.

   Done when every set-apart phrase, every formatting sentence, every colour grouping, every
   current item and every bare icon glyph has a verdict.

7. Regions and their names ([H101](https://www.w3.org/WAI/WCAG22/Techniques/html/H101),
   [ARIA11](https://www.w3.org/WAI/WCAG22/Techniques/aria/ARIA11),
   [ARIA13](https://www.w3.org/WAI/WCAG22/Techniques/aria/ARIA13),
   [ARIA20](https://www.w3.org/WAI/WCAG22/Techniques/aria/ARIA20), H97). Read `landmarks` (role,
   name, selector) and `mainCount` against the regions of step 1. The criterion asks for structure,
   not for landmarks — headings can carry it, and the Understanding offers H101 and ARIA11 as
   routes rather than as the only route — so `mainCount: 0`, or two same-role landmarks with no
   distinguishing name, is a confirmation candidate. Record a fail only where a block the eye reads
   as one unit (a filter sidebar, a related-articles panel, a sticky toolbar) has no landmark, no
   heading and no text naming it. Names: a landmark with an empty `name` above a visible title
   needs `aria-labelledby` pointing at that title (ARIA13); `role="region"` without an accessible
   name does not surface as a landmark at all, so name it (ARIA20); a block of related links
   wrapped in nothing is H97's `nav`. Done when every region of step 1 has a landmark, a heading, a
   text description or a recorded confirmation question.

8. Structure removed or broken by ARIA
   ([F92](https://www.w3.org/WAI/WCAG22/Techniques/failures/F92); ACT bc4a75, ff89c9). List what
   hides or flattens real structure:

   ```bash
   agent-browser eval --stdin <<'EOF'
   (() => {
     const s = 'table, ul, ol, dl, h1, h2, h3, h4, h5, h6, th, li, label, fieldset, nav, main'
     return [...document.querySelectorAll('[role=presentation], [role=none], [aria-hidden=true]')]
       .filter(e => e.getBoundingClientRect().height && (e.matches(s) || e.querySelector(s)))
       .map(e => ({ sel: e.tagName + (e.id ? '#' + e.id : ''),
         role: e.getAttribute('role'), hidden: e.getAttribute('aria-hidden'),
         text: e.textContent.trim().slice(0, 60) }))
   })()
   EOF
   ```

   A hit on a data table, a real list, a title or a labelled field removes structure the eye still
   sees: fail (F92). A layout table, a decorative separator, an icon or a duplicate of content
   exposed elsewhere passes. Then the axe results:

   - `aria-required-children` incomplete: `agent-browser wait --load networkidle`, then
     `agent-browser snapshot -s "<css>"`. bc4a75 expects "Each test target only owns elements with
     a semantic role from the required owned element list for the test target's semantic role", and
     it does not apply at all to an element with "an inclusive ancestor in the accessibility tree
     with an aria-busy attribute value of true" — so a container still `aria-busy="true"` is
     `cannot-tell`, and children that never arrive fail. Its assumption bounds the fail: "If the
     semantic role on the target element is incorrectly used, and any relationships between
     elements are already programmatically determinable, failing this rule may not result in
     accessibility issues for users of assistive technologies, and it should then not be considered
     a failure under WCAG success criterion 1.3.1 Info and Relationships." A stray `role="list"` on
     a `ul` whose `li` still expose `listitem` is that case: pass it and note the stray role.
   - `aria-required-parent` violations are ff89c9: "Each test target is the child in the
     accessibility tree of an element that has a semantic role that is one of the required context
     roles of the target element." It skips an element "that has an implicit semantic role that is
     identical to its explicit semantic role" (`<li role="listitem">`), and its assumption makes
     either reading a fail: "A heading incorrectly marked up with role="cell" does not fail success
     criterion 1.3.1 Info and Relationships for not being in the context of a row. Having an
     inappropriate role is itself an issue under 1.3.1 Info and Relationships, so in either
     scenario a failure of this rule means this success criterion is not satisfied." Record the
     fail and name the structure that is lost.
   - Role validity and ARIA state or property rules (674b10, 5f99a7, 6a7281, 5c01ea, kb1m8s,
     4e8ab6) are the 4.1.2 file's in this same pass; count one here only when the broken ARIA
     removes a list, table, group, heading or region that steps 2 to 7 relied on.

   Emulated links ([F42](https://www.w3.org/WAI/WCAG22/Techniques/failures/F42)) belong to the
   `keyboard` pass under 4.1.2. Done when every hit and every incomplete has a line.

9. Structure drawn with characters
   ([F33](https://www.w3.org/WAI/WCAG22/Techniques/failures/F33),
   [F34](https://www.w3.org/WAI/WCAG22/Techniques/failures/F34),
   [F48](https://www.w3.org/WAI/WCAG22/Techniques/failures/F48); T1, T2, T3). The same sweep the
   1.3.2 pass runs; its `columns` hits are decided here:

   ```bash
   agent-browser eval --stdin <<'EOF'
   (() => {
     const id = e => e.tagName.toLowerCase() + (e.id ? '#' + e.id : '')
     const columns = [], nbsp = String.fromCharCode(160).repeat(3)
     const w = document.createTreeWalker(document.body, NodeFilter.SHOW_TEXT)
     for (let n; (n = w.nextNode()); ) {
       const t = n.textContent, el = n.parentElement, c = el && getComputedStyle(el)
       if (!t.trim() || !c || c.display === 'none' || c.visibility === 'hidden') continue
       const pre = /pre/.test(c.whiteSpace) && t.includes('\n') && /\S[\p{Zs}\t]{3,}\S/u.test(t)
       if (pre || t.includes(nbsp)) columns.push({ sel: id(el), hit: t.trim().slice(0, 80) })
     }
     return { columns }
   })()
   EOF
   ```

   A hit that reads as rows and columns of data fails (F34; F48 when it sits inside `pre`); a hit
   that reads as aligned columns of prose fails (F33); source code, ASCII art and indented poetry
   pass. A plain-text resource in the sample — a `.txt` file, a plain-text mail body, a
   `text/plain` response rendered in the browser — is Situation B: judge it against the conventions
   only, double blank lines before titles (T3), a consistent bullet or number in the first column
   of each item (T2), blank lines between paragraphs (T1). Done when every `columns` hit and every
   plain-text resource has a verdict.

10. States. For each state in `.notes/audit/recon/<sample>-states.md` — cookie dialog, open menu,
    expanded accordion, active tab, opened modal, loaded search results, the form's error state —
    re-run `structure.js`, `forms.js` and `snapshot`, and repeat steps 2 to 9 on what appeared: the
    dialog's title as a heading or as the dialog's own name, menu items as a `list` or `menu`, the
    expanded panel's contents, the error summary as a list of links, the fields that only now carry
    a label. Done when every state has its own line in the findings table.

The tree cannot show which header a screen reader announces for a spanned cell, whether `strong` is
voiced (most screen readers do not announce it; the markup still satisfies the criterion), how an
SVG diagram, a `canvas` or a cross-origin `iframe` is structured inside, or whether a PDF linked
from the sample carries tags (PDF6, PDF9, PDF10, PDF11, PDF12, PDF17, PDF20 and PDF21 apply inside
PDF documents, which this browser procedure cannot inspect): record `cannot-tell` with the excerpt
and the selector, and note that the PDF needs a PDF checker. Silent video
([ee13b5](https://www.w3.org/WAI/standards-guidelines/act/rules/ee13b5/)) is the `media` pass's
under 1.2.1.

## Deciding

- Fail (certainty ≥ 90): an axe violation from the table above (100); visible label text with no
  accessible name, F111 (95); a `headers` token that resolves to nothing, to another table, to a
  non-cell or to the cell's own id, breaking ACT a25f45 expectation 1 or 2, F90 (95); a data table
  with `thCount: 0` whose first row or column reads as headers, F91 (90); a layout table carrying
  `th`, a `caption` or a non-empty `summary`, F46 (90); data laid out in rows and columns with
  white space or `pre`, F34/F48 (90); `role="presentation"`, `role="none"` or `aria-hidden="true"`
  on a visible data table, list, title or labelled field, F92 (90); a `select` with visually
  grouped options and no `optgroup`, H85 (90).
- Fail (70–89): a title of step 1 with no heading element and no `role="heading"` (85); a fake list
  of two or more sibling items (85); an element whose required context role is absent, ff89c9 (80);
  a visible label that is not the field's name source (80); a radio or checkbox group under one
  question with no `fieldset`, `legend` or named group (80); a heading element on a price, quote,
  teaser or slogan, F43 (80); spanning or two-axis headers with no `scope` and no `headers` (80); a
  header cell with no data cell in its row or column, d0f69e (80); a sentence pointing at
  formatting ("items in bold are in stock") with no matching markup, G117/G138 (75); formatting
  that says what the text does not, F2 (75); a current item shown by style alone with
  `aria-current` null (75); aligned prose columns drawn in white space, F33 (75); required child
  roles that never arrive after `networkidle`, bc4a75 (75); a font icon carrying meaning with no
  role, no name and no adjacent text, ARIA24 (75); rows or cards grouped by background colour with
  no markup and no text saying what the grouping means (70); a block the eye reads as one unit with
  no landmark, no heading and no naming text (70); `role="region"` with no accessible name, ARIA20
  (70); a plain-text resource whose titles or list items follow no convention, T2/T3 (70).
- Needs confirmation (50–69): a region with neither landmark nor heading while headings elsewhere
  carry the structure (55): ask whether users must find it as a unit; a hint away from its field
  and absent from `describedbyText` (55): ask which field it serves and whether it is still "near
  the information it is describing (when the page is linearized)"; set-apart text of unclear
  meaning or a heading-sized slogan (55): ask the author what the styling says; a `headers` token
  resolving to a `td` that may be the row's real header (55): ask whether that cell is a header; a
  `ul` used purely for layout (50); a `div role="table"` whose structure the tree exposes but a
  screen reader may flatten (50); an SVG diagram, `canvas` or cross-origin `iframe` whose internal
  structure cannot be read (50).
- Pass: every title is a heading and every heading starts a section; every visual list is a `list`
  and every option group an `optgroup`; every data table has `th`, with `scope` or `headers` where
  the headers span or sit on both axes, and no layout table carries `th`, `caption` or `summary`;
  every header cell has data cells; every field takes its name from the text beside it and every
  visual group has a name; every meaningful variation in formatting or colour has markup or text;
  the current item carries `aria-current` or text; every region has a landmark, a heading or naming
  text; no ARIA hides or flattens real structure; and every state holds.
- Not present: no text, or one unformatted run with no field, list, table, title or region, in
  every state.
- False positives to avoid: skipped heading levels, a missing `h1`, an off-screen heading naming
  its section; a header-only table or an empty column's header that d0f69e fails, which its own
  assumption allows; a stray `role="list"` on a `ul` whose items still expose `listitem` (bc4a75's
  assumption); `<li role="listitem">`, which ff89c9 does not apply to; regions without landmarks
  where headings carry the structure; a layout table with no `th`, `caption` or `summary`; a
  lead-in paragraph before a table mistaken for a caption; `b` or `i` as a typographic convention;
  an asterisk in the label text explained by a sentence in the same form; navigation links in a
  `ul`; a `dl` with `div` wrappers around `dt`/`dd`; a `title`-only name, which H65 allows; a
  placeholder-only label (3.3.2); a correct text description where markup was possible, since
  programmatic determination is "strongly encouraged", not required; colour marking a single item
  (1.4.1).

## Reporting

- File under: 1.3.1 for structure or a relationship the eye sees and the tree lacks. Route: no
  visible label and no name to 4.1.2; a name that omits the visible label text also to 2.5.3;
  colour on a single item to 1.4.1; reading order to 1.3.2; same-named landmarks to 2.4.1; invalid
  ARIA to 4.1.2 unless it removes a list, table, group, heading or region; emulated links to 4.1.2
  (`keyboard` pass); an unnamed icon that is the whole control to 1.1.1; a video-only transcript to
  1.2.1. One issue per distinct pattern; a template defect is one issue that names every sample it
  appears on.
- Title patterns: "Section titles of <page> are styled text, not headings", "Table <name> has no
  header cells", "Header cells of <table> point to the wrong cells", "List of <items> is not marked
  up as a list", "Options in <field> are not grouped", "Label '<text>' is not linked to its field",
  "Radio buttons for <question> have no group label", "<Meaning> is shown by bold only", "Current
  page is shown by styling only", "<Region> has no landmark or heading", "Layout table is marked up
  as a data table"
- Severity: High when a data table a task depends on has no headers or the wrong ones, a form's
  labels or groups are not associated, a long sectioned page has no headings, or ARIA hides a whole
  structure from the tree; Medium when part of the page lacks headings, lists are fake, option
  groups are missing, a group label is missing while the labels stay clear, or the defect sits in a
  site-wide template; Low when one emphasis, one short list, a stray `th` or a single unnamed
  region is all that is affected.
- Type: Technical for markup and ARIA; Content when an editor styled the title, typed the bullets
  or pasted the white-space table in a rich-text field, or when the fix is a sentence that says
  what the formatting means.
- Evidence: full-page screenshot with `highlight "<css>"` on the region, plus the
  `snapshot -s "<css>"` excerpt quoted in the body so the reader sees what the tree exposes; an
  element `screenshot "<css>" <path>` for a table or a form; the `get html` fragment when the
  defect is invisible on screen (`summary`, `headers`, `role="presentation"`, `aria-current`). No
  GIF — nothing here is motion.
- Recommendation: name the element and give the markup. Mark titles with `h1`–`h6` (H42) or
  `role="heading"` with `aria-level` (ARIA12); wrap items in `ul`/`ol`/`dl` and link groups in
  `nav` (H48, H97); group `select` options with `optgroup` (H85); give data tables `th` with
  `scope` (H63), or `id`/`headers` for two-axis headers (H43), plus a `caption` (H39), and strip
  `th`, `caption` and `summary` from layout tables (F46); tie labels with `label for` (H44) or
  `aria-labelledby` (ARIA16), or `title` where a `label` cannot be used (H65), and keep the label
  where the eye expects it (G162); wrap groups in `fieldset`/`legend` (H71) or a named
  `role="group"` (ARIA17); tie a hint to its field with `aria-describedby` (ARIA1) and mark
  required fields with `aria-required` (ARIA2) plus a sentence that explains the asterisk;
  mark meaning with `em`, `strong`, `del` or `code` (H49, G115) or add it as text (G117,
  G138); name a font icon with `role="img"` (ARIA24); set `aria-current="page"` (ARIA26); identify
  regions with `header`, `nav`, `main`, `footer` (H101) or ARIA landmarks (ARIA11) named by
  `aria-labelledby` (ARIA13), and name every `role="region"` (ARIA20); keep the look in CSS and the
  meaning in markup (G140, C22).

  ```html
  <!-- titles: an element or a role, both are sufficient (H42, ARIA12) -->
  <h2>Our products</h2>
  <div role="heading" aria-level="2">Our products</div>

  <!-- a list, and a group of links (H48, H97) -->
  <ul>
    <li>Free returns</li>
    <li>Next-day delivery</li>
  </ul>
  <nav aria-label="Categories">
    <ul>
      <li><a href="/beds">Beds</a></li>
    </ul>
  </nav>

  <!-- data table: caption and a scope per axis (H39, H51, H63) -->
  <table>
    <caption>
      Opening hours
    </caption>
    <tr>
      <th scope="col">Day</th>
      <th scope="col">Open</th>
    </tr>
    <tr>
      <th scope="row">Monday</th>
      <td>09:00-17:00</td>
    </tr>
  </table>

  <!-- two-axis headers: each cell names its own headers, none names itself (H43) -->
  <th id="bus12" scope="col">Bus 12</th>
  <th id="stop-main" scope="row">Main Street</th>
  <td headers="stop-main bus12">08:15</td>

  <!-- label, group, option group (H44, H71, H85, ARIA2) -->
  <label for="email">E-mail</label> <input id="email" type="email" aria-required="true" />
  <fieldset>
    <legend>Delivery</legend>
    <input type="radio" id="post" name="delivery" /> <label for="post">By post</label>
  </fieldset>
  <select>
    <optgroup label="Beds"><option>Single</option></optgroup>
  </select>

  <!-- meaning, not looks (H49, ARIA24, ARIA26) -->
  <p>Price: <del>EUR 30</del> <strong>EUR 20</strong> (sale)</p>
  <span class="icon-warning" role="img" aria-label="Warning"></span>
  <a href="/beds" aria-current="page">Beds</a>

  <!-- regions, named from the title the eye reads (H101, ARIA11, ARIA13, ARIA20) -->
  <main>...</main>
  <section aria-labelledby="related">
    <h2 id="related">Related articles</h2>
    ...
  </section>
  ```
