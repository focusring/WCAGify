# 1.4.13 Content on Hover or Focus

Level AA · WCAG 2.1+ · Guideline 1.4 Distinguishable · Group: `visual` (also `keyboard`)

Sources: [Understanding][u] · [Spec][s] · [Techniques][t] · [Plain English][p] · ACT: none.

[u]: https://www.w3.org/WAI/WCAG22/Understanding/content-on-hover-or-focus.html
[s]: https://www.w3.org/TR/WCAG22/#content-on-hover-or-focus
[t]: https://www.w3.org/WAI/WCAG22/quickref/#content-on-hover-or-focus
[p]: https://aaardvarkaccessibility.com/wcag-plain-english/1-4-13-content-on-hover-or-focus/

## Requirement

> Where receiving and then removing pointer hover or keyboard focus triggers additional content to
> become visible and then hidden, the following are true:
>
> - Dismissible:
>   A mechanism is available to dismiss the additional content without moving pointer hover or
>   keyboard focus, unless the additional content communicates an input error or does not obscure
>   or replace other content;
> - Hoverable:
>   If pointer hover can trigger the additional content, then the pointer can be moved over the
>   additional content without the additional content disappearing;
> - Persistent:
>   The additional content remains visible until the hover or focus trigger is removed, the user
>   dismisses it, or its information is no longer valid.
>
> Exception: The visual presentation of the additional content is controlled by the user agent and
> is not modified by the author.
>
> Note 1: Examples of additional content controlled by the user agent include browser tooltips
> created through use of the HTML `title` attribute [HTML].
>
> Note 2: Custom tooltips, sub-menus, and other nonmodal popups that display on hover and focus are
> examples of additional content covered by this criterion.
>
> Note 3: This criterion applies to content that appears in addition to the triggering component
> itself. Since hidden components that are made visible on keyboard focus (such as links used to
> skip to another part of a page) do not present additional content they are not covered by this
> criterion.

Terms (WCAG 2.2 glossary):

- **mechanism**: "process or technique for achieving a result". Note 1: "The mechanism may be
  explicitly provided in the content, or may be relied upon to be provided by either the platform
  or by user agents, including assistive technologies." Note 2: "The mechanism needs to meet all
  success criteria for the conformance level claimed." So a dismissal that only works by moving the
  pointer to a close control, or a key the page never documents, is not a mechanism here.
- **input error**: "information provided by the user that is not accepted". Note: "This includes:
  [...] Information that is required by the web page but omitted by the user [...] Information that
  is provided by the user but that falls outside the required data format or values." A format hint
  shown on focus before anything was typed is not an input error and keeps its Dismissible duty.
- **user agents**: "any software that retrieves and presents web content for users", with the
  example "Web browsers, media players, plug-ins, and other programs — including assistive
  technologies". The Exception turns on this: only presentation the browser itself draws is out.

## In plain terms

When hovering over or focusing a component makes extra content appear (a custom tooltip, a hover
card, a sub-menu, a suggestion list, a field hint), the author owes three separate things:
Dismissible, Hoverable and Persistent. Each is judged on its own and any one of them failing fails
the criterion, so record three verdicts per addition. It stays while the pointer or focus rests on
the trigger, the pointer can move onto it without it vanishing, and a key such as Escape removes it
without moving pointer or focus. This serves people who pan a magnified view with the pointer or
focus, whose enlarged pointer covers the content, or who need more time to bring it into view.

## Applies when

- Present: author content that becomes visible on `:hover`/`mouseenter` or `:focus`/`:focus-within`
  of a trigger and hides again when the pointer or focus leaves: custom tooltips (`role="tooltip"`,
  hidden `aria-describedby` targets, `::after` tooltips), sub-menus opening on hover, hover cards,
  previews, action bars over a card, suggestion lists and field hints that open on focus.
- Not present: hovering and focusing every candidate adds nothing; the only effects are style
  changes on the trigger, skip links that slide in on focus (Note 3), native `title` tooltips, and
  content that opens on click, Enter or Space only.
- Exceptions:
  - User-agent presentation: "The visual presentation of the additional content is controlled by
    the user agent and is not modified by the author." Native `title` tooltips (Note 1), `<select>`
    and `<datalist>` drop-downs, native date and colour pickers, the browser's validation bubble.
    Recognise it by the absence of author DOM and author CSS for the popup: the step 2 diff finds
    no added element at all. A script that reads `title` and draws its own tooltip is author
    content and stays in scope.
  - Dismissible only, input error: "The additional content communicates an input error message:
    these can persist without being dismissible, as they generally require the user's attention,
    explicit confirmation or remedial action." Match the text against `forms.js` `visibleErrors`.
  - Dismissible only, nothing meaningful covered: "The additional content does not replace or
    obscure other meaningful content (including the trigger element itself): if the additional
    content only appears over white space or purely decorative content, such as a background
    graphic which provides no information, it won't interfere with a user's ability to view or
    operate the page." Decided by the step 2 `obscures` field, not by eye alone.
  - Out of scope, modal dialogs: "Modal dialogs are out of scope for this criterion because they
    must take keyboard focus and thus should not appear on hover or focus. Refer to Success
    Criterion 3.2.1 On Focus."
  - Out of scope, the trigger itself (Note 3): a component that only becomes visible on focus and
    presents nothing beyond itself — a skip link, a control that fades in — is not additional
    content.

## axe-core

No axe-core rule is tagged with this criterion; everything below is manual. The data pack lists no

## Manual procedure

Work at `set viewport 1280 900` in every recorded state (initial, cookie dialog, open menu, expanded
section, error state) and inside each `structure.js` `iframes` entry (`frame "<css>"`, steps 1 to 5,
`frame main`). `snapshot` shows whether added content is exposed, not where it sits or what it
covers: the diff script and screenshots decide that. Each addition ends with four records —
Hoverable, Persistent, Dismissible, and whether the popup is author-drawn (F95 needs that second
fact). Record `cannot-tell` for a trigger that emulation cannot reach (a canvas or WebGL surface, a
frame that `frame` will not enter).

1. Inventory the candidate triggers and store the visible baseline. `titleAttrs` from
   `structure.js` counts user-agent tooltips: exempt, note the number only.

   ```bash
   agent-browser mouse move 0 0
   agent-browser eval --stdin <<'EOF'
   (() => {
   const q = (s) => [...document.querySelectorAll(s)];
   let n = Math.max(0, ...q('[data-w1413]').map((el) => +el.dataset.w1413 || 0));
   const path = (el) => `[data-w1413="${el.dataset.w1413 ??= ++n}"]`;
   const vis = (el) => { const r = el.getBoundingClientRect(), c = getComputedStyle(el);
     return r.width > 1 && r.height > 1 && c.visibility !== 'hidden' && c.opacity !== '0'; };
   const out = { css: [], unreadable: [], hints: q('[aria-haspopup], [aria-describedby]').map(path),
     popups: q('[role="tooltip"], [class*="tooltip" i], [class*="popover" i], [class*="menu" i]')
       .filter((el) => !vis(el)).map(path) };
   const re = /display|visib|opacity|height|clip|transform|top|left|content/;
   const rule = (r, sheet) => { for (const s of (r.selectorText ?? '').split(',')) {
     const i = s.search(/:(hover|focus)/); if (i < 0 || !/[ >+~]|::/.test(s.slice(i))) continue;
     const trigger = s.slice(0, i).trim(); let m = [];
     try { m = q(trigger).slice(0, 8).map(path); } catch {}
     if (m.length && !out.css.some((c) => c.trigger === trigger))
       out.css.push({ sheet, sel: s.trim(), trigger, pseudo: /::/.test(s), matches: m }); } };
   const walk = (rules, sheet) => { for (const r of rules) { try {
     if (r.selectorText && re.test(r.style?.cssText ?? '')) rule(r, sheet);
     const sub = r.styleSheet?.cssRules ?? r.cssRules;   // a style rule carries an empty list
     if (sub?.length) walk(sub, r.href ?? sheet);
   } catch { out.unreadable.push(r.href ?? sheet); } } };
   walk([...document.styleSheets].map((s) => ({ styleSheet: s, href: s.href ?? 'inline' })), '');
   window.__w1413 = { q, vis, path, base: new Set(q('body *').filter(vis)) };
   return out; })();
   EOF
   ```

   The trigger list is every `matches` and `hints` entry, the link or button beside each `popups`
   entry (`nav li` for a sub-menu, the card for an overlay), the search field and every form
   field, plus the triggers of `:hover` and `:focus` rules in each `unreadable` sheet (`tab new`,
   `open <href>`, `get text body`, `tab close`), plus every `focusables.js` `order` entry with
   `visible: true`, by `selector` and `name`, where a JS-only tooltip with no class hint and no
   CSS rule hides. Walk the `order` sequence; for a run of identical components (a row of cards, a
   table of icon buttons) hover one representative and name the run. Done when every trigger is
   listed with its source.

2. Hover each trigger and diff the page against the baseline (`box` is the client rectangle,
   `obscures` the first element carrying text under the addition's centre, `gap` the distance
   between trigger and addition in CSS pixels).

   ```bash
   agent-browser hover '<trigger>'
   agent-browser wait 1000
   agent-browser eval --stdin <<'EOF'
   (() => {
   const { q, vis, path, base } = window.__w1413, t = document.querySelector('<trigger>');
   const top = (list) => list.filter((el) => !list.includes(el.parentElement));
   const box = (el) => el.getBoundingClientRect().toJSON();
   const under = (el) => { const r = el.getBoundingClientRect();
     const x = Math.round((r.left + r.right) / 2), y = Math.round((r.top + r.bottom) / 2);
     const hit = document.elementsFromPoint(x, y).find((e) => e !== el && !el.contains(e) &&
       !e.contains(el) && (e.innerText || '').trim());
     return hit ? { selector: path(hit), text: hit.innerText.trim().slice(0, 60) } : null; };
   const gap = (a, b) => Math.round(Math.max(0, b.top - a.bottom, a.top - b.bottom,
     b.left - a.right, a.left - b.right));
   return { trigger: t && { selector: path(t), box: box(t) }, active: path(document.activeElement),
     added: top(q('body *').filter((el) => vis(el) && !base.has(el))).map((el) => ({
       selector: path(el), box: box(el), text: (el.innerText || '').trim().slice(0, 60),
       obscures: under(el), gap: t ? gap(box(t), box(el)) : null })),
     replaced: top([...base].filter((el) => !vis(el))).map(path) }; })();
   EOF
   ```

   Each `added` entry is additional content of this trigger, unless `mouse move 0 0` leaves it on
   screen: the page updates itself there, strike it. Every `added` entry is author-drawn by
   construction — a user-agent tooltip never enters the DOM — so record F95's second check (the
   appearance is controlled by the user agent, not the author) as false for it. Empty `added` and
   `replaced`: the trigger adds nothing (Note 3), strike it, unless step 1 flagged it `pseudo: true`
   (a CSS-drawn tooltip the diff cannot see: `screenshot` before and after the hover and judge
   steps 3 and 4 by eye). Take evidence: `highlight '<added.selector>'`, then `screenshot` to
   `.notes/audit/evidence/`. Dismissible applies when `obscures` is non-null, `replaced` is
   non-empty, or the addition's box covers the trigger's box; `obscures: null` with the addition's
   box outside the viewport is not an answer — scroll it into view and re-run. A `gap` above 0 is
   the Hoverable risk the Understanding names: "This condition generally implies that the additional
   content overlaps or is positioned adjacent to the target." Done when every trigger has a diff and
   a screenshot, or is struck.

3. Hoverable (F95, SCR39 hover check 1): move the pointer from the trigger straight onto the
   content, the move wrapped in `record start <file.webm>` / `record stop` for the GIF. The
   Understanding names this exact move: "A technique to view the content fully in both situations is
   to move the mouse pointer directly from the trigger onto the new content."

   ```bash
   agent-browser hover '<trigger>'
   agent-browser wait 1000
   agent-browser eval --stdin <<'EOF'
   (() => {
   const { path } = window.__w1413;
   const a = document.querySelector('<trigger>'), b = document.querySelector('<added.selector>');
   if (!a || !b) return { error: 'trigger or content missing after hover' };
   const t = a.getBoundingClientRect(), c = b.getBoundingClientRect();
   const tx = (t.left + t.right) / 2, ty = (t.top + t.bottom) / 2;
   const cx = (c.left + c.right) / 2, cy = (c.top + c.bottom) / 2;
   const steps = [];
   for (let i = 1; i <= 6; i++)
     steps.push([Math.round(tx + (cx - tx) * i / 6), Math.round(ty + (cy - ty) * i / 6)]);
   const over = steps.map(([x, y]) => { const e = document.elementsFromPoint(x, y)[0];
     return e ? path(e) : null; });
   return { from: [Math.round(tx), Math.round(ty)], steps, over }; })();
   EOF
   agent-browser mouse move <steps[0][0]> <steps[0][1]>
   agent-browser mouse move <steps[1][0]> <steps[1][1]>
   agent-browser mouse move <steps[2][0]> <steps[2][1]>
   agent-browser mouse move <steps[3][0]> <steps[3][1]>
   agent-browser mouse move <steps[4][0]> <steps[4][1]>
   agent-browser mouse move <steps[5][0]> <steps[5][1]>
   agent-browser wait 600
   agent-browser is visible '<added.selector>'
   ```

   Six waypoints cover a short hop; for a wide `gap` add waypoints so no step jumps over an
   intervening element, and for a sub-menu continue the moves from its first item to its last.
   `true`: Hoverable holds. `false`: run the whole sequence a second time, because one closure can
   be a race; on the second `false` Hoverable fails. Cite
   [F95](https://www.w3.org/WAI/WCAG22/Techniques/failures/F95) only with both of its checks false:
   "The pointer can be moved over the new content without the additional content disappearing" is
   false here, and "The appearance of the additional content is controlled by the user agent, not
   the author" was recorded false in step 2 — F95's expected result is that content fails when #1
   and #2 are both false. Read the `over` list for F95's second example: when a waypoint lands on a
   selector that step 1 listed as another trigger, re-run the step 2 diff from the final pointer
   position; a different `added` entry there means the content was replaced on the way rather than
   kept, which fails Hoverable just as a closure does. `is visible` answers
   `Element not found` when the content left the DOM: read that as `false`. Done when every
   hover-triggered entry has a Hoverable verdict and, on a failure, a recording.

4. Persistent and Dismissible (SCR39 hover checks 2 and 3). Install the timer log first, hover, then
   read it back: the largest delay logged between hover and hide is the auto-hide timer and sets how
   long the wait has to be.

   ```bash
   agent-browser eval --stdin <<'EOF'
   (() => { const orig = window.setTimeout; window.__w1413t = [];
   window.setTimeout = function (fn, ms, ...rest) {
     window.__w1413t.push(ms ?? 0); return orig.call(this, fn, ms, ...rest); };
   window.__w1413restore = () => { window.setTimeout = orig; return window.__w1413t; };
   return true; })();
   EOF
   agent-browser hover '<trigger>'
   agent-browser wait 5000
   agent-browser is visible '<added.selector>'
   agent-browser eval --stdin <<'EOF'
   (() => window.__w1413restore())();
   EOF
   agent-browser hover '<trigger>'
   agent-browser wait 1000
   agent-browser press Escape
   agent-browser wait 300
   agent-browser is visible '<added.selector>'
   ```

   First result `true`: Persistent holds for the period observed. `false`: the content hid while
   hover was held, which fails Persistent unless "its information is no longer valid" — the
   Understanding's example is "a 'busy' message that is no longer valid", so a "saving", "copied" or
   "loading" notice is the exemption and a tooltip, hover card or sub-menu is not. WCAG sets no
   minimum time, so any automatic hide while the trigger is held fails; when the timer log returns a
   delay above 5000 raise the wait past it and re-run before recording a pass. Second result
   `false`: Dismissible is met. `true` and step 2 made Dismissible apply: try, in SCR39's order, any
   other key the page documents, then activating the trigger — `agent-browser click '<trigger>'`
   with the pointer already on it, which moves no hover — and re-check with `is visible`. SCR39
   accepts all three: "Either by pressing Esc, by pressing another documented keyboard shortcut, or
   by activating the trigger." A click that navigates instead of closing is not a mechanism: `back`
   and record Dismissible unmet. A close control inside the popup is not a mechanism either, because
   reaching it moves pointer hover. When the content covers the trigger, `hover` on it fails; return
   with `mouse move <x> <y>` on a part the content leaves free. Done when every hover-triggered
   entry has a Persistent and a Dismissible verdict.

5. Focus (SCR39 focus checks 1 and 2): repeat steps 2 and 4 with `focus '<selector>'` in place of
   `hover` for every focusable step 1 trigger and form field, without the pointer moves (Hoverable
   is hover-only, and SCR39 asks only for Persistent and Dismissible on focus). `active` in the diff
   must be the trigger (content that takes focus is 3.2.1) and must still be the trigger in a diff
   rerun after Escape: a mechanism that moves focus does not count. Where the trigger is activated
   as the dismissal, use `agent-browser press Enter` rather than `click`, so focus stays put. A
   hover trigger that adds nothing on focus is a 2.1.1 note for the `keyboard` pass, which re-checks
   focus-triggered content at every Tab stop, per the Understanding's note that "Content which can
   be triggered via pointer hover should also be able to be triggered by keyboard focus". Done when
   every focusable trigger has its diff and two verdicts.

## Deciding

- Fail (certainty ≥ 90): `is visible` is `false` after the pointer travelled the step 3 waypoints
  from the trigger onto the added content, twice in a row, and the addition came from the DOM diff,
  so both F95 checks are false ([F95](https://www.w3.org/WAI/WCAG22/Techniques/failures/F95)) (95);
  content hides on a timer while the pointer stays on the trigger and its information is still
  valid, the timer log naming the delay (92); focus-triggered content hides on a timer while
  `active` stays the trigger (92).
- Fail (70–89): content with a non-null `obscures` or a non-empty `replaced` that neither Escape,
  nor a documented shortcut, nor activating the trigger removes, on hover or on focus (85); a
  waypoint crossing a neighbouring trigger whose popup replaces the one under test, so the content
  cannot be reached by a straight pointer path (F95, second example) (85); an addition with a `gap`
  above 0 that closes while the pointer crosses the bare page between trigger and content, the
  Understanding requiring it to overlap or sit adjacent (82); a CSS `::after` tooltip over text or
  controls in the screenshot that no key dismisses (80); the only dismissal is a close control
  inside the popup, which the pointer must travel to, or a key the page nowhere documents (78);
  Escape hides the content but moves focus off the trigger, with no other mechanism (75); a sub-menu
  that closed on one gap crossing of two (75).
- Needs confirmation (50–69): content not dismissible whose `obscures` is null and whose
  screenshot shows it over a background graphic (60): ask whether that graphic carries information,
  the exemption covering only "purely decorative content, such as a background graphic which
  provides no information"; Hoverable for a `pseudo: true` tooltip (60): generated content is no DOM
  node, so `is visible` and `elementsFromPoint` cannot address it — ask the human to make the move
  with a real mouse; content that hides on a timer that may be an invalidation, such as a status or
  'busy' notice (55): ask what it means; a step 1 candidate that emulation could not open (50): ask
  the human to try it with a mouse.
- Pass: every hover-triggered addition survives the pointer moving onto it, every addition stays
  while hover or focus is held, and every addition that obscures or replaces meaningful content and
  is not an input error closes on Escape, on a documented shortcut, or on activating the trigger,
  with hover and focus unchanged.
- Not present: no author content appears on hover or focus in any state of the sample.
- False positives to avoid: `title` tooltips, native `<select>` lists and pickers are user-agent
  content; style changes on the trigger and skip links are not additional content (Note 3);
  content opened by click, Enter or Space is not covered; a modal dialog is 3.2.1; a focus hint
  naming a missing or rejected value is an input error and needs no Escape; activating the trigger
  is a full dismissal mechanism, so a popup with no Escape handler that closes on a second click of
  its trigger passes Dismissible; content that stays after the pointer leaves passes Persistent, and
  so does a sub-menu that closes once the pointer has left both the trigger and the menu, which is
  the Understanding's "removes hover or focus from the trigger and the additional content".

## Reporting

- File under: 1.4.13 for content that vanishes under the pointer, hides on its own or cannot be
  dismissed; hover content that never appears on focus goes to 2.1.1, a popup that moves focus
  into itself to 3.2.1, a tooltip absent from the accessibility tree to 4.1.2, a tooltip covering
  the focused control to 2.4.11. One issue per component, naming every sample it recurs on.
- Title patterns: "Tooltip on the <control> disappears when the pointer moves onto it", "Sub-menu
  closes before the pointer reaches it", "Hover card cannot be dismissed with Escape", "Tooltip on
  the <control> hides itself after a few seconds", "Suggestion list cannot be closed with Escape",
  "Chart pop-up is replaced by the next data point's pop-up on the way to it"
- Severity: High when the content is needed for the task (a sub-menu that is the only route to
  pages, a format hint, a price) and cannot be reached or read, or when it covers controls and
  cannot be dismissed; Medium when a supplementary tooltip or preview fails Hoverable or
  Persistent; Low when the content only repeats visible text and the defect is the missing Escape.
- Type: Technical for `mouseleave` handlers, hide timers, missing `keydown` handling and CSS-only
  tooltips; Design when the popup sits away from its trigger and the layout must change first.
- Evidence: the page screenshot with `highlight` on the trigger and the added content, taken with
  the content open; the step 3 recording as a GIF when the content vanishes under the pointer, is
  replaced on the way, or hides on a timer; for a missing Escape, screenshots before and after the
  key; name the element the step 2 `obscures` field returned, as that is what the popup hides.
- Recommendation: [SCR39](https://www.w3.org/WAI/WCAG22/Techniques/client-side-script/SCR39): nest
  the popup inside the trigger and drive it from `mouseenter`/`mouseleave`, so the pointer never
  leaves the trigger while it is over the popup, or, where the layout forbids nesting, cancel the
  hide on the popup's own `mouseenter`; drop the hide timer; close it on Escape from a `document`
  `keydown` listener, which fires while the pointer only hovers. Keep the nested text short or
  point at a sibling popup with `aria-describedby` instead, because a span inside the link joins
  the link's accessible name.

  ```html
  <a class="trigger" href="/pricing"
    >Pricing
    <span role="tooltip" id="tip" hidden>Per seat, billed yearly</span>
  </a>
  ```

  ```css
  .trigger {
    position: relative;
  }
  .trigger [role='tooltip'] {
    position: absolute;
    left: 0;
    top: 1em;
  }
  ```

  ```js
  const trigger = document.querySelector('.trigger'),
    tip = document.getElementById('tip')
  const show = () => {
    tip.hidden = false
  }
  const hide = () => {
    tip.hidden = true
  }
  trigger.addEventListener('mouseenter', show)
  trigger.addEventListener('mouseleave', hide)
  trigger.addEventListener('focusin', show)
  trigger.addEventListener('focusout', hide)
  document.addEventListener('keydown', (e) => {
    if (e.key === 'Escape') hide()
  })
  ```
