## Requirement

> The purpose of each link can be determined from the link text alone or from the link text
> together with its programmatically determined link context, except where the purpose of the
> link would be ambiguous to users in general.

Terms (WCAG 2.2 glossary), verbatim:

- **purpose of each link**: "nature of the result obtained by activating a hyperlink". The
  Understanding page lists the same term as **link purpose**.
- **programmatically determined link context**: "additional information that can be
  programmatically determined from relationships with a link, combined with the link text, and
  presented to users in different modalities". Example: "In HTML, information that is
  programmatically determinable from a link in English includes text that is in the same paragraph,
  list item, or table cell as the link or in a table header cell that is associated with the table
  cell that contains the link." Note: "Since screen readers interpret punctuation, they can also
  provide the context from the current sentence, when the focus is on a link in that sentence."
- **ambiguous to users in general**: "the purpose cannot be determined from the link and all
  information of the web page presented to the user simultaneously with the link (i.e., readers
  without disabilities would not know what a link would do until they activated it)". Example: "The
  word guava in the following sentence 'One of the notable exports is guava' is a link. The link
  could lead to a definition of guava, a chart listing the quantity of guava exported or a
  photograph of people harvesting guava. Until the link is activated, all readers are unsure and
  the person with a disability is not at any disadvantage."

Two clauses do the deciding. "and presented to users in different modalities": context that is only
visually near the link — a heading above the card, an icon column, alignment under an image — is not
link context. The Note on punctuation is what admits the enclosing _sentence_, which is the basis of
[G53](https://www.w3.org/WAI/WCAG22/Techniques/general/G53) and which the ACT set below leaves out.

5effbb narrows the WCAG term and says so: "This definition is based on (but not equivalent to) the
WCAG definition of programmatically determined link context." Its set is every element included in
the accessibility tree that is "being an ancestor of the link in the flat tree with a semantic role
of listitem; or being the closest ancestor of the link in the flat tree that generates a block
container; or being the closest ancestor of the link in the flat tree that has a semantic role of
cell or gridcell; or being a header cell assigned to the closest ancestor of the link in the flat
tree that has a semantic role of cell or gridcell; or being referenced by an aria-describedby
attribute of the link." Collect with the ACT set; decide with the WCAG term, sentence included.

## In plain terms

Every link tells the reader what activating it yields, in its own text (its accessible name) or in
that text with the sentence, paragraph, list item or table cell (and header cells) holding it: "Read
more" alone says nothing, inside the paragraph introducing the article it does. Screen reader users
read a page as a list of links and tab between them; people with motor or cognitive disabilities
skip links they do not need. The only escape is a link the page leaves unclear to every reader
alike.

## Applies when

- Present: any element with the semantic role `link` in the accessibility tree — c487ae applies to
  "any HTML element that is an inheriting semantic link included in the accessibility tree": `a` and
  `area` with `href`, `[role="link"]`, an SVG `a` with `href`, roles inheriting from link
  (`doc-biblioref`, c487ae Passed Example 11). `links.js` lists `a[href]` and `[role="link"]`;
  `images.js` returns image-map areas as `kind: 'area'`; `structure.js` `skipLinks` the skip links.
  An SVG anchor written with `xlink:href` matches none of the probe selectors — `snapshot` still
  lists it. A link exposed only in a recorded state (open menu, dialog) counts in that state.
- Still applicable, do not filter out: a link positioned off screen (`left: -9999px`) is in the
  tree (c487ae Passed Example 9, Failed Example 8); a link carrying `role="none"` or
  `role="presentation"` keeps the link role through Presentational Roles Conflict Resolution because
  it is focusable (c487ae Failed Example 10); a link whose name comes only from `title` (Passed
  Example 5).
- Not applicable in a state: the link is programmatically hidden, which 5effbb defines as "it has a
  computed CSS property visibility whose value is not visible; or at least one of the following is
  true for any of its inclusive ancestors in the flat tree: has a computed CSS property display of
  none; or has an aria-hidden attribute set to true" (c487ae Inapplicable Examples 2 to 4).
- Not present: no link in `links.js` and no `kind: 'area'` in `images.js`, in the sample and in
  every state; check the header, the footer and any cookie dialog before recording `not-present`.
- Exceptions: "except where the purpose of the link would be ambiguous to users in general". The
  Understanding Note: "There may be situations where the purpose of the link is supposed to be
  unknown or obscured. For instance, a game may have links identified only as door #1, door #2, and
  door #3. This link text would be sufficient because the purpose of the links is to create suspense
  for all users." The exception has a hard limit, from the Intent: "However, whatever amount of
  context is available on the web page that can be used to interpret the purpose of the link must be
  made available in the link text or programmatically associated with the link to satisfy the
  success criterion." So the exception holds only while _nothing_ on the page tells a sighted reader
  more ("guava" in a sentence about exports; two social-media links both named "ACT rules" in one
  sentence, fd3a94 Passed Example 9).
- Out of scope: `a` without `href` (c487ae Inapplicable Example 6, 5effbb Inapplicable Example 3);
  `a` whose role is changed to something else, e.g. `role="button"` (c487ae Inapplicable Example 1);
  a `span` with an `onclick` and no role (fd3a94 Inapplicable Example 4); an element marked up as a
  link that does not behave as one — c487ae assumes "that all links are user interface components as
  defined by WCAG 2. When the link role is used on elements that do not behave as links, failing
  this rule might not mean that the success criteria are failed."

## axe-core

| Rule        | Decides                     | Result → outcome                            |
| ----------- | --------------------------- | ------------------------------------------- |
| `link-name` | non-empty name (c487ae)     | violation → fail (100); incomplete → step 3 |
| `area-alt`  | `area[href]` named (c487ae) | violation → fail (100); incomplete → step 3 |

Both sit in the WCAG 2.0 A/AA rule set, so `agent-browser a11y` runs them by default; both are
tagged 4.1.2 as well, and `area-alt` is Critical, `link-name` Serious. Settles: a non-empty
accessible name for every link and image-map area in the states axe ran on
([F89](https://www.w3.org/WAI/WCAG22/Techniques/failures/F89);
[H24](https://www.w3.org/WAI/WCAG22/Techniques/html/H24) for `area`). Incomplete: compute the name
in step 3. Leaves open, and this list drives the procedure: whether the name with its
programmatically determined context describes the purpose (5effbb); generic names, file names,
"image" or "logo"; context that sits outside the link's own paragraph, list item or cell
([F63](https://www.w3.org/WAI/WCAG22/Techniques/failures/F63)); identical names in one context on
different resources (fd3a94); a short/long link-text switch
([G189](https://www.w3.org/WAI/WCAG22/Techniques/general/G189),
[SCR30](https://www.w3.org/WAI/WCAG22/Techniques/client-side-script/SCR30)); the exception. 5effbb
and fd3a94 are proposed rules with no axe implementation, followed here by hand. For an `area[href]`
that is not nested in a `map`, c487ae warns that "there are differences between browsers and
assistive technology on if the area is included in the accessibility tree": treat an axe result on
such an area as `cannot-tell`, step 7.

## Manual procedure

1. Inventory the links per state (re-run after each state is reached; selectors go stale):

   ```bash
   agent-browser wait --load networkidle
   agent-browser eval --stdin < <skill-dir>/scripts/probes/links.js
   agent-browser eval --stdin < <skill-dir>/scripts/probes/images.js
   ```

   Keep `links[]` (`selector`, `text`, `name`, `href`, `target`, `opensNewWindow`,
   `isImageOnly`, `context`, `contextText`, `generic`), `sameNameDifferentHref`, `emptyLinks`
   and `counts` (`total`, `generic`, `empty`, `newWindow`, `imageOnly`) per state in the
   findings file, plus every `images.js` entry with `kind: 'area'` and an `href`
   (`agent-browser get attr "<selector>" href`). Then drop what is not applicable: for each `a`
   entry run `agent-browser get attr "<selector>" role` and drop it when the role is anything but
   absent, `link`, `none`, `presentation` or a `doc-*` link role; run
   `agent-browser snapshot -s "<selector>"` and, where it returns no node, mark the link "hidden in
   this state" instead of failing it. `links.js` keeps `[role="link"]` elements without an `href`,
   which are in scope, and keeps hidden links, which are not. On a state axe did not cover, every
   remaining `emptyLinks` entry is a c487ae fail (95). Done when every state has its filtered link
   list, its `area` list and its empty-link count recorded, with the dropped selectors and the
   reason beside them.

2. Look for a short/long link-text switch before judging any name (G189, SCR30). Read the first
   controls of the page:

   ```bash
   agent-browser eval --stdin <<'EOF'
   (() => {
     const clean = e => (e.textContent || '').replace(/\s+/g, ' ').trim();
     return [...document.querySelectorAll('a[href], button, [role="link"], [role="button"]')]
       .slice(0, 15)
       .map(e => ({ tag: e.localName, text: clean(e), href: e.getAttribute('href') }));
   })()
   EOF
   ```

   A control named "Full link version", "Short link version", "Expand links" or the like near the
   beginning of the page is G189 (it leads to a conforming alternate version whose link text is
   self-contained) or SCR30 (a script rewrites the link text in place). Run
   `agent-browser click "<selector>"` and `agent-browser wait --load networkidle`, re-run step 1,
   and evaluate that version:
   the criterion is met if either version meets it. Record the alternate URL in the findings so the
   report can name it. The switch itself is held to G189's own words — "If the control for switching
   to the alternate version is a link, it must always be possible to understand the purpose of the
   control directly from its link text" — so an unnamed or generic switch is itself a step 3 fail.
   Done when the findings state either "no link-text switch" or which version the rest of this
   procedure judged, with its URL.

3. Judge the name alone (c487ae; [G91](https://www.w3.org/WAI/WCAG22/Techniques/general/G91),
   [H30](https://www.w3.org/WAI/WCAG22/Techniques/html/H30)). Read each `name` and sort it into (a)
   it says what activating the link yields — a destination, an action, or, per the Intent, the plain
   name of the target: "In cases where the link takes one to a document or a web application, the
   name of the document or web application would be sufficient to describe the purpose of the link
   ... Note that it is not required to use the name of the document or web application; other things
   may also describe the purpose of the link" (Understanding Example 1: "Medieval period of history"
   linked inside a sentence about the Medieval period passes on its name alone); (b)
   `generic: true`, a URL, a file name (`\.(png|jpg|svg|gif|webp|pdf)$`), a lone "image", "logo"
   or "icon", or a name describing the picture rather than the target; (c) an `emptyLinks` entry
   or an unnamed `area`. The probe's `generic` test is anchored and matches only these whole names,
   case-insensitively: `read more`, `learn more`, `more`, `click here`, `here`, `link`,
   `details`, `view`, `see more`, `lees meer`, `meer`, `klik hier`, `hier`, `bekijk`,
   `lees verder`, `verder`, `download`, `open`, `go`, `next`, `previous`, `volgende`,
   `vorige`, and any bare `https?://…`. Anything longer ("Read more about the budget", "Go") is
   not flagged: read every name yourself and move the vague ones into (b) by hand. For
   `isImageOnly: true` read the matching `images.js` entry (`inLink` equals the `href`) and judge
   its `alt` as link text. Where axe returned incomplete, compute the name with
   `agent-browser snapshot -s "<selector>"` and `agent-browser get attr "<selector>" title`; an
   `aria-labelledby` pointing at a missing id or an empty element yields an empty name (c487ae
   Failed Examples 6 and 7), and per the accname computation "it is not possible for a non-empty
   accessible name to be composed only of whitespace since these must be trimmed", so a
   whitespace-only name is list (c). List (a) passes; list (c) fails (F89, H24) and goes to
   Reporting; list (b) to step 4. Done when every link of every state is in list (a), (b) or (c).

4. Judge the name with its programmatically determined context (5effbb). The rule applies to "any
   inheriting semantic link for which all the following is true: the link is included in the
   accessibility tree; and the link has a non-empty ("") accessible name" — so list (c) never
   reaches here. Its expectation: "The accessible name of each target element together with its
   programmatically determined link context describes the purpose of the link."
   ([G53](https://www.w3.org/WAI/WCAG22/Techniques/general/G53),
   [H77](https://www.w3.org/WAI/WCAG22/Techniques/html/H77),
   [H78](https://www.w3.org/WAI/WCAG22/Techniques/html/H78),
   [H79](https://www.w3.org/WAI/WCAG22/Techniques/html/H79),
   [H81](https://www.w3.org/WAI/WCAG22/Techniques/html/H81),
   [ARIA7](https://www.w3.org/WAI/WCAG22/Techniques/aria/ARIA7),
   [ARIA8](https://www.w3.org/WAI/WCAG22/Techniques/aria/ARIA8).) Collect each list (b) link's
   context set — list-item ancestors, block container, cell with its assigned header cells,
   `aria-describedby` targets:

   ```bash
   agent-browser eval --stdin <<'EOF'
   (() => {
     const a = document.querySelector('<selector>');
     const txt = e => e ? e.innerText.replace(/\s+/g, ' ').trim() : null;
     const isBlock = e => /^(block|flex|grid|list-item|table|table-cell|flow-root)$/
       .test(getComputedStyle(e).display);
     let b = a.parentElement; while (b && !isBlock(b)) b = b.parentElement;
     const ids = (e, attr) => (e?.getAttribute(attr) || '').split(/\s+/).filter(Boolean)
       .map(id => txt(document.getElementById(id)));
     const listItems = [...document.querySelectorAll('li,[role="listitem"]')]
       .filter(li => li.contains(a)).map(txt);
     const cell = a.closest('td,th,[role="cell"],[role="gridcell"]');
     const span = c => { let i = 0; for (const s of c.parentElement?.cells ?? [])
       { if (s === c) return [i, i + s.colSpan]; i += s.colSpan } return [0, 0] };
     const covers = th => th.parentElement === cell.parentElement || (span(th)[0] < span(cell)[1]
       && span(cell)[0] < span(th)[1] && th.parentElement.rowIndex < cell.parentElement.rowIndex);
     const headers = !cell ? [] : ids(cell, 'headers').length ? ids(cell, 'headers')
       : [...(cell.closest('table')?.querySelectorAll('th') ?? [])].filter(covers).map(txt);
     return { listItems, block: txt(b), cell: txt(cell), headers,
       described: ids(a, 'aria-describedby'), title: a.getAttribute('title') };
   })()
   EOF
   ```

   `innerText` is rendered text, so `display: none` and `visibility: hidden` context drops out;
   ignore what sits inside `aria-hidden="true"`. `listItems` is every list-item ancestor (a nested
   list counts, H81) and `headers` every assigned header cell, column headers included. Slice the
   sentence containing the link out of `block` as well: the glossary Note admits it, and G53 rests
   on it (Understanding Example 2 — "Learn more about the Government of Ireland's Commission on
   Electronic Voting at Go Vote!" — passes a link named only "Go Vote!"). Worked example: a news
   card whose "Read more" link returns

   ```json
   {
     "listItems": [],
     "block": "The council published its 2024 budget on Tuesday. Read more",
     "cell": null,
     "headers": [],
     "described": [],
     "title": null
   }
   ```

   names the destination, so the link passes; the same card returning `block: "Read more"` with the
   heading and summary as siblings fails.

   The name with `listItems`, `block`, the sentence, `cell`, `headers` or `described` names the
   destination or the result: pass (5effbb Passed Examples 3, 5, 6, 8, 9; Understanding Example 5,
   the news page where each "Read more" sits in the paragraph that summarises its article). A
   `title` that completes it: pass by [H33](https://www.w3.org/WAI/WCAG22/Techniques/html/H33) with
   a note, because H33 itself warns "Because of the extensive user agent limitations in supporting
   access to the title attribute, authors should use caution in applying this technique" (it is not
   shown on keyboard focus or touch). Context after the link counts; the Intent only prefers it
   before ("This context will be most usable if it precedes the link"), so record that as a
   recommendation, not a fail.

   None of the set names it: fail. That includes a card whose heading and summary are siblings of
   the `<p>` or `<li>` holding only "Read more" (5effbb Failed Examples 4 and 5; F63), a preceding
   heading alone ([H80](https://www.w3.org/WAI/WCAG22/Techniques/html/H80) is advisory only), an SVG
   link whose only text is "Go" (Failed Example 3), and a "Download" cell whose row and headers
   name nothing — in Failed Example 6 the book title sits in a _sibling_ `td` of the same row,
   which is neither the link's cell nor a header cell for it. For each fail run
   `agent-browser highlight "<selector>"` and
   `agent-browser screenshot .notes/audit/evidence/<sample>--2.4.4--<n>.png`. Done when every list
   (b) link is marked "context names it", "fail" or "exception" (step 6).

5. Identical names in the same context (fd3a94). The rule applies to "any set of two or more HTML or
   SVG elements" that are inheriting semantic link nodes, in the same web page, included in the
   accessibility tree, with "matching accessible names that are not empty ("")" and "the same
   programmatically determined link context"; the test target is "the full set of link elements that
   share the same matching accessible name and programmatically determined link context". Its
   expectation, all three alternatives: "For each pair of links in each target set, one of the
   following is true: both links resolve to the same resource; or both links resolve to equivalent
   resources; or there is no visual information within the web page to let users know that both
   links resolve to non-equivalent resources." Note: "Resolving the links includes potential
   redirects, if the redirects happen instantly."

   For each `sameNameDifferentHref` entry find the links with that `name` and compare their context
   sets from step 4; the entry drops the `#` fragment, so pair same-named links to different
   fragments from `links[]` yourself, and pair an `aria-hidden="true"` twin out (Inapplicable
   Example 7). Different sets — each "Read more" in its own card, its own `<li>`, its own `<div>` —
   leave no pair, and step 4 already judged each link (Inapplicable Examples 3, 5, 6). Keep reading
   the Background for those: "Links with identical name that are in identical (but not the same)
   contexts also fail 2.4.4 Link Purpose (In Context). However, defining 'identical context'
   unambiguously has been deemed infeasible at this time, and so has been left out of this rule." So
   two cards whose context text is word-for-word identical and whose destinations differ are a 2.4.4
   fail even though fd3a94 is inapplicable — record it as a step 4 fail.

   The same set (two "Contact us" in one paragraph or one flex row): resolve each destination in a
   second tab, which leaves the sample's state intact:

   ```bash
   agent-browser tab new
   agent-browser open <href>
   agent-browser wait --load networkidle
   agent-browser get url
   agent-browser get title
   agent-browser get attr "meta[http-equiv='refresh']" content
   agent-browser read
   agent-browser tab close
   ```

   One URL after an instant redirect: pass (Passed Example 2). A `refresh` value whose delay is
   greater than zero (`30; URL='index.html'`) is not instant: the pair fails (Failed Example 8).
   Equivalent resources: pass (Passed Examples 3 to 6). Judge equivalence by the rule's glossary —
   "Non-identical resources can still be equivalent resources by equally complying to the
   expectation formed by the user when navigating to them, thus serving an equivalent purpose. This
   would usually involve that the advertised key content is the same." Resources stay equivalent
   when they "are located on different URLs, including different domains", "present different
   navigation options", "contain different amounts of information and/or differently worded
   information" or "use different layouts". They are not equivalent when the format or the language
   is the point: "If getting the same content in different formats or languages is the purpose of
   having separate links, the resources are not equivalent" — so an HTML link and a PDF link that
   share a name are a fail, not an equivalent pair.

   Non-equivalent resources: fail when any visual information on the page tells the two apart —
   words in the surrounding sentence or an adjacent paragraph that are outside the link's own
   context set ("via chat", "by phone"; "W3C pages for ACT:", "Community group for ACT:"), a CSS
   background icon, alignment under images, colour, an SVG shape (Failed Examples 1 to 7; hand the
   visual-only cue to 1.3.1 or 1.1.1). No visual information at all distinguishes them: the third
   alternative holds, take the pair to step 6. The URL itself never counts — fd3a94 assumes "that
   reading the URL, such as from the status bar when the link is focused, is not considered part of
   the context, and therefore, it does not disambiguate links". A login-walled or unreachable
   destination: `cannot-tell` for that pair. Done when every entry is marked "different contexts",
   "identical but not same context", "same resource", "equivalent", "fail", "no visual cue → step 6"
   or `cannot-tell`.

6. Apply the exception to what is left of list (b) and of step 5. Take a full-page screenshot and
   ask what a sighted reader knows before activating:

   ```bash
   agent-browser screenshot .notes/audit/evidence/<sample>--2.4.4--context.png --full
   ```

   Nothing on the page beyond the link text — a linked word in prose, "door #1" in a game, two
   social-media links both named "ACT rules" in one sentence (fd3a94 Passed Example 9) — is the
   exception: pass with the note "exception", because "all readers are unsure and the person with a
   disability is not at any disadvantage". A heading, an icon, a colour or a column position that
   tells sighted readers more: the fail stands, on the Intent's limit that "whatever amount of
   context is available on the web page that can be used to interpret the purpose of the link must
   be made available in the link text or programmatically associated with the link". Where the
   disambiguating cue is presentational, fd3a94 sends it on as well: such pages "are likely to fail
   success criterion 1.3.1 Info and Relationships if the disambiguation information is conveyed
   through presentation, but not semantically", and "when this information is non-text content, such
   a page is likely to fail success criterion 1.1.1 Non-text Content". Done when no link is
   undecided and every excepted link carries the sentence that justifies the exception.

7. Cannot-tell. Link text and context in a language you cannot judge: `cannot-tell`, queued. Links
   inside an `iframe`: `agent-browser frame <@ref>`, then re-run step 1 inside it. Links inside a
   shadow root: `links.js` misses them and `snapshot` lists them, so judge their names from the
   tree. fd3a94 assumes "that assistive technologies are exposing all links on the page in the same
   way no matter which document tree they are in. If an assistive technology requires the user to
   'enter' an iframe or a shadow tree before exposing its links, then it is possible for two links
   to have identical name and context but resolve to different resources without failing Success
   Criterion 2.4.4": a pair split across documents is `cannot-tell`. An `area[href]` outside a
   `map`: `cannot-tell`, on c487ae's accessibility-support note. An element with a link role that
   does not behave as a link (no navigation, no `href`, an in-page widget): `cannot-tell` with the
   c487ae and 5effbb assumption quoted, and check 4.1.2 instead. A name that reads as a homonym of
   another link's name: fd3a94 assumes "homonyms alone are not used as link names", so a genuine
   homonym pair is `cannot-tell`. A PDF sample needs /Link structures the browser does not expose
   ([PDF11](https://www.w3.org/WAI/WCAG22/Techniques/pdf/PDF11),
   [PDF13](https://www.w3.org/WAI/WCAG22/Techniques/pdf/PDF13)): `cannot-tell`, queued. Done when
   every link the earlier steps could not settle carries `cannot-tell`, the reason that settles it
   (language, frame, shadow root, area outside a map, non-link behaviour, homonym, PDF) and a
   question queued for the human.

## Deciding

- Fail (certainty ≥ 90): axe `link-name` or `area-alt` violation (100); an empty-named link or an
  `area[href]` without a name on a state axe did not cover (95; c487ae, F89, H24); a link whose only
  content is an image with `alt=""`, `role="presentation"` or `role="none"` (95; c487ae Failed
  Examples 2 to 4, F89); an `aria-labelledby` on the link or its image pointing at a missing id or
  an empty element (95; Failed Examples 6 and 7); a focusable link carrying `role="none"` or
  `role="presentation"` and no text (95; Failed Example 10); a link named by an image file name,
  "image", "graphic" or "icon" whose step 4 context names nothing either (90).
- Fail (70–89): a `generic: true` name ("Read more", "Click here", "Here", "More", "Download",
  "Details", "Next") whose context set names no destination — alone in its `<p>`, `<li>` or `<div>`
  while the heading, summary or list that names it sits outside (85; 5effbb Failed Examples 1, 4, 5;
  F63); an SVG link whose only content is a word like "Go" with nothing in its block (85; Failed
  Example 3); a "Download" or "Details" link in a cell whose row and assigned header cells name
  nothing, the title sitting in a sibling cell (80; Failed Example 6); identical names in one
  context set reaching non-equivalent resources while visual information on the page tells them
  apart — adjacent words outside the context set, a CSS background icon, alignment under images,
  colour (85; fd3a94 Failed Examples 1 to 7); two cards with word-for-word identical context and
  different destinations, which fd3a94 leaves out but 2.4.4 still fails (80; fd3a94 Background); the
  same pair joined only by a delayed `meta refresh` (75; Failed Example 8); identical names on an
  HTML and a PDF (or two languages) of one document, which are not equivalent resources (80); an
  image link whose alt describes the picture, not the destination (75); a bare URL with an opaque
  path and no context (75); a name naming another destination than the page it opens (70); a
  short/long link-text switch that is itself unnamed or generic (75; G189, SCR30).
- Needs confirmation (50–69): a bare URL or domain whose words hint at the destination
  (`example.com/pricing`) (60), ask whether readers are expected to parse URLs; a vague name the
  probe leaves unflagged ("Overview", "Resources", "Read more about it") with thin context (60), ask
  what the reader should expect; a step 5 pair with similar destinations (55), ask whether they
  cover the user's expectation equally well; a link whose name is only in a `title` attribute (60;
  H33), ask whether keyboard and touch users can reach it; an element with a link role whose
  behaviour you could not confirm (55).
- Pass: every link in every recorded state has a non-empty name that, alone or with its list item,
  block, sentence, cell, header cells or described-by text, tells the reader what activating it
  yields; identical names in one context set reach the same or equivalent resources, or nothing on
  the page distinguishes them; the rest are excepted. A page that offers a conforming alternate
  version with full link text (G189) or expands the link text on request (SCR30) passes on that
  version.
- Not present: no link in the sample or in any recorded state.
- False positives to avoid: generic visible text completed by hidden text or ARIA ("Read more <span
  class="visually-hidden">about the 2024 budget</span>", `aria-label`, `aria-labelledby`:
  [C7](https://www.w3.org/WAI/WCAG22/Techniques/css/C7), ARIA8, ARIA7; the visible-text mismatch is
  2.5.3); a link named with the plain name of the document or application it opens, which the Intent
  calls sufficient; "HTML", "PDF", "mp3" under the book's title in a nested list or a header cell
  (H81, H79; 5effbb Passed Examples 5 and 6; Understanding Example 4); an icon and text inside one
  `a` where the icon carries `alt=""` (Understanding Example 3;
  [H2](https://www.w3.org/WAI/WCAG22/Techniques/html/H2)); two adjacent links, one image and one
  text, to the same `href` — the same resource satisfies fd3a94, and merging them is advisory only

## Reporting

- File under: 2.4.4 for generic or vague names, context outside the link's block, identical names to
  different resources, opaque URLs, alt that describes the picture, and a link with no content at
  all. An image-only link or an image-map `area` with an empty name is one issue under 1.1.1 (F89
  names 2.4.4, 2.4.9 and 4.1.2): record `fail` here and cite that issue. A visual-only cue that
  tells identical links apart is a second issue under 1.3.1 (or 1.1.1 when the cue is an image). A
  template's "Read more" is one issue naming every sample it is on; a wrong link in body copy is its
  own. Where the page offers a full-link-text version (G189, SCR30), name that version in the issue
  and report only what that version still fails.
- Title patterns: "Links say only 'Read more'", "Link text is a URL", "Several 'Contact us' links
  lead to different pages", "Image link is named after the file", "Link has no text", "Image-map
  area has no alternative text", "Icon link has no name", "Download links do not name the document"
- Severity: High when the defect hides the destinations of the main navigation or the primary
  content from screen reader users; Medium when one component's links are ambiguous but other text
  lets a user work them out; Low when one vague link sits under a heading that makes it clear.
- Type: Content when an editor wrote the link text ("click here" in body copy, an alt that describes
  the picture); Technical when a template generates it (a card's "Read more", an icon link without a
  name, a missing `aria-labelledby`).
- Evidence: the page screenshot with `highlight` on the link, or on the block that holds it to show
  the missing context; for an identical-name pair both links in one shot and both `href`s, plus the
  two destination titles from step 5. No GIF.
- Recommendation: write link text that names the destination or the result (G91, H30):

  ```html
  <a href="/reports/2024.pdf">Annual report 2024 (PDF)</a>
  ```

  Where the text must stay short, put the description in the same sentence, paragraph, list item or
  cell (G53, H77, H78, H79, H81), or attach it with `aria-labelledby` naming the link and its card
  heading (ARIA7):

  ```html
  <h3 id="card-7">Budget 2024</h3>
  <p>
    The council published its 2024 budget.
    <a id="more-7" href="/budget-2024" aria-labelledby="more-7 card-7">Read more</a>
  </p>
  ```

  or with `aria-label` (ARIA8), or with text hidden in CSS (C7):

  ```html
  <a href="/budget-2024">Read more<span class="visually-hidden"> about the 2024 budget</span></a>
  ```

  Give every image-map area its alternative text (H24):

  ```html
  <area shape="rect" coords="0,0,30,100" href="sun.htm" alt="Sun" />
  ```

  Merge an adjacent icon link and text link to one resource into a single link with a null alt (H2):

  ```html
  <a href="/products"><img src="icon.svg" alt="" />Products</a>
  ```

  Name identical links apart ("Contact us by chat", "Contact us by phone"). Prefer context that
  precedes the link. Where short link text is a deliberate choice, offer a control near the top of
  the page that switches to full link text (G189) or expands it with a script (SCR30), and name that
  control so its own purpose is clear. Announcing "opens in a new window" (G201, SCR24) and adding a
  `title` (H33) are advisory: offer them as advice, not as the fix.

  must do it, and 5effbb notes the criterion "is more strict than this rule"); 2.5.3 (`aria-label`
  without the visible text); 2.4.2 (link text and page title agreeing is good practice); 3.2.4 (one
  destination named consistently across pages); 1.3.1 and 1.1.1 (a visual-only cue telling identical
