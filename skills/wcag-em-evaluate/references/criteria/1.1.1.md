# 1.1.1 Non-text Content

Level A · WCAG 2.0+ · Guideline 1.1 Text Alternatives · Group: `structure` (also `media`)

Sources: [Understanding](https://www.w3.org/WAI/WCAG22/Understanding/non-text-content.html) ·

## Requirement

> All non-text content that is presented to the user has a text alternative that serves the
> equivalent purpose, except for the situations listed below.
>
> - Controls, Input: If non-text content is a control or accepts user input, then it has a name
>   that describes its purpose. (Refer to Success Criterion 4.1.2 for additional requirements for
>   controls and content that accepts user input.)
> - Time-Based Media: If non-text content is time-based media, then text alternatives at least
>   provide descriptive identification of the non-text content. (Refer to Guideline 1.2 for
>   additional requirements for media.)
> - Test: If non-text content is a test or exercise that would be invalid if presented in text,
>   then text alternatives at least provide descriptive identification of the non-text content.
> - Sensory: If non-text content is primarily intended to create a specific sensory experience,
>   then text alternatives at least provide descriptive identification of the non-text content.
> - CAPTCHA: If the purpose of non-text content is to confirm that content is being accessed by a
>   person rather than a computer, then text alternatives that identify and describe the purpose
>   of the non-text content are provided, and alternative forms of CAPTCHA using output modes for
>   different types of sensory perception are provided to accommodate different disabilities.
> - Decoration, Formatting, Invisible: If non-text content is pure decoration, is used only for
>   visual formatting, or is not presented to users, then it is implemented in a way that it can
>   be ignored by assistive technology.

Terms (WCAG 2.2 glossary), verbatim; these decide the verdict:

- **non-text content**: "any content that is not a sequence of characters that can be
  programmatically determined or where the sequence is not expressing something in human language".
  Note: "This includes ASCII art (which is a pattern of characters), emoticons, leetspeak (which
  uses character substitution), and images representing text".
- **text**: "sequence of characters that can be programmatically determined, where the sequence is
  expressing something in human language" — characters painted inside an image are not text.
- **text alternative**: "Text that is programmatically associated with non-text content or referred
  to from text that is programmatically associated with non-text content. Programmatically
  associated text is text whose location can be programmatically determined from the non-text
  content." Example: "An image of a chart is described in text in the paragraph after the chart. The
  short text alternative for the chart indicates that a description follows."
- **name**: "text by which software can identify a component within web content to the user". Note
  1: "The name may be hidden and only exposed by assistive technology, whereas a label is presented
  to all users. In many (but not all) cases, the label and the name are the same." Note 2: "This is
  unrelated to the name attribute in HTML" — take the name from the accessibility tree
  (`snapshot`), never from a `name` attribute.
- **pure decoration**: "serving only an aesthetic purpose, providing no information, and having no
  functionality". Note: "Text is only purely decorative if the words can be rearranged or
  substituted without changing their purpose." W3C's example is a text one: "The cover page of a
  dictionary has random words in very light text in the background."
- **specific sensory experience**: "a sensory experience that is not purely decorative and does not
  primarily convey important information or perform a function"; W3C's examples are "a performance
  of a flute solo, works of visual art".
- **CAPTCHA**: initialism for "Completely Automated Public Turing test to tell Computers and Humans
  Apart". Note 1: "CAPTCHA tests often involve asking the user to type in text that is displayed in
  an obscured image or audio file."
- **ASCII art**: "picture created by a spatial arrangement of characters or glyphs (typically from
  the 95 printable characters defined by ASCII)".
- **assistive technologies**: "hardware and/or software that acts as a user agent, or along with a
  mainstream user agent, to provide functionality to meet the requirements of users with
  disabilities that go beyond those offered by mainstream user agents" — screen readers and braille
  displays read what the accessibility tree exposes, so "can be ignored by assistive technology" is
  decided from `snapshot`, not from how the page looks.

## In plain terms

Everything the user perceives that is not text (photos, icons, SVG, canvas, image buttons, media,
emoji, ASCII art) needs text that does the same job, attached so a screen reader can reach people
who cannot see or hear it; W3C's intent is that the information can then "be rendered through any
sensory modality" — speech, enlarged text, braille. Controls need a name that says what they do;
media, tests and sensory content need identifying text. A CAPTCHA needs text that identifies it and
describes its purpose, plus a version in another modality. Decorative, formatting and invisible
images are hidden from AT, because alt text on them "just distracts people using screen readers from
the content on the page".

## Applies when

- Present: `img` (also inside `picture`, and lazy-loaded images below the fold), `svg`, `canvas`,
  `input type="image"`, `area`, `object`/`embed` rendering an image, audio or video, `[role="img"]`,
  an icon font glyph or CSS `background-image` that carries meaning, `video`/`audio`, emoji,
  emoticons, ASCII art or leetspeak, an ARIA `meter` or `progressbar`, a CAPTCHA, in any state.
  Detect with `images.js` (`counts.total > 0`), `media.js` (`counts`) and `structure.js` (`iframes`
  whose `src` contains `captcha`), after paging to the foot of the document so lazy images load.
  A sound that carries information is non-text content too — W3C's e-learning example: "The chime
  sound indicates that the answer is correct and the beep sound indicates that the answer is
  incorrect." Re-run `media.js` after every interaction that answers the user; an `audio` item with
  `controls` false and no `tracks` that appears only then is a sound cue (step 7).
- Not present: `images.js` reports `counts.total = 0` in every state, `media.js` returns no `media`
  and no `animatedImages`, no interaction produces a sound cue, the text has no emoji or ASCII art,
  and no CAPTCHA is embedded.
- Exceptions. Each one lowers what the alternative must carry; none takes the item out of scope.
  1. Controls, input: an image that is, or is the only content of, a link, button, `input
type="image"` or `area` needs a name that describes the purpose, W3C: "so that the person at
     least knows what the non-text content is and why it is there". Recognise it by `images.js`
     `inLink`/`inButton`, or `kind` `input-image`/`area`.
  2. Time-based media: identification is enough here, the full alternative belongs to 1.2.x. W3C
     splits this exception: "prerecorded audio-only and prerecorded video-only files are covered
     here", i.e. by the general rule (their equivalent alternative is 1.2.1's), while for live
     audio-only and live video-only content "text alternatives provide a descriptive label"
     ([G68](https://www.w3.org/WAI/WCAG22/Techniques/general/G68)). Recognise it by `media.js` items
     and by `animatedImages` that play a sequence.
  3. Test: "a test or exercise that would be invalid if presented in text" — W3C's examples are a
     hearing test, "a visual skill development exercise" and a spelling test; the identification
     "would not provide the same information needed to pass the test". Recognise it by an image that
     is the question inside a quiz or exercise form.
  4. Sensory: content "primarily intended to create a specific sensory experience" (art, music, a
     performance); "text alternatives at least identify the non-text content with a descriptive
     label and where possible, additional descriptive text".
  5. CAPTCHA: text that identifies and describes its purpose, plus a second CAPTCHA "using output
     modes for different types of sensory perception". W3C: "Requiring two different forms of
     CAPTCHA on a given site ensures that most people with disabilities will find a form they can
     use." Recognise it by a `captcha` iframe, a challenge image, an "I am not a robot" widget.
  6. Decoration, formatting, invisible: W3C's examples are "Transparent images used to move text
     over on a page; an invisible image that is used to track usage statistics; and a swirl in the
     corner that conveys no information but just fills up a blank space to create an aesthetic
     effect". Implement it so AT ignores it — `alt=""` and no `title`
     ([H67](https://www.w3.org/WAI/WCAG22/Techniques/html/H67)), `role="none"`, a CSS background
     ([C9](https://www.w3.org/WAI/WCAG22/Techniques/css/C9)), `aria-hidden="true"` — and give it no
     text. Spacer images belong in CSS margin and padding
     ([C18](https://www.w3.org/WAI/WCAG22/Techniques/css/C18)). Recognise it by `images.js`
     `presentational: true`, or `width`/`height` 0.

## axe-core

| Rule                    | Decides                       | Result → outcome                            |
| ----------------------- | ----------------------------- | ------------------------------------------- |
| `image-alt`             | `img` named or presentational | violation → fail (100); incomplete → step 2 |
| `role-img-alt`          | `[role="img"]` named          | violation → fail (100); incomplete → step 2 |
| `svg-img-alt`           | `svg` with img role named     | violation → fail (100); incomplete → step 2 |
| `input-image-alt`       | image button named            | violation → fail (100); incomplete → step 2 |
| `object-alt`            | `object` named                | violation → fail (100); incomplete → step 2 |
| `aria-meter-name`       | meter named                   | violation → fail (100); incomplete → step 2 |
| `aria-progressbar-name` | progressbar named             | violation → fail (100); incomplete → step 2 |

All seven are in the default "WCAG 2.0 Level A & AA Rules" set — none is experimental or deprecated,
so `agent-browser a11y` runs every one of them, and each carries both `failure` and `needs review`,
so each can also come back as `incomplete`. Impact: `image-alt` and `input-image-alt` critical, the
other five serious; use impact for severity, never for the verdict.

Settles, within the ACT scopes it implements:
[23a2a8](https://www.w3.org/WAI/standards-guidelines/act/rules/23a2a8/) — `img` and elements with a
semantic `img` role, "except if the element is programmatically hidden", expecting "an accessible
name that is not empty (""), or has a semantic role of none or presentation";
[7d6734](https://www.w3.org/WAI/standards-guidelines/act/rules/7d6734/) — `svg` with an explicit
role of `img`, `graphics-document` or `graphics-symbol` that is in the accessibility tree;
[59796f](https://www.w3.org/WAI/standards-guidelines/act/rules/59796f/) — `input type="image"` in
the tree, whose name must be "neither empty (""), nor the default name for this element (localized
version of "Submit Query")"; [8fc3b6](https://www.w3.org/WAI/standards-guidelines/act/rules/8fc3b6/)
— `object` in the tree, with "no explicit role", embedding "a resource whose MIME type is either
image, or audio or video"; plus ARIA meters and progress bars, which have no ACT rule.

Leaves open: whether the name serves the equivalent purpose
([qt1vmo](https://www.w3.org/WAI/standards-guidelines/act/rules/qt1vmo/);
[F30](https://www.w3.org/WAI/WCAG22/Techniques/failures/F30),
[F13](https://www.w3.org/WAI/WCAG22/Techniques/failures/F13),
[F20](https://www.w3.org/WAI/WCAG22/Techniques/failures/F20),
[F67](https://www.w3.org/WAI/WCAG22/Techniques/failures/F67)); whether decorative marking is right
([e88epe](https://www.w3.org/WAI/standards-guidelines/act/rules/e88epe/);
[F38](https://www.w3.org/WAI/WCAG22/Techniques/failures/F38),
[F39](https://www.w3.org/WAI/WCAG22/Techniques/failures/F39)) and stays unexposed
([46ca7f](https://www.w3.org/WAI/standards-guidelines/act/rules/46ca7f/)); `svg` without a role,
`canvas`, `embed`, `area` ([F65](https://www.w3.org/WAI/WCAG22/Techniques/failures/F65)), an
`object` with an explicit role or a non-media MIME type (a PDF viewer), icon fonts and CSS
backgrounds ([F3](https://www.w3.org/WAI/WCAG22/Techniques/failures/F3)); image-only links
([c487ae](https://www.w3.org/WAI/standards-guidelines/act/rules/c487ae/)); emoji, ASCII art,
leetspeak, look-alikes ([H86](https://www.w3.org/WAI/WCAG22/Techniques/html/H86);
[F71](https://www.w3.org/WAI/WCAG22/Techniques/failures/F71),
[F72](https://www.w3.org/WAI/WCAG22/Techniques/failures/F72)); long descriptions
([G95](https://www.w3.org/WAI/WCAG22/Techniques/general/G95)); image groups
([G196](https://www.w3.org/WAI/WCAG22/Techniques/general/G196)); media identification
([G100](https://www.w3.org/WAI/WCAG22/Techniques/general/G100), G68); tests, sensory items, CAPTCHA
([G143](https://www.w3.org/WAI/WCAG22/Techniques/general/G143),
[G144](https://www.w3.org/WAI/WCAG22/Techniques/general/G144)).

## Manual procedure

1. Inventory. Run in every state of the sample — the loaded page, the cookie dialog, an open menu,
   each carousel slide, an open modal, each tab panel, the search suggestions, the form's error
   state — and page to the foot first so lazy images load:
   ```bash
   agent-browser press End
   agent-browser wait 1000
   agent-browser press Home
   agent-browser eval --stdin < <skill-dir>/scripts/probes/images.js
   agent-browser eval --stdin < <skill-dir>/scripts/probes/media.js
   agent-browser eval --stdin < <skill-dir>/scripts/probes/links.js
   agent-browser snapshot
   ```
   Sort `images` into (a) `name` empty and `presentational` false, (b) `presentational` true, (c)
   named. Inside (a) and (b), keep `alt: null` (no `alt` attribute at all — F65 when informative,
   F38 when decorative) apart from `alt: ""` (deliberately marked decorative). Check the sort
   against `counts`: `counts.withoutAlt` is how many `img` carry no `alt` attribute,
   `counts.presentational` is the size of (b), and `counts.inControlsWithoutName` is how many image
   controls step 3 must take, whatever list they landed in. A `visible: false`
   item that belongs to another state is presented content: judge it in that state; one with `width`
   or `height` 0 in every state is "not presented to users". Done when every image, media item and
   image-only link is in one list and the seven rules' `incomplete` entries are taken from
   `.notes/audit/axe/<sample>[--<state>].json`.
2. Axe incompletes. For each `incomplete` node:
   ```bash
   agent-browser snapshot -s "<selector>"
   agent-browser get html "<selector>"
   agent-browser get attr "<selector>" alt
   ```
   Read the exposed role and name from the snapshot line and the attribute from `get attr` (selector
   first, then the attribute name). `aria-labelledby` to a missing or empty id, `alt=" "` (one
   space), `role="none"` on a focusable `img`: the name is empty; fail (95) when the image is
   informative, else step 4. A real name: list (c). Done when no `incomplete` node is unresolved.
3. Empty names outside axe's reach (ACT 23a2a8, 7d6734, e88epe, c487ae; F65, F3). Every `links.js`
   `emptyLinks` entry that contains an image, from any list: fail (95; ACT c487ae — "any HTML
   element that is an inheriting semantic link included in the accessibility tree" must have a
   non-empty name). Then take list (a) items of `kind` svg, canvas, area, object or css-background,
   plus list (a) items with `inLink` or `inButton` set and `controlText` empty. Icon fonts and
   CSS-inserted glyphs are in neither probe, so enumerate the pseudo-elements once per state:
   ```bash
   agent-browser eval --stdin <<'JS'
   (() => {
     const out = [];
     for (const el of document.querySelectorAll('body *')) {
       for (const pseudo of ['::before', '::after']) {
         const c = getComputedStyle(el, pseudo).content;
         if (!c || c === 'none' || c === 'normal' || /^"\s*"$/.test(c)) continue;
         out.push({
           tag: el.tagName, cls: el.className, pseudo, content: c,
           text: (el.textContent || '').trim().slice(0, 40),
           label: el.getAttribute('aria-label'), hidden: el.getAttribute('aria-hidden'),
         });
       }
     }
     return out;
   })()
   JS
   ```
   A `content` that is a glyph or a `url(...)` on an element whose `text` is empty and whose `label`
   is null is an unnamed icon. For every candidate:
   ```bash
   agent-browser scrollintoview "<selector>"
   agent-browser screenshot "<selector>" .notes/audit/evidence/<sample>--1.1.1--<n>.png
   ```
   It conveys information (a meaningful icon, a chart, a photo that is the subject, text in the
   image) missing from `nearbyText` and `figcaption`: fail (80; F3) for an unroled `svg`, `canvas`,
   `embed`, CSS background or icon-font glyph in `i`/`span` without text. Purely decorative: pass.
   `area` with `href` and no `alt`: fail (95; H24 is the fix). An `object` outside 8fc3b6's scope
   with no name and no fallback in its body (H53): fail (85). Done when every list (a) item and
   every unnamed pseudo-element icon has a verdict.
4. Decorative marking (ACT e88epe, 46ca7f; H67, C9). e88epe covers "any img, canvas or svg element
   that is visible" that is out of the accessibility tree, or is an `svg` with an empty name and
   role `graphics-document`, or a `canvas` with an empty name and no explicit role; it "never
   applies" to an element with "an ancestor in the flat tree that is named from author" or to an
   `img` "where the current request's state is not completely available" (a broken image). For each
   list (b) item with `width` and `height` above 0 (`visible` is false for anything under
   `aria-hidden`, the e88epe case) and not already scored in step 3, screenshot it as in step 3. It
   shows information `nearbyText`, `figcaption` and `controlText` lack (product photo, infographic,
   the site logo, a status icon): fail (80). The information is adjacent (icon before "PDF
   document", image beside text in one link, H2) or it is decoration: pass — e88epe's own note, "It
   is relatively common for an informative image such as an icon to be marked up as decorative, if
   the text alternative is adjacent to the image. This is a conforming alternative version for the
   image. This fails the rule but meets conformance requirement 1 of WCAG 2.2." Its selector is in
   `focusables.js` `order` or `get html` shows a global `aria-*` attribute, and `snapshot -s
"<selector>"` lists it as an unnamed `img`: fail (90; 46ca7f resolves the conflict by exposing
   the element, and "When these conflicts arise on decorative non-text content, this is also a
   failure of Success Criterion 1.1.1"). Done when every list (b) item has a verdict.
5. Descriptiveness (ACT qt1vmo — "an accessible name that serves an equivalent purpose to the
   non-text content of that test target";
   [G94](https://www.w3.org/WAI/WCAG22/Techniques/general/G94), G95; F30, F39, F13, F20, F67).
   qt1vmo skips an image under an ancestor "named from author" and a broken `img`. Resolve the
   associated text once per state, so an assembled name and a long description are read as the user
   gets them:
   ```bash
   agent-browser eval --stdin <<'JS'
   (() => {
     const text = (ids) => (ids || '').split(/\s+/).filter(Boolean)
       .map((i) => document.getElementById(i))
       .map((n) => (n ? (n.textContent || '').trim() : '[MISSING ID]'))
       .join(' ');
     const out = [];
     for (const el of document.querySelectorAll('img, svg, canvas, object, [role="img"]')) {
       out.push({
         tag: el.tagName.toLowerCase(),
         src: el.getAttribute('src') || el.getAttribute('data') || '',
         alt: el.getAttribute('alt'), title: el.getAttribute('title'),
         labelledby: text(el.getAttribute('aria-labelledby')),
         describedby: text(el.getAttribute('aria-describedby')),
         figcaption: (el.closest('figure')?.querySelector('figcaption')?.textContent || '').trim(),
         adjacentLink: (el.parentElement?.querySelector('a[href]')?.textContent || '').trim(),
       });
     }
     return out;
   })()
   JS
   ```
   `[MISSING ID]` in `labelledby` is the empty-name case of step 2; `describedby`, `figcaption` and
   `adjacentLink` hold the long description G92, G73 and G74 ask for. For each list (c) item compare
   `name` with what it shows and why it is there (`nearbyText`, `figcaption`, `inLink`). The purpose
   decides the wording, not the picture: W3C's same image of the world is "International Travel" on
   a travel site and "International Campuses" on a university site; a thumbnail of a newspaper front
   page linking to its home page is "Smallville Times"; a floor-plan image map is "Building floor
   plan. Select a room for more information."; a refreshing camera image is "traffic web camera"
   with the travel-time table beside it. For an image in a link or button, judge the control's whole
   name (`snapshot -s`) against the destination or action
   ([G82](https://www.w3.org/WAI/WCAG22/Techniques/general/G82),
   [H30](https://www.w3.org/WAI/WCAG22/Techniques/html/H30), H36,
   [ARIA9](https://www.w3.org/WAI/WCAG22/Techniques/aria/ARIA9) when the name is concatenated from
   several text nodes); a control named by its own `aria-label` puts the image out of scope.
   `nameSource` equal to `title`: 23a2a8 passes it and
   [H65](https://www.w3.org/WAI/WCAG22/Techniques/html/H65) allows `title` where a `label` cannot be
   used ([H44](https://www.w3.org/WAI/WCAG22/Techniques/html/H44) is the preferred fix for a form
   control), but tooltips are not reliably read; queue it (55) asking "is this title the intended
   alternative?" unless the same text is also in `nearbyText`. Fails: file name, path, "image",
   "photo" or placeholder (95; F30); `alt` "spacer", "image", "icon" or "picture" on an image that
   adds no information (90; F39), the same on an informative image (95; F30); describes a different
   image (85); text in the image missing from it (85; images of text go to 1.4.5); colour-coded
   information missing (80; F13); a chart with a short name and no long description in
   `aria-describedby`, `figcaption`, adjacent text or link (80; G95 with
   [G92](https://www.w3.org/WAI/WCAG22/Techniques/general/G92),
   [G73](https://www.w3.org/WAI/WCAG22/Techniques/general/G73),
   [G74](https://www.w3.org/WAI/WCAG22/Techniques/general/G74),
   [ARIA15](https://www.w3.org/WAI/WCAG22/Techniques/aria/ARIA15)); a long description that is
   present but drops the data, trend or implication the chart shows (75; F67); name no longer
   matches the state, e.g. a hard-coded rating or a play button that stays "Play" after it starts
   (75; F20). A group whose first image carries the group's alternative and the rest `alt=""` is
   correct (G196). W3C's chart example sets the bar for a long description: the short label is
   "Figure one - Sales in June, July and August", and the long one "identifies the type of chart,
   provides a high-level summary of the data, trends and implications comparable to those available
   from the chart. Where possible and practical, the actual data is provided in a table." Detail
   follows the context: the news photo of two leaders is "President X of Country X shakes hands with
   Prime Minister Y of country Y", while the same photo on a page about diplomatic nuance also
   describes "the room where the leaders are standing as well as the expressions on the leaders'
   faces" — an addition that "might be included on the same page as the photograph or in a separate
   file associated with the image through a link or other standard programmatic mechanism", so a
   linked description page counts and an unlinked one does not. An image whose full explanation is
   already in the running text needs only a brief description that points there: W3C's engine
   animation "is an alternative for text and the text alternative includes only a brief description
   of the animation and refers to the tutorial text for more information" — pass it, and record no
   missing long description. Done when every list (c) item has a verdict.
6. Emoji, emoticons, ASCII art, look-alike text (H86; F71, F72). `kind` emoji items pass when
   wrapped in `role="img"` with `aria-label` or when the Unicode name matches the meaning here. The
   snapshot flattens these into ordinary text, so scan the text nodes for the three patterns — ASCII
   art is "picture created by a spatial arrangement of characters or glyphs", leetspeak and
   look-alikes substitute characters:
   ```bash
   agent-browser eval --stdin <<'JS'
   (() => {
     const emoji = /\p{Extended_Pictographic}/u;
     const art = /[\u{2500}-\u{259F}\u{25A0}-\u{25FF}\u{2190}-\u{21FF}]/u;
     const look = /[\u{1D400}-\u{1D7FF}\u{24B6}-\u{24E9}\u{FF21}-\u{FF5A}]/u;
     const hits = [];
     const w = document.createTreeWalker(document.body, NodeFilter.SHOW_TEXT);
     for (let n = w.nextNode(); n; n = w.nextNode()) {
       const t = (n.nodeValue || '').trim();
       if (!t) continue;
       const el = n.parentElement;
       const pre = el.closest('pre, code') !== null;
       const kinds = [];
       if (emoji.test(t)) kinds.push('emoji');
       if (art.test(t) || (pre && t.includes('\n'))) kinds.push('ascii-art');
       if (look.test(t)) kinds.push('look-alike');
       if (!kinds.length) continue;
       hits.push({
         kinds, text: t.slice(0, 60), tag: el.tagName, role: el.getAttribute('role'),
         label: el.getAttribute('aria-label'), hidden: el.closest('[aria-hidden="true"]') !== null,
       });
     }
     return hits;
   })()
   JS
   ```
   A screen reader speaks these character by character or by Unicode name, which the snapshot cannot
   show: judge from the `text` sample and the surrounding sentence. ASCII art with no adjacent text
   alternative: fail (90; F72). Look-alike letters replacing a word: fail (85; F71). An emoticon or
   emoji replacing a word with no text nearby: fail (70). Done when every hit has a verdict.
7. Media, tests, sensory content, CAPTCHA (G100, G68, G143, G144). For each `media.js` item read the
   exposed name with `snapshot -s "<selector>"`, `textAlternativeNearby`, and the heading or link
   text before it in the snapshot; none of these says what the audio or video is: fail (80; G100).
   W3C's passing pattern is the speech recording whose link says "Chairman's speech to the
   assembly", where "A link to a text transcript is provided immediately after the link to the audio
   clip": the name identifies the recording and `textAlternativeNearby` holds the transcript link. A
   live audio-only or live video-only stream needs only "a descriptive label" (G68), but W3C puts
   the prerecorded ones under the general rule — "Note that prerecorded audio-only and prerecorded
   video-only files are covered here" — so they owe an equivalent alternative: record the missing
   identification here and the missing transcript or audio description under 1.2.1. An
   `animatedImages` entry that plays a sequence is a media item here; a short loop is an image (step
   5). Read live against prerecorded from `media.js`: an absent or infinite `duration` with a
   streaming manifest in `sources` (`.m3u8`, `.mpd`) or a provider live URL, confirmed by the page's
   own wording ("live", "livestream"); everything else is prerecorded and owes the full alternative
   of 1.2.x on top of the identification here. For each `structure.js` iframe whose `src` contains
   `captcha`:
   ```bash
   agent-browser frame "<iframe selector>"
   agent-browser snapshot
   agent-browser frame main
   ```
   Expect text that names the CAPTCHA and its purpose (G143) and a control that switches to an audio
   or other-modality version (G144); either one missing: fail (90). A quiz with image questions or a
   gallery of artworks needs only identification; missing: fail (75). For a sound cue, trigger the
   feedback (answer wrongly, then correctly), re-run `media.js` and read the text on screen at that
   moment: no message or status text saying what the sound says is a fail (70); a cue that cannot be
   tied to any visible text is `cannot-tell`, queued (55) as "does this sound carry information the
   screen does not show?". The `media` pass re-checks this step on every player it operates. Done
   when every media item, sound cue, test, sensory item and CAPTCHA has a verdict.
8. Record. For each fail, `highlight "<selector>"` then `screenshot` the page or element into
   `.notes/audit/evidence/`; note selector, `kind`, name, `nameSource`, verdict and certainty in the
   findings file. For an F20 state mismatch, capture the change itself:
   ```bash
   agent-browser record start .notes/audit/evidence/<sample>--1.1.1--<n>.webm
   agent-browser click "<the control that changes the image>"
   agent-browser record stop
   ```
   Record `cannot-tell` for an image that cannot be rendered (broken `src`, lazy load that never
   resolves, behind a login), for an `object` or PDF whose inner images cannot be inspected, or for
   content that needs domain expertise. Done when every verdict from steps 2–7 is in the findings
   file with its evidence path.

## Deciding

- Fail (certainty ≥ 90): any of the seven rules in violation (100); decorative `img` with no `alt`
  attribute (100 via axe; F38); `img`, `area`, `input type="image"` or `[role="img"]` with no name
  and no presentational role (95; F65); image button named the default, localised "Submit Query"
  (95; 59796f); `alt=" "` or `aria-labelledby` to a missing id on an informative image (95);
  image-only link with no name (95; c487ae); name that is a file name, a path or placeholder text
  (95; F30); decorative-marked image that is focusable or has global ARIA and is exposed as an
  unnamed `img` (90; 46ca7f); "spacer", "image" or "icon" as alt on a decorative image (90; F39);
  ASCII art with no text alternative (90; F72); image CAPTCHA with no purpose text or no other
  modality (90; G143, G144).
- Fail (70–89): name describes a different image (85; ACT qt1vmo); text in the image missing from
  the name (85); look-alike letters replacing words (85; F71); an `object` outside 8fc3b6's scope
  with neither a name nor fallback content in its body (85; H53); informative image marked
  decorative or `aria-hidden` (80; ACT e88epe); unroled `svg`, `canvas`, `embed`, CSS background or
  icon font that conveys information with no equivalent text (80; F3); chart or diagram with no long
  description (80; G95); colour-coded information missing from the name (80; F13); media element
  with no identification (80; G100); long description present but not presenting the same
  information (75; F67); name that no longer matches the image's state (75; F20); test or sensory
  item without identification (75); emoji or emoticon replacing a word (70); sound cue carrying
  information (right, wrong, error) with no message or status text saying the same (70).
- Needs confirmation (50–69): decorative or informative is not settled by the context (60): ask
  "does this image add information the text lacks?"; an emoji's Unicode name may not carry the
  intended meaning (60); a long description's completeness or a domain diagram's equivalence (60;
  F67); test or sensory item or not (60); an alternative written in a language other than the
  content's (60) — W3C: "Text alternatives and equivalents should match the human language of the
  original content (normally the default human language of the page)" — ask whether the page
  language or the alt text is wrong; a `title`-only name (55); an `object` or PDF whose inner images
  cannot be inspected (50; [PDF1](https://www.w3.org/WAI/WCAG22/Techniques/pdf/PDF1),
  [PDF4](https://www.w3.org/WAI/WCAG22/Techniques/pdf/PDF4)).
- Pass: every non-text item in any state has a name serving the equivalent purpose in its context
  (controls: the purpose; media, tests, sensory content: identification; CAPTCHA: identifying and
  purpose-describing text plus another modality) or is ignorable by AT; no axe violation.
- Not present: no image, SVG, canvas, image control, media, CAPTCHA, emoji or ASCII art anywhere.
- False positives to avoid: `alt=""` on an image whose information is in the adjacent text (icon
  before "PDF document", image beside text in one link,
  [H2](https://www.w3.org/WAI/WCAG22/Techniques/html/H2)) is correct although ACT e88epe reports it;
  an image inside a control named by `aria-label` (e88epe and qt1vmo both exclude an ancestor "named
  from author"); images hidden in every state; broken images; alt that repeats the caption; a
  `title` attribute supplies a name (ACT 23a2a8 passes it); the first image of a group carrying the
  whole group's alternative (G196); a `canvas` or `svg` that only paints a background.

## Reporting

- File under: 1.1.1 for `img`, `area`, `input type="image"`, `[role="img"]`, roled `svg`, `object`,
  CSS background images, emoji and ASCII art, decorative-marking mistakes and image-only links
  (2.4.4 and 4.1.2 are related). Under 4.1.2 when an icon-only `button` with an unroled `svg`, icon
  font or CSS background has no name; under 1.2.x for transcripts, audio description and captions;
  under 1.4.5 for images of text with a correct alternative; under 1.4.1 when only colour is
  missing. One issue per distinct defect; a repeat on other samples is one issue that names those
  samples.
- Title patterns: "Image without text alternative", "Alt text is the file name", "Informative image
  hidden from screen readers", "Chart has no text description", "Image button has no name",
  "Icon-only link has no name", "Decorative image is announced as 'image'", "CAPTCHA has no audio
  alternative", "Video is not identified in text", "Alt text no longer matches the image".
- Severity: High when the image carries information or a function nothing else provides, so the task
  stops or the content is lost for screen reader users — image-only navigation, an unnamed image
  button, a chart, a CAPTCHA with a single modality. Medium when the information is partly available
  elsewhere or the defect repeats across the product and slows every page — site-wide icons, file
  names as alt in a gallery, a photo whose caption carries most of the meaning. Low when the only
  effect is noise with an easy workaround — a decorative image announced as "image", a redundant alt
  repeating the adjacent text.
- Type: Content when the `alt` attribute exists and its text is wrong, generic, a file name or empty
  on an informative image (an editor fixes it in the CMS); Technical when markup is missing or wrong
  (no `alt`, no `role`, CSS background, `svg` without role, image map, CAPTCHA, emoji).
- Evidence: the page screenshot with the image drawn by `highlight`, or the element screenshot when
  the image is small; add the `snapshot -s "<selector>"` line or the `get html` fragment to the body
  when the defect is invisible on screen (an empty `alt`, an `aria-hidden` icon); for F20 (state not
  updated) a screenshot of each state or a GIF; for a CAPTCHA a shot of the whole widget showing
  which modality switches exist.
- Recommendation: give the alt text to use, in the report's language, and cite the technique for the
  element at hand — [H37](https://www.w3.org/WAI/WCAG22/Techniques/html/H37) for `img`,
  [ARIA6](https://www.w3.org/WAI/WCAG22/Techniques/aria/ARIA6) or
  [ARIA10](https://www.w3.org/WAI/WCAG22/Techniques/aria/ARIA10) for `svg`, `[role="img"]` and
  `canvas`, [H36](https://www.w3.org/WAI/WCAG22/Techniques/html/H36) for image buttons,
  [H24](https://www.w3.org/WAI/WCAG22/Techniques/html/H24) for `area`,
  [H53](https://www.w3.org/WAI/WCAG22/Techniques/html/H53) for `object` fallback content,
  [H67](https://www.w3.org/WAI/WCAG22/Techniques/html/H67) and
  [C9](https://www.w3.org/WAI/WCAG22/Techniques/css/C9) for decorative images,
  [C18](https://www.w3.org/WAI/WCAG22/Techniques/css/C18) for spacer images,
  [H86](https://www.w3.org/WAI/WCAG22/Techniques/html/H86) for emoji and ASCII art,
  [G95](https://www.w3.org/WAI/WCAG22/Techniques/general/G95) with G92/G73/G74/ARIA15 for charts,
  [G143](https://www.w3.org/WAI/WCAG22/Techniques/general/G143) and
  [G144](https://www.w3.org/WAI/WCAG22/Techniques/general/G144) for CAPTCHA,
  [G100](https://www.w3.org/WAI/WCAG22/Techniques/general/G100) for media identification. Show the
  fix as markup:
  ```html
  <!-- informative image: the alternative says what it conveys here (H37) -->
  <img src="chart.png" alt="Sales per quarter 2024, described below" />
  <!-- decorative image: empty alt, no title (H67) -->
  <img src="swirl.png" alt="" />
  <!-- icon-only control: the control carries the name, the icon is hidden (ARIA6) -->
  <button type="button" aria-label="Search">
    <svg aria-hidden="true" focusable="false">...</svg>
  </button>
  <!-- image submit button (H36) and image map area (H24) -->
  <input type="image" src="search.png" alt="Search" />
  <area shape="rect" coords="0,0,100,50" href="/kitchen" alt="Kitchen" />
  <!-- chart: short name plus a programmatically associated description (G95, ARIA15) -->
  <figure>
    <img src="chart.png" alt="Bar chart, sales per quarter 2024" aria-describedby="chart-desc" />
    <figcaption id="chart-desc">Q1 ... Q4 ... with the table below</figcaption>
  </figure>
  <!-- emoji standing in for a word (H86) -->
  <span role="img" aria-label="party popper">&#127881;</span>
  ```
  For a CSS background that carries meaning, move the image into an `img` with an `alt`, or add
  visible text and keep the background decorative (F3, C9). For a CAPTCHA, ask for a second modality
  and, beyond the minimum, W3C's further steps: "Providing more than two modalities of CAPTCHAs",
  "Providing access to a human customer service representative who can bypass CAPTCHA", "Not
  requiring CAPTCHAs for authorized users".
