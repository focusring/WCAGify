# 2.2.2 Pause, Stop, Hide

Level A · WCAG 2.0+ · Guideline 2.2 Enough Time · Group: `motion`

Sources: [Understanding](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html)
· [Spec](https://www.w3.org/TR/WCAG22/#pause-stop-hide)
· [Techniques](https://www.w3.org/WAI/WCAG22/quickref/#pause-stop-hide)
· [Plain English](https://aaardvarkaccessibility.com/wcag-plain-english/2-2-2-pause-stop-hide/)
· ACT: [efbfc7](https://www.w3.org/WAI/standards-guidelines/act/rules/efbfc7/) (Proposed)

## Requirement

> For moving, blinking, scrolling, or auto-updating information, all of the following are true:
>
> - Moving, blinking, scrolling: For any moving, blinking or scrolling information that (1) starts
>   automatically, (2) lasts more than five seconds, and (3) is presented in parallel with other
>   content, there is a mechanism for the user to pause, stop, or hide it unless the movement,
>   blinking, or scrolling is part of an activity where it is essential; and
> - Auto-updating: For any auto-updating information that (1) starts automatically and (2) is
>   presented in parallel with other content, there is a mechanism for the user to pause, stop, or
>   hide it or to control the frequency of the update unless the auto-updating is part of an
>   activity where it is essential.
>
> Note 1: For requirements related to flickering or flashing content, refer to Guideline 2.3.
>
> Note 2: Since any content that does not meet this success criterion can interfere with a user's
> ability to use the whole page, all content on the web page (whether it is used to meet other
> success criteria or not) must meet this success criterion. See Conformance Requirement 5:
> Non-Interference.
>
> Note 3: Content that is updated periodically by software or that is streamed to the user agent
> is not required to preserve or present information that is generated or received between the
> initiation of the pause and resuming presentation, as this may not be technically possible, and
> in many situations could be misleading to do so.
>
> Note 4: An animation that occurs as part of a preload phase or similar situation can be
> considered essential if interaction cannot occur during that phase for all users and if not
> indicating progress could confuse users or cause them to think that content was frozen or
> broken.

Terms (WCAG 2.2 glossary): **blinking**: "switch back and forth between two visual states in a way
that is meant to draw attention", with the note "See also flash. It is possible for something to be
large enough and blink brightly enough at the right frequency to be also classified as a flash" —
blinking above 3 per second is also a flash and is judged under 2.3.1 as well. **mechanism**:
"process or technique for achieving a result"; Note 1: "The mechanism may be explicitly provided in
the content, or may be relied upon to be provided by either the platform or by user agents,
including assistive technologies"; Note 2: "The mechanism needs to meet all success criteria for the
conformance level claimed" — Note 1 is what puts an operating-system or browser setting in play at
all, Note 2 is what makes an unnamed or keyboard-unreachable pause button a failure of this
criterion and not only of 4.1.2 or 2.1.1. **paused** (`dfn-pause`): "stopped by user request and not
resumed until requested by user" — content that restarts on its own, or the moment focus moves away,
was never paused. **essential**: "if removed, would fundamentally change the information or
functionality of the content, **and** information and functionality cannot be achieved in another
way that would conform" — both halves must hold.

## In plain terms

W3C states the goal as "Fewer users are distracted by content that updates or moves" and the job as
"Let users control content changes that occur in parallel with other content". Anything that moves,
blinks, scrolls or changes by itself beside other content needs a control to pause, stop or hide it;
auto-updating content may instead offer a setting for the update frequency. Motion that ends within
5 seconds is fine — "Five seconds was chosen because it is long enough to get a user's attention,
but not so long that a user cannot wait out the distraction if necessary to use the page" — while
auto-updating text has no grace period; hover, focus and scroll triggers still count as "starts
automatically". It matters for people with attention deficits and cognitive disabilities, for anyone
"who has trouble reading stationary text quickly as well as anyone who has trouble tracking moving
objects", and for screen reader users whom the updates keep interrupting.

## Applies when

- Present: content that starts on its own beside other content. W3C scopes the two halves: "'Moving,
  blinking and scrolling' refers to content in which the visible content conveys a sense of motion",
  the common cases being "motion pictures, synchronized media presentations, animations, real-time
  games, and scrolling stock tickers"; "'Auto-updating' refers to content that updates or disappears
  based on a preset time interval", the common cases being "automatically updated weather
  information, news, stock price updates, and auto-advancing presentations and messages". Motion
  enters scope only once it lasts more than five seconds; auto-updating has no five-second
  exception, and "or disappears" puts a message that vanishes on a timer in scope. Detect:
  - Moving or scrolling: an auto-advancing carousel (`motion.js` `carousels[]` with `autoAdvances`
    true); a `<marquee>` or `role="marquee"` ticker (`marquee` > 0 counts both); a `running`
    `animations[]` entry with `iterations` `'infinite'` or `duration` × `iterations` above 5000 ms;
    an animated GIF, APNG or WebP (`media.js` `animatedImages[]`); an autoplaying video, muted or
    not (`media[]` with `autoplay` true and `loop` true or `duration` > 5); canvas, WebGL and SVG
    motion, which only a screenshot pair or a recording reveals.
  - Blinking: `<blink>` or `text-decoration: blink` (`blink` > 0 counts both) or a script toggling
    visibility, opacity or colour. A colour or opacity toggle changes no text, so `get text` and ACT
    efbfc7 both miss it (efbfc7 Inapplicable Example 3: "This span element changes color but not its
    innerText property") — the screenshot pair and the recording carry that case.
  - Auto-updating: text that changes on a timer — tickers, live scores, clocks, countdowns, feeds,
    vanishing messages (`autoUpdating[]`; `structure.js` `liveRegions[]` names the ones that are
    announced as well, which are also 4.1.3 candidates).
  - Probe limits to close in step 1 and step 2: `autoUpdating[]` only lists a host that mutated
    three or more times inside the probe's five-second window (`changesIn5s` >= 3) and caps at 20
    entries, so a feed on a 10-second or 60-second timer is absent from it; `animatedImages[]`
    matches on the `.gif`, `.apng` and `.webp` file extension, so a still GIF is listed and an
    animation served from an extensionless URL or from a CSS background is not; `marquee` and
    `blink` are counts with no selectors; `media[]` only holds an `<iframe>`, `<embed>` or
    `<object>` whose `src` names a known provider, so a generic animated third-party frame is
    missing; `counts.autoplaying` excludes muted videos, so read `media[].autoplay` itself.
  - Starts automatically, verbatim: "Moving, blinking, scrolling, auto-updating content is
    considered to start automatically either when it starts without direct user activation or
    interaction (such as activating a button), or when it starts as a result of an indirect
    interaction (such as focusing/hovering over an element, or scrolling an element into view).
    Content that starts automatically from an indirect interaction also potentially fails 2.3.3
    Animation from Interactions."
  - ACT efbfc7 applies to "any HTML element that has a visible text node as a descendant in the flat
    tree" for which all three hold: "changed: the innerText property of the element changes multiple
    times within a 10 minute time span where there is no user interaction"; "no child changed: the
    element does not have children in the flat tree whose innerText property also changes"; "not
    alone: the element has an ancestor element in the flat tree with a non-empty innerText property
    whose value is different from the innerText of the test target". "No child changed" fixes the
    target at the innermost changing element — report that selector, not its container. "Not alone"
    is the criterion's "in parallel with other content". Note 2 makes the whole criterion a
    non-interference requirement, so every piece of content on the page is in scope: advertisements,
    third-party embeds, and content that only exists to satisfy some other criterion.
- Not present: in every state, no `running` animation outlasts 5 seconds, `marquee` and `blink` are
  0, `autoUpdating[]` is empty, the step 2 sampler returns `[]` on both comparisons and
  slow-changing text is unchanged after a minute, no carousel has `autoAdvances` true, no video or
  embed in `media[]` autoplays, every animated image stops within 5 seconds, and screenshots 5
  seconds apart match. An ACT `inapplicable` or `passed` outcome alone does not carry this: efbfc7
  maps both to "success criterion needs further testing", and its own background adds that "Content
  that changes less frequently may fail success criteria 2.2.2 without failing this rule".
- Exceptions: "part of an activity where it is essential" on both halves of the glossary test: a
  real-time game (W3C's counter-example is "A game is designed so that users take turns rather than
  competing in real-time" — "One party can pause the game without invalidating the competitive
  aspect of it"), a live clock in that game, a demonstration the page exists to show (and even then
  W3C's example "An essential animation can be paused without affecting the activity" gives the
  animations "pause" and "restart" buttons). A preload animation "if interaction cannot occur during
  that phase for all users" (Note 4), where W3C's loading example turns on "The animation is the
  only content on the page" — a spinner drawn over a page the visitor can still read is in parallel
  and is not excepted. Not "in parallel with other content": the same preloader, and a forced
  full-page advertisement — "A site requires that all users view a 15 second advertisement before
  they can access free content ... Because viewing the advertisement is a requirement for all users
  and because it is not presented in parallel with other content, no mechanism to pause, stop or
  hide it needs to be provided." Motion that ends within 5 seconds
  ([G11](https://www.w3.org/WAI/WCAG22/Techniques/general/G11),
  [SCR22](https://www.w3.org/WAI/WCAG22/Techniques/client-side-script/SCR22),
  [G152](https://www.w3.org/WAI/WCAG22/Techniques/general/G152)); "there is no five second exception
  for auto-updating since it makes little sense to auto-update for a few seconds and then stop"
  (Understanding). Content the visitor started by activating a link or button is not automatic
  (efbfc7 Inapplicable Example 4: a span that changes "only as a result of the user activating a
  button on the page"). Content that also flashes goes to 2.3.1 and, at AAA, 2.3.2 (Note 1); sound
  that starts by itself is 1.4.2 — "This success criterion is specifically concerned with moving,
  blinking, scrolling, and auto-updating visual content"; a timed page reload is 2.2.1.

## axe-core

| Rule      | Decides                                    | Result → outcome       |
| --------- | ------------------------------------------ | ---------------------- |
| `blink`   | a `<blink>` element is visible on screen   | violation → fail (100) |
| `marquee` | a `<marquee>` element is visible on screen | violation → fail (100) |

Both are in the WCAG 2.0 A & AA rule set, on by default, `failure` only, impact serious. Both match
the element name alone (`selector: "blink"`, `selector: "marquee"`), not the behaviour, so the
violation stands on the markup even though Chromium no longer animates either. Both run with
`excludeHidden: false` and a single `none: ["is-on-screen"]` check: an element that is `display:
none`, `visibility: hidden` or positioned off the document is reported as a **pass**, not a
violation, while one merely below the fold is still flagged. `role="marquee"` is outside the
`marquee` selector.

Settles: `<blink>` and `<marquee>` on screen when axe ran. Leaves open: everything else — either
element while hidden; `role="marquee"`, `role="timer"`, `text-decoration: blink` and scripted
tickers; CSS, web-animation, SVG, canvas and image animations; autoplaying video and embedded
players; carousels; auto-updating text, live regions and feeds; vanishing messages; hover, focus and
scroll starts; every state other than the one axe ran in; and, for every one of them, whether a
working, visible, named, keyboard-reachable control exists that keeps the content stopped.

## Manual procedure

Steps 1 to 4 run in the initial state, step 5 in the other states of `recon/<sample>-states.md`,
step 6 per fail. Do not click or hover during step 1 and step 2: efbfc7 applicability requires the
changes to happen "where there is no user interaction".

1. Inventory. Wait, screenshot, run the probes (`motion.js` watches 5 seconds), screenshot again:

   ```bash
   agent-browser wait --load networkidle
   agent-browser screenshot .notes/audit/evidence/<sample>-motion-t0.png --full
   agent-browser eval --stdin < <skill-dir>/scripts/probes/motion.js
   agent-browser screenshot .notes/audit/evidence/<sample>-motion-t5.png --full
   agent-browser eval --stdin < <skill-dir>/scripts/probes/media.js
   ```

   Candidates: every `running` `animations[]` entry with `iterations` `'infinite'` or `duration` ×
   `iterations` above 5000; `marquee` > 0 and `blink` > 0; every `autoUpdating[]` entry; every
   `carousels[]` entry with `autoAdvances` true; every `media[]` entry with `autoplay` true and
   `loop` true or `duration` > 5 or null; every `animatedImages[]` entry; every region that differs
   between the two screenshots. `metaRefresh` non-null belongs to 2.2.1, not here.

   `marquee`, `blink` and CSS background animations arrive as bare counts or not at all, so name
   them:

   ```bash
   agent-browser eval --stdin <<'EOF'
   (() => { const sel = (e) => (e.id ? '#' + e.id : [e.localName, ...e.classList].join('.'));
   const out = [];
   for (const e of document.querySelectorAll('marquee, blink, [role="marquee"], [role="timer"]'))
     out.push({ selector: sel(e), kind: e.localName + '/' + (e.getAttribute('role') || '-'),
       onScreen: e.getClientRects().length > 0 && getComputedStyle(e).visibility === 'visible' });
   for (const e of document.querySelectorAll('body *')) {
     const s = getComputedStyle(e);
     if (s.textDecorationLine.includes('blink'))
       out.push({ selector: sel(e), kind: 'blink-style' });
     if (s.animationIterationCount.split(', ').includes('infinite'))
       out.push({ selector: sel(e), kind: 'css-infinite', name: s.animationName,
         state: s.animationPlayState });
     if (/\.(?:gif|apng|webp)/i.test(s.backgroundImage))
       out.push({ selector: sel(e), kind: 'css-background', src: s.backgroundImage.slice(0, 80) });
   }
   return out; })()
   EOF
   ```

   An `onScreen` false entry is the axe pass that this criterion still has to judge in the state
   that reveals it (step 5). For an image, a canvas or a screenshot-only region, record it and watch
   past the five-second line:

   ```bash
   agent-browser record start .notes/audit/evidence/<sample>-motion.webm
   agent-browser wait 7000
   agent-browser record stop
   ```

   An `animatedImages[]` entry that does not move in the recording is a still GIF or WebP matched on
   its file extension: drop it with that reason. Done when each candidate is in the findings file
   with selector, kind and observed duration.

2. Text changes over a long span (ACT efbfc7 applicability). `motion.js` only reports a host that
   mutated three or more times in five seconds, so sample `innerText` directly and apply the rule's
   three conditions — changed, no child changed, not alone:

   ```bash
   cat > .notes/audit/2.2.2-text-changes.js <<'EOF'
   (() => { const sel = (e) => (e.id ? '#' + e.id : [e.localName, ...e.classList].join('.'));
   const vis = (e) => { const r = e.getBoundingClientRect();
     return r.width > 0 && r.height > 0 && getComputedStyle(e).visibility !== 'hidden' };
   const text = (e) => e.innerText.replace(/\s+/g, ' ').trim();
   const now = new Map();
   for (const el of document.querySelectorAll('body *'))
     if (vis(el) && [...el.childNodes].some((n) => n.nodeType === 3 && n.data.trim()))
       now.set(el, text(el));
   const before = window.__t222;
   window.__t222 = now;
   if (!before) return { baseline: now.size };
   const changed = new Map([...now].filter(([el, t]) => before.has(el) && before.get(el) !== t));
   return [...changed]
     .filter(([el]) => ![...changed.keys()].some((o) => o !== el && el.contains(o)))
     .filter(([el]) => { let p = el.parentElement;
       while (p) { const t = text(p); if (t && t !== now.get(el)) return true; p = p.parentElement }
       return false })
     .map(([el, t]) => ({ selector: sel(el), was: before.get(el).slice(0, 60),
       now: t.slice(0, 60) })); })()
   EOF
   agent-browser eval --stdin < .notes/audit/2.2.2-text-changes.js
   agent-browser wait 30000
   agent-browser eval --stdin < .notes/audit/2.2.2-text-changes.js
   agent-browser wait 30000
   agent-browser eval --stdin < .notes/audit/2.2.2-text-changes.js
   ```

   The first run returns `{ baseline: n }`; each later run returns the targets that changed since
   the previous one, already filtered to the innermost changed element (no child changed) and to
   elements that have an ancestor carrying other text (not alone). A selector that appears in both
   comparisons has "changed multiple times" and is applicable; one that appears once is a single
   change — extend with `agent-browser wait 60000` and another run, up to the rule's 10-minute span,
   for text the recon calls slow-changing (weather, stock, scores, a queue position). The baseline
   lives in `window.__t222`, which any `reload`, `back`, `forward` or navigation clears: re-run the
   baseline after each. A target whose node is replaced rather than re-texted loses its identity and
   drops out of the map; for such a region run `get text "<selector>"` twice, 5 seconds apart, and
   compare by hand. Done when every applicable text target is in the findings file with its
   selector, the two values, and how many changes were seen in what span.

3. Classification. Drop, with the reason, a candidate that stops by itself within 5 seconds (motion
   only, never auto-updating); that is alone on screen (a preloader, a forced interstitial); that
   started only after the visitor activated a link or button; or that is essential on both halves of
   the glossary test (a live game clock). A spinner or progress indicator drawn over content that is
   still readable stays a candidate: Note 4 excepts it only when "interaction cannot occur during
   that phase for all users". Done when each candidate is applicable, dropped or `cannot-tell`.

4. The mechanism (ACT efbfc7; [G186](https://www.w3.org/WAI/WCAG22/Techniques/general/G186)). The
   Expectation, in full: "For each test target there is at least one set of instruments, where each
   instrument is in the same web page as the test target or can be found in a clearly labeled
   location from that web page, to achieve at least one of the following objectives: pause and
   resume the change of the visible text content; or stop the change of the visible text content; or
   hide the changing visible text content; or control the frequency of the changes of the visible
   text content." Any one of the four objectives satisfies it, and "If there is more than one test
   target, the same instrument may be used to pause (or stop, or hide or alter the frequency) of
   several or even all test targets" — one page-wide control for every moving region is a pass.

   Search `snapshot -i` for a button, link, switch or checkbox named for pause, stop, play, hide,
   close, "autoplay" or update frequency; `carousels[].pauseControl` names a candidate, but that
   search runs inside the carousel element only and matches `pause|play|stop` in the text, the
   `aria-label` or the class name, so a `null` may still have a page-wide control elsewhere and a
   hit may be a "Play" button that only starts it. A `<video>` with `controls` true has one. Operate
   it, re-run the probe, move focus away, re-run:

   ```bash
   agent-browser find role button click --name "Pause"
   agent-browser eval --stdin < <skill-dir>/scripts/probes/motion.js
   agent-browser press Tab
   agent-browser wait 5000
   agent-browser eval --stdin < <skill-dir>/scripts/probes/motion.js
   ```

   The control counts when, in both re-runs, the candidate is gone from `autoUpdating[]`, its
   `animations[]` entry reads `playState` `paused` or is absent, or `carousels[].autoAdvances` is
   false; for a hide control, `is visible "<css>"` returns false; for a frequency control, the step
   2 sampler shows the slower interval; for motion only a screenshot pair reveals, two screenshots 5
   seconds apart now match. Either resume behaviour passes — "Content that is paused can either
   resume in real-time or continue playing from the point in the presentation where the user left
   off" — and Note 3 relieves the author of preserving what arrived while paused; hiding is equally
   good, "Hiding content would have the same result as pausing and jumping to current display".

   What must not happen is the control tying the user down: "For a mechanism to be considered 'a
   mechanism for the user to pause,' it must provide the user with a means to pause that does not
   tie up the user or the focus so that the page cannot be used. The word 'pause' here is meant in
   the sense of a 'pause button' although other mechanisms than a button can be used. Having an
   animation stop only so long as a user has focus on it (where it restarts as soon as the user
   moves the focus away) would not be considered a 'mechanism for the user to pause' because it
   makes the page unusable in the process." A ticker that only pauses while the pointer rests on it
   fails for the same reason; test it with `hover "<css>"`, then `mouse move 5 5`, then re-run the
   probe.

   Then confirm the control itself meets level A, which the rule leaves out — "The instruments used
   to pass this rule (if any), must meet all level A Success Criteria in order to fully satisfy
   Success Criterion 2.2.2: Pause, Stop, Hide. These extra requirements are left out of this rule,
   and should be tested separately":

   ```bash
   agent-browser eval --stdin < <skill-dir>/scripts/probes/focusables.js
   agent-browser focus "<css>"
   agent-browser press Enter
   ```

   The control's `order[]` entry must read `visible` true, a non-empty `name`, `inAriaHidden` false
   and `obscured` false (glossary "mechanism" Note 2), and `press Enter` or `press Space` must do
   what the click did. A control on another page or behind another control counts when it is at "a
   clearly labeled location": "The location of a target is said to be clearly labeled when the
   target can be found by activating 'identifiable' instruments which either lead the user to find
   the target, or to another page or page state from which this action can be repeated until the
   target is found" — a "Control changes" button that opens a dialog holding Pause and Hide is such
   a location (efbfc7 Passed Example 5), and "a web page changes state when the document's body
   changes without a change in the document's URL". An embedded player is part of the same web page,
   which efbfc7 defines as "the set of all fully active documents which share the same top-level
   browsing context": `frame @eN`, `snapshot -i`, find and operate the player's pause button, `frame
main`. Done when each candidate has a verified control or a fail indicator.

5. Other states, indirect starts, reduced motion. Repeat steps 1 to 4 after closing the cookie
   dialog, in each open menu and dialog, and after `scroll down 800` repeated to the page end —
   efbfc7 counts content as visible when it "can be brought into the viewport via scrolling", and a
   hidden `<blink>` or `<marquee>` that axe passed may become a violation in the state that shows
   it. Then `hover` each card, teaser and hero, `wait 6000`, re-run `motion.js`, `reload`: motion
   that starts on hover, focus or scrolling into view "starts automatically" (Understanding); note
   it for 2.3.3 too. Last:

   ```bash
   agent-browser set media reduced-motion
   agent-browser reload
   agent-browser eval --stdin < <skill-dir>/scripts/probes/motion.js
   agent-browser set media
   agent-browser reload
   ```

   Read `reducedMotionActive` true first, to confirm the emulation took. A candidate that disappears
   only here has at most a platform mechanism (glossary "mechanism" Note 1), and efbfc7 makes the
   same reservation: "If there are other ways to control the automatically changing content that do
   not require the user to interact with the web page, failing this rule might not be a failure of
   the success criterion" — record it for the confirmation queue rather than as a fail.
   `reducedMotionQueryUsed` false is not proof that no such rule exists: the probe cannot read
   cross-origin stylesheets and swallows that error. Done when every state, every indirect start and
   this result are noted.

6. Evidence. `highlight "<css>"` then `screenshot <path>` where a control is missing or hidden; the
   step 1 recording for movement; the t0 and t5 screenshots, or the two `was`/`now` values from step
   2, for auto-updating text; a recording of click, `press Tab` and resume for a focus-tied pause.
   Done when each fail has one.

## Deciding

- Fail (certainty ≥ 90): an axe `blink` or `marquee` violation — 100. A `role="marquee"` or scripted
  ticker scrolling past 5 seconds beside other content with no pause or stop control
  ([F16](https://www.w3.org/WAI/WCAG22/Techniques/failures/F16)) — 95. A carousel with
  `autoAdvances` true, `pauseControl` null and no pause, stop or autoplay control anywhere on the
  page — 95. A text target the step 2 sampler returns in both comparisons, beside other content,
  with no instrument on the page or at a clearly labelled location for any of efbfc7's four
  objectives (the rule's Failed Example 1) — 95. A `running` animation with `iterations`
  `'infinite'` beside other content, no control, and neither a preloader alone on screen nor a
  spinner for a request in flight — 90. A video that is `playing` with `loop` true or `duration` >
  5, `controls` false and no pause button — 90. A control after which the content resumes once focus
  leaves or within the 5-second wait, so it was never "stopped by user request and not resumed until
  requested by user" — 90.
- Fail (70–89): blinking that keeps toggling after 5 seconds with no stop
  ([F112](https://www.w3.org/WAI/WCAG22/Techniques/failures/F112) for markup or images,
  [F50](https://www.w3.org/WAI/WCAG22/Techniques/failures/F50) for script,
  [F7](https://www.w3.org/WAI/WCAG22/Techniques/failures/F7) for an `<object>` or plug-in) — 85. An
  animated image or screenshot-only motion confirmed by the recording to still move after 5 seconds,
  no control — 85. Content that stops only while the pointer hovers it or while focus rests on it,
  which "ties up the user or the focus so that the page cannot be used" — 85. A working control that
  `press Enter` and `press Space` do not operate, or whose `order[]` entry is missing (the mechanism
  must itself meet every level A criterion) — 85. Motion started by hover, focus or scrolling into
  view that runs past 5 seconds, no control — 80. A control that works but reads `visible` false,
  `inAriaHidden` true or `obscured` true, or appears only on hover — 80. A message carrying
  information that vanishes on a timer with no way to keep it — 75. A working control whose `name`
  is empty — 75.
- Needs confirmation (50–69): motion that stops only under `set media reduced-motion` — 60; ask
  whether the audit accepts the operating-system setting as the mechanism. An animation the author
  could call essential (a progress indicator while the page is usable, a demonstration the page is
  about) — 60; ask whether removing it "would fundamentally change the information or functionality"
  and whether it can be achieved another way that conforms. A control only on another page reached
  through a labelled link — 60; ask whether it governs this page. A video with `duration` null,
  `playing` false, or an embed whose player the frame cannot read — 55; ask how long it moves. A
  text target seen changing only once in ten minutes — 55; efbfc7's 10-minute span "is arbitrary ...
  not included in WCAG" and slower content "may fail success criteria 2.2.2 without failing this
  rule"; ask how often it updates in production. A changing spinner that carries no information —
  50, per efbfc7's assumption that "If the automatically changing content is not information ... the
  rule might fail but the success criterion might still be satisfied".
- Pass: every applicable item ends by itself within 5 seconds (motion only), or has a visible,
  named, keyboard-operable control on the page or at a clearly labelled location that achieves one
  of efbfc7's four objectives — pause and resume, stop, hide, or control the frequency — and keeps
  the content stopped after focus and pointer move away.
- Not present: nothing in any state moves, blinks or scrolls past 5 seconds, or changes on a timer.
- False positives to avoid: a `css-transition`, a finite animation of 5000 ms or less, or one whose
  `playState` is `paused`; a live region that changes only after the visitor acts; a spinner for a
  request the visitor triggered; a preloader alone on screen; a video the visitor started; a
  carousel that advances only on "Next"; `metaRefresh` (2.2.1); `<blink>` looking static (axe still
  fails). A control that jumps to the current display on resume instead of continuing where it
  stopped is correct for real-time content, and Note 3 excuses the content generated while paused.
  Hiding satisfies the criterion as fully as pausing. Separate controls per region are a pass:
  "While having separate controls for each of the elements does satisfy the normative requirements
  of this success criterion", the single page-wide control is only a best practice. A control placed
  below or beside the content rather than adjacent to it is a pass — W3C's example is "a 'freeze
  animation' button near the bottom of the animation". Blinking that stops by itself within 5
  seconds passes, including W3C's blinking advertisement and the arrow that blinks near an
  unsubmitted submit button. An `animatedImages[]` entry matched only on its file extension is not
  motion until the recording shows it.

## Reporting

- File under: 2.2.2 for content that moves, blinks, scrolls or updates without a working pause, stop
  or hide control, and for a control that ties up focus or the pointer or lets the content resume by
  itself. The same video's sound is a separate 1.4.2 issue; a flash faster than 3 per second is
  2.3.1 (and 2.3.2 if the audit targets AAA); hover- or scroll-started motion also gets a 2.3.3
  issue; a timed page reload is 2.2.1; an unnamed control is 4.1.2, one the keyboard cannot reach
  2.1.1. The same carousel or ticker on several samples is one issue that names the other samples.
- Title patterns: "Home page carousel advances by itself and cannot be paused", "News ticker scrolls
  continuously without a stop control", "Hero video loops without a pause button", "Live results
  update every few seconds with no way to stop them", "Pause button only holds the slider while it
  has focus", "Notification disappears before it can be read".
- Severity: High when the content fills a main part of the viewport, sits beside the primary task,
  or keeps re-announcing in a screen reader. Medium when the region is small or peripheral (a
  sidebar ticker, a looping GIF), or the only working control is hidden until hover. Low when the
  motion is a small ornament outside the reading area.
- Type: Technical: add the control, stop the timer, honour `prefers-reduced-motion`; also for a
  hidden or unnamed control. Design when the perpetual motion is a design decision (looping hero
  video). Content when an editor uploaded an animated image or switched autoplay on in the CMS.
- Evidence: the `.webm` recording of the movement with the region highlighted; for auto-updating
  text, the two screenshots a few seconds apart, with the old and new value quoted in the issue
  text; for a focus-tied pause, a GIF of click, Tab and resume.
- Recommendation: add a visible, keyboard-operable control beside the content that keeps it stopped
  until the visitor restarts it ([G186](https://www.w3.org/WAI/WCAG22/Techniques/general/G186),
  [G4](https://www.w3.org/WAI/WCAG22/Techniques/general/G4),
  [SCR33](https://www.w3.org/WAI/WCAG22/Techniques/client-side-script/SCR33) for scrolling text),
  and let one control govern every moving region on the page: "As a best practice, if a page
  contains more than one moving, blinking, scrolling, or auto-updating element, provide a single
  mechanism to pause, stop, hide, or (in the case of auto-updating content) control the update
  frequency that affects all these elements at the same time."

  ```html
  <p>Live score: <span id="score">0 – 0</span></p>
  <button id="pause">Pause updates</button>
  ```

  ```js
  let timer = setInterval(update, 5000) // starts automatically
  const button = document.querySelector('#pause')
  button.addEventListener('click', () => {
    if (timer) {
      clearInterval(timer)
      timer = null
      button.textContent = 'Resume updates'
    } else {
      timer = setInterval(update, 5000)
      button.textContent = 'Pause updates'
    }
  })
  ```

  For a CSS ticker, let the same button toggle a class and stop the animation; keep the
  reduced-motion rule as an addition, never as the mechanism:

  ```css
  .ticker {
    animation: scroll 20s linear infinite;
  } /* F16 while nothing can stop it */
  .paused .ticker {
    animation-play-state: paused;
  } /* the button toggles .paused on <html> */
  @media (prefers-reduced-motion: reduce) {
    .ticker {
      animation: none;
    }
  }
  ```

  For blinking, end it inside the five seconds instead of adding a control
  ([G11](https://www.w3.org/WAI/WCAG22/Techniques/general/G11),
  [SCR22](https://www.w3.org/WAI/WCAG22/Techniques/client-side-script/SCR22),
  [G152](https://www.w3.org/WAI/WCAG22/Techniques/general/G152) for an animated GIF set to stop
  after n cycles) — `animation: blink 1s steps(2) 4` runs 4 seconds and stops by itself — or offer a
  reload without the blinking content
  ([G191](https://www.w3.org/WAI/WCAG22/Techniques/general/G191)). Replace `<marquee>` and `<blink>`
  with static markup.

- Related: 2.3.3 (motion triggered by interaction), 2.3.1 and, at AAA, 2.3.2 (flashing), 1.4.2
  (sound of the same media), 2.2.1 (timed reload or vanishing message), 4.1.3 (auto-updating text
  announced as a status message), 4.1.2, 2.1.1 and 2.4.7 (the control's name, keyboard access and
  focus indicator, all of which the mechanism must satisfy in its own right).
